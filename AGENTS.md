# ML & DL knowledge base

Obsidian Markdown is the canonical content; publication is a derived surface. Preserve authored text, examples, code, and images outside the requested changes. `raw` contains immutable sources; retain legacy folders until their migration is verified.

For teaching content, sources, illustrations, or translations, read the relevant sections of [.agents/references/editorial.md](.agents/references/editorial.md). It defines content layers, page types and provenance, Russian prose, illustration policy, English parity, and navigation. These editorial requirements do not require a literature review for a tooling or typo fix.

Before declaring a chapter complete, perform the mandatory explanation review in that reference. Compare the full explanation with the selected source sections, work through the example, and inspect the rendered figures. Style cleanup, source links, passing tests, and old audit closure do not establish teaching quality. Record unresolved explanatory gaps and revise them before claiming completion.

When adding or moving published material, update the applicable content index, navigation, manifest, and asset/provenance links. Validate the affected publication path using the repository's current scripts; before publication, run its required build/link checks and inspect the actual rendered pages. A Markdown file existing on disk does not establish publication completeness.

Keep the task's deliverable, language, destination, and acceptance criteria explicit across follow-ups. Report content completion, local build validation, and live publication separately, with evidence for each claimed stage.

# Векторы, матрицы и тензоры

Пусть у двух объектов есть по три числовых признака. Запишем их в таблицу:

$$
X=\begin{bmatrix}
1&2&0\\
0&1&3
\end{bmatrix}.
$$

В каждой строке находится один объект, в каждом столбце — значения одного
признака. Форма таблицы — `[2,3]`. Можно прибавить поправку к каждому числу,
найти среднее по каждому столбцу или построить два новых признака вместо
трёх исходных. Эти действия используют разные операции: поэлементное
сложение, усреднение и матричное умножение. На этой таблице разберём, что
происходит с числами и формой в каждом случае.

Языковая модель тоже работает с числовыми массивами. Позднее строки будут
соответствовать позициям в тексте, а дополнительные оси — разным
последовательностям и головам внимания. Правила операций при этом сохранятся.

## От скаляра к тензору

**Скаляр** — одно число. Например, среднее всех шести чисел таблицы $X$:

$$
\bar{x}=\frac{1+2+0+0+1+3}{6}=\frac76.
$$

В математике **вектор** — элемент пространства, для которого определены
сложение и умножение на число. Столбец чисел — его координатная запись в
выбранном базисе. Это различие полезно: один и тот же язык линейной алгебры
описывает направленные отрезки, коэффициенты многочлена и скрытые состояния
нейросети. В программной библиотеке набор координат обычно представлен
одномерным массивом. Запись $\mathbf{x}\in\mathbb{R}^{d}$ означает, что у него
$d$ вещественных координат. В математических формулах этой главы векторы
считаются столбцами; например, первая строка таблицы хранит координаты вектора

$$
\mathbf{x}=
\begin{bmatrix}
1\\2\\0
\end{bmatrix}.
$$

В NumPy массив формы `(3,)` сам по себе не является ни строкой, ни столбцом.
Формы `(1,3)` и `(3,1)` уже обозначают двумерные массивы с разным расположением
осей. Это различие понадобится при транспонировании и broadcasting.

Вектором может быть и функция. Например, многочлен $f(t)=1+2t$ задаётся
координатами $[1,2]$ в базисе из функций $1$ и $t$. У многочлена
$g(t)=3-t$ координаты $[3,-1]$. При сложении функций складываются их
коэффициенты: $f(t)+g(t)=4+t$, то есть $[1,2]+[3,-1]=[4,1]$.
Поэтому геометрические стрелки, столбцы чисел и функции могут подчиняться
одним правилам линейной алгебры.

**Матрица** — прямоугольная таблица чисел с двумя осями. Наша $X$ имеет две
строки и три столбца: $X\in\mathbb{R}^{2\times3}$. Элемент $X_{ij}$ находится
в строке $i$ и столбце $j$. В математических формулах индексы обычно начинают
с 1; в примерах Python — с 0.

**Тензор** — массив с произвольным числом осей. В программных библиотеках и
скаляр, и вектор, и матрица тоже являются тензорами: число их осей равно 0,
1 и 2. Здесь используется принятое в ML значение слова «тензор»; более общее
математическое определение для операций над массивами нам не потребуется.
Слово «размерность» двусмысленно: у вектора может быть 4096 компонентов, но
только одна ось. Поэтому будем различать **число осей** (`ndim`) и
**длину оси**. Число осей иногда называют рангом тензора, но его нельзя путать
с рангом матрицы — числом линейно независимых строк или столбцов.

| Объект | Пример | Форма | Осей |
|---|---|---:|---:|
| скаляр | среднее всех значений | `[]` | 0 |
| вектор | признаки одного объекта | `[3]` | 1 |
| матрица | два объекта по три признака | `[2,3]` | 2 |
| тензор | четыре таблицы | `[4,2,3]` | 3 |

Число элементов равно произведению длин осей: в `[4,2,3]` хранится
$4\cdot2\cdot3=24$ числа. Форма ещё не определяет объём памяти: те же
24 значения в формате float32 занимают 96 байт, а в float64 — 192 байта
без учёта служебных данных массива.

## Форма — часть смысла

У массива формы `[2,3]` может быть много разных смыслов: два объекта с тремя
признаками, два дня с тремя измерениями или три координаты у двух точек.
Форма ограничивает допустимые операции, но не сообщает, какую задачу мы решаем.

Для примера с текстом возьмём две фразы: «кот спит» и «пёс спит». В этой
учебной задаче каждому слову соответствует один идентификатор:
`кот → 0`, `спит → 1`, `пёс → 2`. Получается массив формы `[2,2]`:

```text
token_ids = [
  [0, 1],
  [2, 1],
]
```

Таблица эмбеддингов $\mathbf{E}\in\mathbb{R}^{V\times d}$ содержит по строке
на каждый элемент словаря размером $V$. Эмбеддинг — числовой вектор, которым
представлен элемент словаря. Для маленького примера выберем $V=3$, $d=3$ и
зададим значения вручную:

$$
E=\begin{bmatrix}
1&0&0\\
0&1&0\\
1&1&-1
\end{bmatrix}.
$$

Выбор строки по индексу (embedding lookup) заменяет `0` первой строкой,
`1` — второй, `2` — третьей. Для двух фраз получаем:

```text
X_text = [
  [[1,0,0], [0,1,0]],  # «кот спит»
  [[1,1,-1], [0,1,0]], # «пёс спит»
]
```

Форма результата — `[2,2,3]`: две последовательности, две позиции в каждой,
три координаты на позицию. Обозначим число последовательностей через $B$,
число позиций в каждой — через $T$, длину вектора — через $d$.
В общем случае это переход `[B,T] → [B,T,d]`.
Такой выбор строк не требует плотного матричного умножения. В настоящей
языковой модели таблица обычно обучается, а разбиение на токены сложнее
выбранного здесь соответствия «одно слово — один индекс».

У обученного эмбеддинга отдельная координата не обязана соответствовать
понятному человеку свойству. Векторами можно пользоваться и без такой
интерпретации координат: ниже будут разобраны их длины, скалярные произведения
и линейные преобразования.

Оси нельзя трактовать как безымянные размеры. Перестановка `[B, T, d]` в
`[T, B, d]` сохраняет число элементов, но меняет договорённость о том, какая
ось обозначает примеры, а какая — позиции. Если $B=T$, даже сами размеры не
выдадут ошибочную перестановку. Проверять нужно и форму, и соответствие
элементов исходным объектам.

## Поэлементные операции и broadcasting

Сложение и умножение на число применяются к каждому элементу отдельно:

$$
\begin{aligned}
X+X&=\begin{bmatrix}2&4&0\\0&2&6\end{bmatrix},\\[4pt]
2X&=\begin{bmatrix}2&4&0\\0&2&6\end{bmatrix}.
\end{aligned}
$$

Поэлементное умножение двух массивов той же формы также сохраняет форму.
Например, $X\odot X$ возводит в квадрат каждое число. В NumPy для него
используется оператор `*`; для матричного умножения — другой оператор, `@`.

Если формы различаются, библиотека иногда может согласовать их по правилу
**broadcasting**. Пусть к первому признаку каждого объекта нужно прибавить
10, ко второму — 20, к третьему — 30. Вектор поправок
$\mathbf b=[10,20,30]$ имеет форму `[3]`, а $X$ — `[2,3]`:

$$
\begin{aligned}
Y&=
\begin{bmatrix}
1+10&2+20&0+30\\
0+10&1+20&3+30
\end{bmatrix}\\[4pt]
&=\begin{bmatrix}11&22&30\\10&21&33\end{bmatrix}.
\end{aligned}
$$

Для проверки формы выравниваются справа: `[2,3]` и `[1,3]`.
Длины по каждой паре осей должны совпадать либо одна из них должна равняться 1.
Отсутствующая слева ось считается осью длины 1. В данном случае первая ось
вектора расширяется с 1 до 2, поэтому одна поправка используется для обеих строк.
Не требуется заранее создавать копию вектора для каждого объекта.

Если вместо поправок по признакам нужны поправки по объектам, форму нужно
изменить. Столбец `[[10],[20]]` формы `[2,1]` прибавляет 10 ко всей первой
строке и 20 ко всей второй:

$$
X+\begin{bmatrix}10\\20\end{bmatrix}
=\begin{bmatrix}11&12&10\\20&21&23\end{bmatrix}.
$$

Массив `[10,20]` формы `[2]` здесь не подходит: при выравнивании справа
получаются несовместимые длины 3 и 2. Добавление оси длины 1 определяет,
какие значения должны повторяться.

В [примере D2L](https://d2l.ai/chapter_preliminaries/ndarray.html#broadcasting)
расширяются обе матрицы:
`[[0],[1],[2]]` имеет форму `[3,1]`, а `[[0,1]]` — `[1,2]`.
У результата форма `[3,2]`: элемент на пересечении строки $i$ и столбца $j$
равен сумме соответствующих исходных значений:

$$
\begin{bmatrix}0\\1\\2\end{bmatrix}
+\begin{bmatrix}0&1\end{bmatrix}
=\begin{bmatrix}0&1\\1&2\\2&3\end{bmatrix}.
$$

Для текста те же правила дают `[B,T,d] + [d] → [B,T,d]`: поправка общая
для всех позиций и последовательностей. Форма `[T,1]` вместо `[d]` тоже
допускает сложение, но означает отдельную скалярную поправку для каждой позиции,
общую для всех её координат и всех последовательностей.

## Суммирование и усреднение по оси

Сумма по оси объединяет значения, которые различаются индексом этой оси.
Для исходной $X$ сумма по первой оси, `axis=0`, складывает строки и оставляет
по одному результату на признак:

$$
[1+0,\ 2+1,\ 0+3]=[1,3,3].
$$

Форма `[2,3]` превращается в `[3]`. Сумма по `axis=1` объединяет признаки
внутри каждого объекта и даёт `[3,4]` формы `[2]`. Среднее вычисляется
аналогично, но делит сумму на длину сворачиваемой оси: средние по столбцам
равны `[0.5,1.5,1.5]`, а по строкам — `[1,4/3]`. При суммировании всех
элементов остаётся скаляр 7.

Иногда ось длины 1 сохраняют параметром `keepdims=True`. Тогда средние каждой
строки имеют форму `[2,1]`: `[[1],[4/3]]`. Их можно вычесть из $X$, чтобы
у каждого объекта получить признаки с нулевым средним. Без сохранённой оси
возникла бы уже знакомая ошибка `[2,3] - [2]`. По этой причине параметры
`axis` и `keepdims` определяют не только результат усреднения, но и то,
как его можно использовать дальше.

## Скалярное произведение

Скалярное произведение двух векторов одинаковой длины равно сумме попарных
произведений:

$$
\mathbf{x}^{\top}\mathbf{y}=\sum_{i=1}^{d}x_i y_i.
$$

У него есть две взаимодополняющие интерпретации.

1. **Взвешенная сумма.** Если $\mathbf{x}$ — признаки, а $\mathbf{w}$ — веса,
   то $\mathbf{w}^{\top}\mathbf{x}$ даёт выход линейного нейрона до активации.
2. **Сравнение направлений.** Для ненулевых векторов скалярное произведение
   связано с углом $\theta$: $\mathbf x^\top\mathbf y
   =\|\mathbf x\|_2\|\mathbf y\|_2\cos\theta$.
   Здесь $\|\mathbf x\|_2$ — евклидова длина, определённая ниже.
   Разделив произведение на обе длины, получаем косинусное сходство.
   Само скалярное произведение зависит и от направлений, и от длин.

Например,

$$
\begin{aligned}
\begin{bmatrix}1&2&-1\end{bmatrix}
\begin{bmatrix}3\\0\\2\end{bmatrix}
&=1\cdot3+2\cdot0-1\cdot2\\
&=1.
\end{aligned}
$$

Суммирование сворачивает общую координатную ось $i$: вместо двух векторов
длины $d$ получается скаляр, у которого нет осей. Например, векторы
`[1,0]` и `[2,0]` имеют произведение 2, а `[1,0]` и `[20,0]` — 20.
Угол в обоих случаях равен нулю, поэтому косинусное сходство одинаково
и равно 1. Вектор `[0,1]` перпендикулярен `[1,0]`: произведение и косинус равны 0.
Для нулевого вектора косинусное сходство по этой формуле не определено.

## Умножение матриц как набор скалярных произведений

Пусть $\mathbf{A}\in\mathbb{R}^{m\times n}$ и
$\mathbf{B}\in\mathbb{R}^{n\times p}$. Их произведение определено, потому что
внутренние размеры совпадают, и имеет форму $m\times p$:

$$
\mathbf{C}=\mathbf{A}\mathbf{B},
\qquad
C_{ij}=\sum_{k=1}^{n}A_{ik}B_{kj}.
$$

Каждый элемент $C_{ij}$ — скалярное произведение строки $i$ матрицы $A$ и
столбца $j$ матрицы $B$.

Применим к нашей таблице матрицу весов $W$ с тремя строками и двумя
столбцами:

$$
\begin{aligned}
XW&=
\begin{bmatrix}1&2&0\\0&1&3\end{bmatrix}
\begin{bmatrix}1&0\\2&-1\\0&2\end{bmatrix}\\[4pt]
&=
\begin{bmatrix}5&-2\\2&5\end{bmatrix}.
\end{aligned}
$$

Первый новый признак равен $x_1+2x_2$, второй — $-x_2+2x_3$.
Для первого объекта это $1+2\cdot2=5$ и $-2+2\cdot0=-2$;
для второго — $0+2\cdot1=2$ и $-1+2\cdot3=5$. Одна и та же
матрица преобразовала признаки обоих объектов независимо. Мы получили два
объекта с двумя признаками, поэтому форма результата равна `[2,2]`.
Это линейное отображение трёхмерного пространства признаков в двумерное.

Поэлементное произведение $X\odot W$ для этих форм невозможно: `[2,3]` и
`[3,2]` несовместимы для broadcasting. Матричное умножение допустимо, потому
что сворачивает общую ось длины 3.

В линейном слое нейросети объекты могут иметь дополнительные оси:

```text
X : [B, T, d_in]
W :       [d_in, d_out]
-----------------------
Y : [B, T, d_out]
```

Операция одновременно применяет одну матрицу весов к каждому токену каждого
примера. Первые оси сохраняются, последняя меняется с $d_{in}$ на $d_{out}$.
Запись `[..., d_in] @ [d_in, d_out] -> [..., d_out]` поэтому полезнее, чем
запоминание частного случая для двумерных матриц.

Здесь $W$ записана в ориентации «входная ширина × выходная ширина».
Некоторые библиотеки, в том числе PyTorch `Linear`, хранят веса
транспонированными и вычисляют $XW^\top$. Это то же отображение при другой
договорённости о форме хранимой матрицы.

## Транспонирование и attention

Транспонирование меняет строки и столбцы местами:
$\mathbf{A}^{\top}\in\mathbb{R}^{n\times m}$. Оно не меняет значения, но
меняет то, какие пары элементов встретятся при умножении.

Для нашей матрицы $X$:

$$
X^\top=
\begin{bmatrix}1&0\\2&1\\0&3\end{bmatrix}.
$$

Теперь строка соответствует признаку, а столбец — объекту. От транспонирования
нужно отличать `reshape`: изменение формы с сохранением последовательности
элементов. Если прочитать строки $X$ подряд, получим `[1,2,0,0,1,3]`.
При `reshape(3,2)` эта последовательность разбивается на три пары:

$$
\operatorname{reshape}(X,[3,2])=
\begin{bmatrix}1&2\\0&0\\1&3\end{bmatrix}.
$$

Формы двух результатов совпали, но числа расположены по-разному.
Перестановка осей сохраняет принадлежность элемента исходному объекту
и признаку; `reshape` задаёт другую группировку элементов.
Произведение длин осей при `reshape` обязано оставаться тем же: массив
из шести элементов нельзя превратить в `[2,4]` без изменения данных.
Нужно ли физически копировать память при изменении формы, зависит от
исходного расположения массива и библиотеки. В
[документации NumPy `reshape`](https://numpy.org/doc/2.3/reference/generated/numpy.reshape.html)
указано: если представление без копирования создать нельзя, операция
по умолчанию создаёт копию данных.

### Применение в self-attention

Внимание (attention) будет подробно разобрано после языковых моделей.
Здесь достаточно рассмотреть одну его операцию: сравнение каждой строки
одной матрицы с каждой строкой другой.

Пусть для одной головы attention
$\mathbf{Q},\mathbf{K}\in\mathbb{R}^{T\times d_h}$. Чтобы сравнить каждый
query с каждым key, вычисляют

$$
\mathbf{S}=\mathbf{Q}\mathbf{K}^{\top}
\in\mathbb{R}^{T\times T}.
$$

Например, при $T=2$, $d_h=3$ возьмём $Q=X$ и
$K=\begin{bmatrix}1&0&1\\0&2&1\end{bmatrix}$. Тогда

$$
QK^\top=
\begin{bmatrix}1&2&0\\0&1&3\end{bmatrix}
\begin{bmatrix}1&0\\0&2\\1&1\end{bmatrix}
=\begin{bmatrix}1&4\\3&5\end{bmatrix}.
$$

Элемент $S_{12}=4$ получился из первой строки Q и второй строки K:
$1\cdot0+2\cdot2+0\cdot1=4$. Строки результата соответствуют запросам
(query), столбцы — ключам (key). На этом шаге получены оценки, ещё не
вероятности.

Форма результата уже раскрывает смысл операции: строка $i$ содержит оценки
того, насколько позиция $i$ согласуется со всеми $T$ позициями. Если забыть
транспонирование, произведение `[T, d_h] @ [T, d_h]` в общем случае не определено.
При случайном совпадении $T=d_h$ размеры окажутся допустимыми, но смысл осей
всё равно будет неверным. Если
переставить не ту ось в батчевом тензоре, код может выполниться, но будет
сравнивать головы или примеры вместо токенов.

## Нормы

Норма превращает вектор в неотрицательное число, характеризующее его величину.
Чаще всего используются

$$
\|\mathbf{x}\|_1=\sum_i|x_i|,
\qquad
\|\mathbf{x}\|_2=\sqrt{\sum_i x_i^2}.
$$

$L_2$-норма — обычная евклидова длина. Она нужна для нормализации эмбеддингов,
контроля градиентов и регуляризации весов. Для матрицы аналогом является
норма Фробениуса — квадратный корень из суммы квадратов всех элементов.

У вектора $\mathbf x=[3,4]^\top$ нормы равны
$\|\mathbf x\|_1=|3|+|4|=7$ и
$\|\mathbf x\|_2=\sqrt{3^2+4^2}=5$.
Деление на евклидову длину даёт единичный вектор
$\hat{\mathbf x}=[3/5,4/5]^\top$:

$$
\|\hat{\mathbf x}\|_2=\sqrt{(3/5)^2+(4/5)^2}=1.
$$

Направление сохранилось, а длина стала равна 1. Именно такое преобразование
имеется в виду при вычислении косинусного сходства нормализованных векторов.
Нулевой вектор нормализовать таким делением нельзя.

Длина не равна числу координат. Векторы `[3,4]` и `[0,0]` оба имеют две
координаты, хотя их евклидовы длины равны 5 и 0. Для исходной таблицы $X$
норма Фробениуса равна
$\sqrt{1^2+2^2+0^2+0^2+1^2+3^2}=\sqrt{15}$.

## Как проверять формы без угадывания

При разборе любой операции полезен один и тот же порядок.

1. Подписать смысл каждой оси: batch, token, head, channel.
2. Записать входные формы до формулы.
3. Для умножения проверить совпадение внутренних размеров.
4. Для сложения проверить равенство форм или явно объяснить broadcasting.
5. Записать форму результата и истолковать каждую её ось.

Например, в многоголовом внимании координаты каждого токена разделяются на
$H$ групп ширины $d_h$, где $d=H d_h$. Группы называются головами.
После разделения появляется дополнительная ось:

```text
[B, T, d]
  → [B, T, H, d_h]
  → [B, H, T, d_h]
d = H · d_h
```

Первый переход разбивает последнюю ось на две, не меняя принадлежности
координат токенам. Второй переставляет оси токенов и голов: теперь операции
внутри внимания могут работать с каждой головой независимо. После внимания
выполняется обратная перестановка и головы снова объединяются. Порядок этих
действий и сами вычисления разобраны в
[[00 Учебник/05 Attention и Transformer/Masking, multi-head и формы тензоров|главе о масках, головах и формах]].

## Проверка числовых примеров в NumPy

Код повторяет операции с исходной таблицей и отдельно сравнивает `reshape` с
транспонированием. Он предполагает установленный NumPy; Transformer или
обученная модель для этих проверок не нужны.

```python
import numpy as np

X = np.array([[1., 2., 0.], [0., 1., 3.]])
W = np.array([[1., 0.], [2., -1.], [0., 2.]])
assert X.shape == (2, 3)
assert np.array_equal(X @ W, [[5., -2.], [2., 5.]])
assert np.array_equal(X + [10., 20., 30.],
                      [[11., 22., 30.], [10., 21., 33.]])
assert np.array_equal(X + [[10.], [20.]],
                      [[11., 12., 10.], [20., 21., 23.]])
assert np.array_equal(X.sum(axis=0), [1., 3., 3.])
assert np.array_equal(X.sum(axis=1), [3., 4.])
assert X.mean(axis=1, keepdims=True).shape == (2, 1)
centered = X - X.mean(axis=1, keepdims=True)
assert np.allclose(centered.mean(axis=1), 0.)

assert np.array_equal(X.T, [[1., 0.], [2., 1.], [0., 3.]])
assert np.array_equal(X.reshape(3, 2),
                      [[1., 2.], [0., 0.], [1., 3.]])
assert not np.array_equal(X.T, X.reshape(3, 2))

E = np.array([[1., 0., 0.], [0., 1., 0.], [1., 1., -1.]])
token_ids = np.array([[0, 1], [2, 1]])
assert E[token_ids].shape == (2, 2, 3)
K = np.array([[1., 0., 1.], [0., 2., 1.]])
assert np.array_equal(X @ K.T, [[1., 4.], [3., 5.]])
assert np.linalg.norm([3., 4.]) == 5.
assert np.isclose(np.linalg.norm(X), np.sqrt(15.))
```

Для последовательной реализации этих операций с проверками доступен
[[05 Источники/Courses/Harvard ML Systems/tinytorch/01_tensor|полный оригинальный модуль TinyTorch 01]].
В нём матричное умножение разобрано как вычисление элементов результата
по строкам и столбцам; отдельно даны `reshape`, `transpose`,
суммирование и усреднение по оси.

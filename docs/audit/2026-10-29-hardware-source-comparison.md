## Source corrections and exclusions

Open source material is not automatically factually correct. These passages were not carried over as unqualified claims:

- Source 113–115: A100 80+ billion transistor claim and generic CPU ratios need independent correction; avoid reproducing as measured facts.
- Source 137–150: Amdahl p is baseline-time accelerated fraction, not universally 90–99% ML matrix multiplication; additive formula assumes no overlap.
- Source 336–359: ResNet/GPT2 p values are constructed assumptions, not hardware benchmarks; bandwidth-bound is not synonym for serial.
- Source 371–393: TPUv1 ratios conditional benchmark, not a proof general-purpose computing ended; historical8087 100x not needed for scope.
- Source 835–841: CPU utilization claim generic; training vs inference priorities depend workload/SLO, not universal latency-only inference.
- Source 1216–1244: RISC-V fragment incomplete illustrative pseudo-ISA, hardcoded32-byteincrement ignores actualvl and no decrement; avoid importing.
- Source 1303–1309: Column-batch Q and K projections then QK^T produce feature-feature not token-token attention. Canonical attention chapter correct.
- Source 1337–1348: Fixed16x16 hardware throughput generic notvalid; LayerNorm not one-to-one elementwise because reduction.
- Source 1426–1451: Single-cycle sigmoid/tanh/SFU table illustrative notGPU guarantee; preserve distinct scalar/vector/tensor/SFU resources without fabricated latency.
- Source 1487–1495: SVE ptrue does not query length; occupancy low does not imply memory-bound; lane divergence details architecture-specific.
- Source 1570–1576: Example MMA instruction pseudo-PTX incomplete/invalid signature; canonical real wmma/ptx example preferable.
- Source 1733–1741: 2:4 hardware requires at most two nonzero entries per group, not exactly. Pattern orientation and metadata matter.
- Source 2065–2078: Systolic energy ratio compares uncached naïve DRAM load/store baseline, not CPU/GPU vector unit benchmark.
- Source 2294–2311: Output-stationary streamedA/B example must not be described as same path as weight-stationary TPU diagram. Dataflow not universally immutable.
- Source 2353–2379: FP32→FP16 does not universally double throughput, precision support depends SKU and instruction.
- Source 2393–2512: Mixed hardware/precision lists and prices not apples-to-apples; avoid treating pricing/peak ratios as serving cost measurement.
- Source 2952–2973: Illustrative tensor journey incorrectly implies obligatory DMA→L2→L1 path and zero-nanosecond register latency. Existing CUDA hierarchy sections should override.
- Source 3157–3188: Irregular address access is not synonymous with memory fragmentation; dense fully connected products are regular.
- Source 3198–3244: Generic memory-latency tables are illustrative, not universal device values.
- Source 3260–3270: A100 supports FP32 accumulation and FP64 Tensor Core paths; HBM does not universally have lower latency than DDR.
- Source 3436–3440: Do not compare aggregate bidirectional NVLink to a one-direction PCIe figure or call a switch's aggregate limit 64 GB/s universally.
- Source 3494–3494: The attention score matrix can be quadratic; KV-cache storage grows linearly with sequence length.
- Source 3533–3533: Roofline is an upper bound, not an equality guaranteeing achieved throughput.
- Source 3879–3879: High arithmetic intensity alone does not establish near-peak performance.
- Source 4071–4082: LayerNorm includes a reduction; fusion speedups are not universal constants.
- Source 4146–4244: Interactive generation can batch; KV caching does not eliminate weight-bandwidth cost.
- Source 4263–4278: Traditional compilers also map operations; NVCC is not directly a high-level model compiler, and Transformer execution is not obligatorily adaptive placement.
- Source 4330–4400: Independent factorial configuration counts include illegal dependency orders and coupled decisions; excluded rather than presented as a valid search-space size.
- Source 4524–4524: Tokens are not literally unchanged activations through every layer; dataflow is not exclusive to one model family.
- Source 4559–4619: NHWC is not a definition of row-major storage. Logical axes and physical strides are distinguished in the new checked example.
- Source 4678–4678: Incomplete torch.batch_norm call is not copied as executable code.
- Source 4757–4765: Four buffers versus two is not a fourfold memory reduction; training BatchNorm is not pointwise; register spills are not automatically shared-memory allocations.
- Source 4891–4939: Source tiling pseudocode omits tail handling and has an invalid split multiplication expression; existing checked examples retain boundary masks.
- Source 4981–4981: Transformers are not unconditionally memory-bound.
- Source 5096–5123: Keras compile does not universally imply the same JIT contract as torch.compile; arbitrary graph rewrites do not create correct KV caching.
- Source 5189–5275: Overlap does not necessarily make a workload compute-bound; JIT exists; runtimes do not automatically retile or fuse arbitrary graphs on every call.
- Source 5335–5353: Peak-based GPT-3 timing is hypothetical, not an achievable execution result; observed synchronization percentage is not a fixed baseline serial fraction.
- Source 5389–5423: CPU is not always the best NMS target; NPU/DSP power ordering and ML-based runtime scheduling are not universal platform properties.
- Source 5503–5514: NPU/CPU carbon example assumes energy and workload values rather than measuring them; use declared energy and carbon boundaries.
- Source 5575–5779: CPU utilization alone does not establish faster latency; procurement decisions cannot be based solely on whether one GEMM lies above the ridge.
- Source 5917–5917: The absolute claim that accelerators cannot make bytes cheaper to move ignores memory hierarchy, dataflow and packaging design.

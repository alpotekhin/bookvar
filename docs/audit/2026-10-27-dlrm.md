Пройденный пример: три списка ID включают пустой список и повторный ID;
sum pooling даёт три явных вектора. Для одного примера показаны bottom
MLP, 3×3 Gram matrix, порядок нижнего треугольника и пятикоординатный вход
верхнего слоя. Logit 1.1 даёт BCE 0.287335. Выведены градиенты по dense
вектору и обоим pooled embeddings, затем по строкам таблиц. Один CPU SGD
шаг всех параметров уменьшает loss до 0.273386.

Пояснено отличие от суммирования FM и входа глубокой ветви DeepFM.
Размеры 26 полей / 128 координат дают 351 пару и 479 координат вместо
3456 при конкатенации. Разделены параметрическая ёмкость, арифметика
взаимодействий, логический payload выбранных строк и измеренный трафик.
512 GB не названы 512 GiB. Четыре FP32 массива — условный пример,
а не универсальный коэффициент памяти sparse/fused optimizer.

Table/row/column sharding объяснены через владение строками/координатами.
Разобраны input distribution, возврат pooled vectors, обратная передача
градиентов и отдельная синхронизация плотных параметров. Неравные размеры
частичных bags показывают ошибочность среднего от средних.

## Проверка кода и фактов

`publishing/tools/check_dlrm_examples.py` исполняет все 19 actual Python
блоков через прежний checker, сохраняя его конечные разности и протокольные
контрпримеры. Новые независимые проверки:

- точное совпадение source segment перенесённого метода;
- все градиенты bottom/top MLP, user/product rows и неиспользованных строк
  batch, а не только проверка уменьшения loss;
- 36 конфигураций batch/fields/width/diagonal: сравнение значений с явными
  парами, ручные градиенты и `cat` mode; отдельный finite-difference gradcheck;
- пустые и повторные IDs: значения и градиенты с учётом кратности;
- row/column reconstruction при пустых bags, повторах и неравных counts.

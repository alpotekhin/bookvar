правки переноса числового результата RMSNorm повторно прочитан сам абзац.
Прежняя редакция сохранена в

- SHA256 до правок: `e2b511ea59d22b934352e6f0f1869d89780393369c3924d0701d3347bf236e51`.
- SHA256 принятой редакции: `8bda8af63d82960da7d5849e132be647542b90d4a9a9daca05ff5a0f2e66d356`.

Сохранены полная реализация encoder–decoder, отдельная реализация современного
causal LM, все пять блоков Python, семь оригинальных иллюстраций, формулы,
сопоставление BERT/GPT/LLaMA и ограничения учебных примеров.

Исправления:

1. Вместо ошибочной формулировки «матрицы и входы обучаются» объяснён градиент
   по входу FFN: из `u1 + 2u1` получается `(3, 0)`. Числа учебного входа
   не объявляются обучаемыми параметрами. Опубликованный блок показывает
   градиент по входу; вычисление `W.grad` ему не приписывается.
2. Для полного примера явно указан right padding. BOS находится первой
   позицией непустой цели; источник непустой. Left padding требует отдельной
   обработки пустых разрешённых строк, разобранной в главе о масках.
3. В пример добавлены вероятности правильных токенов и отдельные потери:
   `9.786662`, `4.631725`, `10.881613`, `12.110340`.
   Сумма `37.410340` делится на четыре действительные цели: `9.352585`.
   Пятая PAD-цель даёт нулевую потерю. Обычное среднее по пяти элементам
   дало бы неверное здесь значение `7.482068`.
4. Разведены три операции: маскирование ключей, игнорирование PAD-цели
   и наличие PAD-класса в softmax. При `ignore_index=PAD` PAD-класс
   сохраняется в знаменателе на остальных позициях. Поэтому общая таблица
   эмбеддингов может получать градиент для строки PAD через выходной слой.
5. Ссылка назад к маскам больше не названа «следующей главой».
   Широкий результат RMSNorm записан координатами в тексте без уменьшения шрифта.

Проход по no-ai-slop использован для проверки точности формулировок, а не
для сокращения главы. Рассуждения, примеры, оговорки и исходные подписи сохранены.

## Численная проверка

Расширен `publishing/tools/check_full_transformer_examples.py`.
Финальный запуск завершился с кодом 0 на PyTorch 2.14.1 и напечатал SHA256
принятой редакции главы. Все пять опубликованных блоков исполнились.

Проверены:

- прежние независимые расчёты FFN, pre/post-norm, cross-attention, CE/KL;
- оба post-norm слоя против нативных слоёв PyTorch: неодинаковые длины,
  padding, выходы, градиенты входа/памяти и всех параметров;
- поэлементная потеря, вероятности целей и делитель по действительным целям;
- нулевой градиент всей игнорируемой строки logits и ненулевой градиент
  PAD-класса на остальных позициях;
- равенство градиента общей таблицы сумме градиентов раздельных входной
  таблицы и выходного слоя. У раздельной входной таблицы PAD-градиент нулевой,
  у выходного слоя — нет;
- отрицательный контроль с `detach` памяти encoder: forward остаётся тем же,
  encoder не получает градиента, а общий выходной слой получает. Один лишь
  `embedding.grad` не доказывает прохождение градиента через encoder;
- причинность всех префиксов, отсутствие утечки через PAD-ключи и один шаг SGD:
  `9.352584927036121 → 8.497538101285013` на том же единственном примере;
- современный блок: dense RoPE/SDPA, все attention-градиенты,
  RMSNorm gradcheck, SwiGLU и причинность префиксов.

Снижение потери после одного шага не объявлено результатом обучения
или обобщением модели.

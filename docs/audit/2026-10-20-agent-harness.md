## Проверка механизмов

| Механизм | Пройденный случай |
|---|---|
| Один шаг | read → write версии 1 → отклонённый final → test версии 1 → проверенный final |
| Бюджет входа | W=8192, фиксированная часть 2180, выход 1024, запас 256; история вмещает 4732; добавление результата даёт 9660 |
| Compaction до переполнения | Сам запрос резюме занимает 7636 с резервом; после замены старой части остаётся 6960 |
| Кеш префикса | Условные token IDs дают общий префикс 6, меняющаяся начальная метка 0, правка третьего токена 2; это не замер hit rate |
| Длинный контекст | Перестановка нужного документа отделена от добавления distractors; данные старых моделей не выданы за универсальный эффект современных |
| Очистка вывода | Из семи наблюдений два старых заменены placeholder; это не содержательное LLM-резюме |
| OpenHands | max_size считает события; 11 независимых событий, keep_first=2 дают замену 2–8; граница атомарной группы сдвигает диапазон |
| Причины сжатия | Превышение событий SOFT, token pressure HARD; источники и версии различены |
| Handoff | Неизвестный исход, прежний ключ, цель, ограничения и event_ref сохраняются; найденный один объект не доказывает отсутствие дубликатов |
| Reminders/hooks | Слот не дублируется, удаляется после проверки текущей версии и появляется для новой; additionalContext не равен запрету исполнения |
| Возобновление | JSON checkpoint сохраняет историю/счётчики; новый env читается при проверке; повторной записи нет |
| Завершение | Проверка старой ревизии, неверное значение финального отчёта, запрет записи и исчерпание лимита не дают done |

Обзорная схема OpenHands не показывает keep_first и атомарные границы.
Это установлено при просмотре и прямо оговорено в подписи; ложное описание
«сохранённого начала» в alt исправлено. Поведение ниже объясняется по коду,
а не выводится из упрощённой схемы.

## Исполнение примеров

check_agent_harness_examples.py:

- пять Python-блоков выполнены отдельно и подряд, десять исполнений;
- JSON checkpoint разобран;
- шесть защищённых полей проверены на удаление;
- проверены неверный ключ, ложное завершение, смена ревизии, неправильный
  финальный отчёт, дублирующийся call_id, неправильный тип версии,
  запрет записи, предел инструментов и предел модельных шагов;
- напоминания не меняют входной словарь и сохраняют другие слоты;
- четыре чистых метода закреплённого OpenHands выполнены из AST:
  _effective_max_tokens, get_condensation_reasons,
  condensation_requirement, _get_forgotten_events;
- проверены независимые события, сдвиг атомарной границы, сохранение
  SystemPromptEvent при keep_first=0, мягкая/жёсткая причины и выбор
  меньшего token cap.

Для чистых методов использованы учебный View, заранее заданные допустимые
границы и искусственный счётчик токенов. Это не интеграционный запуск SDK,
настоящего tokenizer, суммаризатора, модели или sandbox. Ограниченные
возможности учебного runner прямо указаны в главе.

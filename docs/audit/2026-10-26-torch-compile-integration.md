## Источники и проверка механизма

PyTorch 2.14.1 закреплена commit
`5c4886908584029761b579af026dcfb627c84070`.
Полностью прочитаны Dynamo Core Concepts (172 строки), Dynamo Overview
(334), Dealing with Recompilations (204), страница об autograd semantics
и Zero-One Specialization (33). Из `fullgraph=True` прочитаны и использованы
вводная гарантия, Strategy 1/2 и пример явного graph break (1–131);
последующие C++/custom-op разделы не объявлены перенесёнными.

Точные URL, SHA, границы чтения и рассмотренные рисунки перечислены в
`05 Источники/Originals/harvard-performance-2026-10-26/compile-references.json`.
Семь source files и два image candidates сверены по этим хешам.

Механизмы проверены по соответствующим исходным разделам:

- Dynamo Tracing и Overview: FX-операции, остаточный Python, backend callable;
  операция FX не объявлена аппаратным kernel.
- Guards и What is a guard: специализация на Python-константе и метаданных
  тензора, проверки применимости и возможность нескольких cached variants.
- Recompilations: новый вариант нужен, если ни один сохранённый не подходит;
  размер и значение Python float разведены как отдельные причины.
- Graph Breaks и fullgraph: несколько регионов внутри одного вызова;
  их повторное использование не равно новой компиляции при каждом вызове.
- Wrapping Constants with Tensors и Dynamic Shapes: меняющиеся значения
  можно передавать тензором в подходящей тензорной операции; symbolic shapes
  не устраняют все guards и случаи 0/1.
- Graph Breaking to Reduce Recompilation Costs: намеренный break может
  отделить большое стабильное вычисление от маленького меняющегося.
  Удаление всех breaks не обещано как безусловный выигрыш.
- Autograd semantics: AOTDispatcher/AOTAutograd и предположения о backward
  упомянуты с оговорками. Самостоятельный перенос всех AMP-настроек и
  компиляция backward этим небольшим разделом не заявлены.

В исходных материалах найдены дефекты, которые не перенесены в объяснение:
псевдокод `h(x)` в Core Concepts обращается к неопределённому `y`;
summary diagram пишет `x.dtype == 'cpu'`, смешивая dtype и device.
Выбран другой полный исходный рисунок — pipeline из Dynamo Overview.
Ошибочный PNG сохранён только как исходный кандидат, не встроен в главу.
Неподтверждённые проценты ускорения и фиксированные времена компиляции
из Harvard также не добавлены.

## Настоящие CPU-примеры из Markdown

`publishing/tools/check_compile_examples.py` извлекает и исполняет три
настоящих Python fences текущего раздела. Не переписывает их в тестовый
эталон и не запускает остальные CUDA/Triton fences главы.

1. `relu(x*scale+1)`: пять вызовов, три backend invocations. Проверены
   результаты `[0,1,5]`, `[0,3,7]`, `[0,1,7]`, четыре четвёрки и возврат
   к первому cached variant. Изменение содержимого тензора не порождает
   новую специализацию в этом случае; Python float и static shape порождают.
2. Явный break между square и add: два региона, второй вызов использует
   оба сохранённых региона. Отдельная функция с `fullgraph=True` действительно
   вызывает `Unsupported`, а не молча выполняет частично скомпилированный код.
3. `dynamic=True` и tensor-valued scale: длины 3,5,7 и значения 2,3,4
   проходят через один вызов backend; результаты сверены с eager.

Первый реальный `GraphModule.code` включён в текст полностью. Checker
сравнивает этот напечатанный FX-код с настоящим результатом capture.
Читатель видит, где именно встроено `2.0`, почему нельзя использовать этот
вариант для `3.0` и что делают промежуточные ссылки. Обнуление ссылки не
выдано за освобождение GPU memory или границу kernel.

PyTorch 2.14.1, CPU, CUDA False. Backends возвращают `gm.forward` без
оптимизации: эти проверки подтверждают Dynamo capture/guards/cache и
численную корректность примеров, но не Inductor code generation,
AOTAutograd, CUDA Graphs или ускорение. Предупреждение об отсутствии NumPy
не помешало тензорным CPU-проверкам.

Прежний `check_triton_examples.py` также прошёл на текущем SHA: 11 Python
fences проходят AST, четыре самостоятельных CPU-алгоритма выполняются,
сохранены все проверки S8 и примеры CUDA Graphs. Вместе два checker запускают
семь самостоятельных CPU-примеров, не четыре GPU/Triton/API fences.

## Explanation, examples and sources

The chapter follows one request through admission, prefill/decode callbacks,
token delivery and exactly one terminal event. It explains the event-loop
owner, off-thread synchronous model call, immutable phase snapshots and
`call_soon_threadsafe`. The worked three-token case produces `[32,27,34]`
from prompt `[1,7,8,9,10]`; accepted/token/terminal events have separate meanings.
An HTTP 200 stream can subsequently end with an error. Client TTFT ignores the
accepted control record and is distinct from server token-availability time.

Cancellation acknowledgement is not native-call preemption. The deadline/
completion example can publish timeout while the engine ends with `length`;
late tokens are suppressed. Disconnects, failed response-start, channel cleanup
and same-ID reuse are explained against the actual implementation. Token-ID
NDJSON is explicitly not OpenAI-compatible or the original EDLS text-prompt
benchmark protocol. Per-channel buffering is bounded, not production backpressure.

# От изображения к визуальным токенам: ViT и CLIP

По запросу «собака на снегу» можно искать фотографии, сравнивая векторы
запроса и изображений. Для вопроса «какое число стоит в правой нижней
ячейке таблицы?» одного вектора всей страницы может не хватить:
модели нужны локальные признаки и расположение ячеек. Для ответа
текстом понадобится ещё и языковой генератор.

Vision Transformer (ViT) преобразует изображение в последовательность
признаков. CLIP обучает зрительный и текстовый кодировщики так,
чтобы можно было сравнивать их выходы. SigLIP меняет функцию потерь
этого обучения. Ни CLIP, ни SigLIP сами по себе не являются
диалоговой моделью: их основной результат — представления и оценки
соответствия изображения тексту.

Предполагается знакомство с self-attention, cross-entropy и
[[00 Учебник/15 Embeddings, Retrieval и RAG/60 Embeddings и metric learning|контрастивным обучением]].
Числовые примеры ниже используют явно заданные учебные тензоры.
Они проверяют операции и функции потерь, но не измеряют качество
предобученной модели на фотографиях.

## Две задачи: понять чужую модальность и породить её

<!-- source_unit_id: lecture-17-section-2-lecture-17-multimodal-models -->

Для ответа на вопрос по фотографии можно передать языковой модели
непрерывные зрительные признаки. Их не обязательно переводить
в номера из текстового словаря. В генеративной VLM эти векторы
становятся условием для предсказания текстового ответа.

Для получения изображения на выходе требуется также определить,
что именно генерируется и как из этого восстановить пиксели.
Контрастивный вектор CLIP не обучен быть обратимым описанием
изображения. Две фотографии могут иметь близкие векторы и различаться
деталями, которые понадобились бы для восстановления.

В [[00 Учебник/16 Multimodal Models/64g Диффузионные и flow-модели изображений|главе о diffusion и flow matching]]
изображение создаёт отдельный непрерывный генератор.
В [[00 Учебник/16 Multimodal Models/64h Единая мультимодальная последовательность и Chameleon|Chameleon]]
используются дискретные коды изображения, которые можно
предсказывать вместе с текстом. Здесь сначала разбирается входная
сторона: как получить признаки изображения и научить их сопоставляться
с языком. Эти две задачи разделены и в
[Stanford CS336, Lecture 17](https://github.com/stanford-cs336/lectures/blob/8b59b50730766695c2ffedd1a79c50cd09b9eb91/lecture_17.py).

## 1. Изображение как тензор

Цветное изображение представим тензором
$X\in\mathbb R^{H\times W\times C}$. Высота и ширина задаются $H$
и $W$, число каналов — $C$; у RGB оно равно трём.
В библиотеках также используется порядок $[C,H,W]$ или
$[B,C,H,W]$ для пакета. Порядок осей не меняет изображение,
но меняет способ разворачивания его элементов в вектор.

В [ViT, §3.1](https://arxiv.org/abs/2010.11929v2) изображение
делится на непересекающиеся участки $P\times P$, или patches.
Если обе стороны делятся на $P$ без остатка, число участков равно

$$
N=\frac{H}{P}\frac{W}{P}.
$$

Для $224\times224$ при $P=16$ получается сетка $14\times14$,
то есть 196 участков. В каждом RGB-участке содержится
$16\cdot16\cdot3=768$ чисел. Одна общая линейная проекция
переводит каждый такой вектор в размерность $D$.

![[00 Учебник/Assets/Figures/curated/vlm-2026/vit-figure1-patch-sequence.png]]

*Alexey Dosovitskiy et al., [An Image is Worth 16×16 Words](https://arxiv.org/abs/2010.11929v2),
рисунок 1 в высокоразрешённой копии Stanford CS336.
Нижняя часть показывает участки изображения и общую линейную проекцию;
сверху — Transformer encoder и классификационная голова.
Дополнительная позиция 0 соответствует классификационному токену.*

### Patch — это позиция в последовательности, а не слово из словаря

Развёрнутый участок обозначим $x_n\in\mathbb R^{P^2C}$.
Его представление вычисляется как

$$
e_n=x_nW+b,\qquad
W\in\mathbb R^{P^2C\times D}.
$$

Матрица $W$ одинакова для всех участков. Поэтому для одинакового
локального содержимого до добавления позиции получается одинаковый
вектор. Отдельного поиска ближайшего «визуального слова» в словаре
в этой операции нет. В данном случае *visual token* означает
позицию, содержащую непрерывный вектор признаков.

Проследим развёртку на RGB-тензоре $4\times4\times3$ с участками
$2\times2$. Все элементы тензора последовательно пронумерованы
от 0 до 47. Это условные значения для проверки индексов, не
нормализованная фотография.

Левый верхний участок включает первые два пикселя первой строки
и первые два пикселя второй. При порядке HWC его вектор равен
$(0,1,2,3,4,5,12,13,14,15,16,17)$. Следующие участки идут
слева направо, затем сверху вниз. Если вместо этого сделать
простой reshape всего изображения в четыре строки, границы
участков окажутся неверными: соседние элементы строки тензора
не совпадают с прямоугольной областью изображения.

```python
import numpy as np

image = np.arange(48, dtype=float).reshape(4, 4, 3)
P, D = 2, 2
patches = (
    image.reshape(2, P, 2, P, 3)
    .transpose(0, 2, 1, 3, 4)
    .reshape(4, P * P * 3)
)
assert patches[0].tolist() == [0, 1, 2, 3, 4, 5, 12, 13, 14, 15, 16, 17]
W = np.arange(24, dtype=float).reshape(12, D) / 100
bias = np.array([-1., 1.])
projected = patches @ W + bias

# Те же веса в формате [out_channels, in_channels, P, P].
kernel = W.reshape(P, P, 3, D).transpose(3, 2, 0, 1)
chw = image.transpose(2, 0, 1)
conv = []
for row in range(0, 4, P):
    for col in range(0, 4, P):
        local = chw[:, row:row + P, col:col + P]
        conv.append(np.einsum("ocij,cij->o", kernel, local) + bias)
assert np.allclose(projected, conv)
assert np.allclose(projected[0], [15.24, 18.26])
```

Форма результата — $[4,2]$. Первые два числа равны 15.24 и 18.26.
В коде свёртка с kernel size и stride, равными $P$, вычисляет
ту же линейную функцию на каждом участке. Так устроен входной
`Conv2d` в
[оригинальном CLIP VisionTransformer](https://github.com/openai/CLIP/blob/d05afc436d78f1c48dc0dbf8e5980a9d471f35f6/clip/model.py#L206).
Согласование порядка C/H/W и порядка коэффициентов матрицы
обязательно для этой эквивалентности.
В конкретной реализации CLIP у входной свёртки нет смещения;
учебный расчёт выше включает общий случай с $b$.

Само разбиение на участки не выбрасывает пиксели: перестановку
и reshape можно обратить. Потери возникают при изменении размера,
обрезке или преобразовании признаков. В учебном примере линейное
отображение из 12 вещественных координат в 2 имеет ненулевое
ядро: существуют изменения входа, не меняющие выход.
В общем случае размер участка сам по себе ещё не доказывает,
что вся информация внутри него уничтожена.

### Позиции и классификационный токен

Перед сеткой признаков в исходном ViT стоит обучаемый токен
`[CLS]`. Это отдельный вектор, а не участок с нулевыми пикселями.
После Transformer его состояние используется для классификации.
В ViT-Base/16 при входе $224\times224$ последовательность
имеет 197 позиций: 196 участков и один `[CLS]`.
При ширине 768 форма одного входа равна $[197,768]$.

К каждому вектору добавляется обучаемое позиционное представление.
Без него self-attention не отличает произвольную перестановку
участков от перестановки их выходных состояний. Для матрицы
перестановки $\Pi$ слой без позиционной информации, с полным
attention и отключённым dropout обладает свойством

$$
f(\Pi Z)=\Pi f(Z).
$$

Если `[CLS]` оставить на месте, а остальные позиции переставить,
его выход не изменится. Модель сможет учитывать набор локальных
признаков, но не узнает из одного порядка строк, что один объект
стоял слева от другого.

В следующем расчёте используется только одна attention-операция,
без обученной сети. Перестановка участков сохраняет первый
выход без позиций. Когда позиционные векторы закреплены
за местами, тот же обмен содержимым меняет результат.

```python
import numpy as np

def attend(z):
    scores = z @ z.T / np.sqrt(z.shape[1])
    weights = np.exp(scores - scores.max(axis=1, keepdims=True))
    weights /= weights.sum(axis=1, keepdims=True)
    return weights @ z

z = np.array([[.2, .1], [1, 0], [0, 1], [.5, .5], [-.5, .2]])
positions = np.array([[0, 0], [.2, 0], [0, .3], [-.2, 0], [0, -.3]])
permutation = [0, 2, 1, 3, 4]
assert np.allclose(attend(z[permutation]), attend(z)[permutation])
assert np.allclose(attend(z)[0], [.27125546, .36137529])
assert np.allclose(attend(z)[0], attend(z[permutation])[0])
original = attend(z + positions)[0]
swapped = attend(z[permutation] + positions)[0]
assert not np.allclose(original, swapped)
```

В исходном ViT позиции хранятся как обучаемая одномерная таблица;
это не означает, что модель использует только одномерные отношения.
Её элементы соответствуют определённым местам двумерной сетки.
При переходе на большее разрешение таблицу интерполируют
с учётом этой сетки; позиция `[CLS]` обрабатывается отдельно.
Метод описан в §3.2 статьи, а двумерные и мультимодальные
позиции продолжаются в
[[00 Учебник/16 Multimodal Models/64b Разрешение, tiling и пространственные позиции|главе о разрешении и позициях]].

### Блок Transformer в ViT

В зрительном encoder attention полный: каждая позиция может
обращаться ко всем участкам и к `[CLS]`. Причинной маски,
запрещающей смотреть на последующие позиции, здесь нет.
Изображение поступает целиком, и задача не требует предсказывать
его участки по одному слева направо.

В исходном ViT один блок состоит из двух преобразований
с предварительной LayerNorm и остаточными соединениями:

$$
U=Z+\operatorname{MSA}(\operatorname{LN}(Z)),
$$

$$
Z'=U+\operatorname{MLP}(\operatorname{LN}(U)).
$$

MSA обозначает multi-head self-attention. Он объединяет
информацию разных позиций. MLP применяется к каждой позиции
отдельно, с общими весами: первая линейная матрица расширяет
вектор, затем идут GELU и проекция обратно в размерность $D$.
Обе ветви возвращают тензор формы $[N+1,D]$, поэтому их
можно прибавить к входу. Блоки повторяются $L$ раз.

После первого attention-слоя признак участка уже может зависеть
от других частей изображения. Зрительный encoder выдаёт
контекстуальные признаки, а не независимый список локальных
дескрипторов. Проекция patches и self-attention выполняют
разные операции: первая обрабатывает каждый участок общими
весами, второй соединяет информацию между позициями.
В исходном ViT итоговый нормированный вектор `[CLS]`
поступает в классификационную голову; в ViT-варианте CLIP
он проецируется в пространство сравнения с текстом.

## 2. Цена более высокого разрешения

Для одного и того же patch size увеличение каждой стороны
вдвое увеличивает число участков в четыре раза.
Полная матрица attention одного head имеет размер $N\times N$,
поэтому число её элементов возрастает примерно в 16 раз.

| Вход | Размер участка | Сетка | Patches | Позиции с одним CLS |
|---|---:|---:|---:|---:|
| $224\times224$ | 16 | $14\times14$ | 196 | 197 |
| $448\times448$ | 16 | $28\times28$ | 784 | 785 |
| $336\times336$ | 14 | $24\times24$ | 576 | 577 |
| $672\times672$ | 14 | $48\times48$ | 2304 | 2305 |

Это оценка числа попарных взаимодействий, а не обещание
16-кратной задержки всей сети. Проекции и MLP зависят от $N$
линейно при фиксированной ширине; эффективные kernels не обязаны
материализовывать полную матрицу в памяти. Но арифметическая
стоимость полного attention всё равно зависит от числа пар.

Сохранение большего количества токенов имеет смысл только вместе
с подготовкой изображения. Увеличить сетку после того, как
мелкий текст исчез при уменьшении, недостаточно.
И наоборот, patch encoder может читать достаточно детальное
изображение, но последующее сжатие до нескольких векторов
потеряет нужные локальные различия.

### Что теряется при resize и center crop

В
[preprocessing исходного CLIP](https://github.com/openai/CLIP/blob/d05afc436d78f1c48dc0dbf8e5980a9d471f35f6/clip/clip.py#L79)
короткая сторона приводится к размеру, заданному моделью,
затем вырезается центральный квадрат. После перевода в RGB
значения пикселей преобразуются в тензор и нормируются
по каналам. Размер берётся из `model.input_resolution`:
336 относится к ViT-L/14@336px, а не ко всем вариантам CLIP.

Пусть исходный кадр имеет ширину 640 и высоту 480,
а вход модели равен 336. Масштабирование по короткой стороне
даёт $448\times336$. Центральный crop оставляет 336 столбцов:
по 56 столбцов с каждой стороны масштабированного кадра
отрезаются. В исходных координатах это примерно по 80 пикселей
слева и справа. Подпись у края может исчезнуть ещё до ViT.

Уменьшение и crop решают разные задачи. Уменьшение распределяет
исходные детали по меньшей сетке, crop исключает области целиком.
Для общих категорий фотографии такая подготовка может быть
достаточной; для страницы с текстом или интерфейса последствия
нужно проверять на расположении нужных сведений.
AnyRes, tiling, динамическое разрешение и объединение участков
подробно разбираются в
[[00 Учебник/16 Multimodal Models/64b Разрешение, tiling и пространственные позиции|главе 64.2]].

## 3. От классификации к общему пространству изображения и текста

<!-- source_unit_id: lecture-17-contrastive-vision-language-training -->

Обычный классификатор содержит матрицу весов для фиксированного
набора классов. Для нового класса ему обычно нужны обучающие
примеры и изменение классификационной головы.
[CLIP](https://proceedings.mlr.press/v139/radford21a.html)
сопоставляет изображение с текстом: отдельные кодировщики
выдают векторы, которые можно сравнивать скалярным произведением.

Зрительный encoder сначала возвращает признаки своей размерности,
текстовый — своей. Отдельные обучаемые проекции переводят их
в общее пространство размерности $d_e$.
Одинаковое число координат ещё не обеспечивает сопоставимость;
она появляется в ходе совместного обучения на парах.

Исходный CLIP обучался на WIT (WebImageText), корпусе
из 400 миллионов пар изображения и текста из открытых
интернет-источников. Авторы собирали пары по 500 тысячам
запросов и ограничивали число пар для одного запроса,
чтобы уменьшить перекос в пользу часто встречающихся понятий
([§2.1 статьи](https://proceedings.mlr.press/v139/radford21a.html)).
Подпись из интернета не является исчерпывающей разметкой
изображения: она может назвать собаку, но не указать её
положение или цвет ошейника. Обучение использует именно
те соответствия, которые есть в корпусе.

![[00 Учебник/Assets/Figures/curated/vlm-2026/clip-figure1-training-and-zero-shot.png]]

*Alec Radford et al.,
[Learning Transferable Visual Models From Natural Language Supervision](https://proceedings.mlr.press/v139/radford21a.html),
рисунок 1 в исходной копии Stanford CS336.
Слева — все соответствия изображений и текстов внутри пакета;
справа — получение нового классификатора из описаний категорий.*

### Как два кодировщика получают один вектор

В ViT-варианте CLIP глобальный зрительный признак берётся
из выходной позиции `[CLS]` и проецируется в общее пространство.
Не все модели CLIP используют ViT: исходная работа исследовала
также изменённые ResNet с attention pooling.
Название CLIP прежде всего задаёт обучение и способ сопоставления,
а не единственную архитектуру vision encoder.

Текстовая ветвь исходного CLIP использует Transformer с causal
mask. Состояние завершающего токена EOT видит предшествующую
подпись; после нормировки и проекции оно становится вектором текста.
Это не mean pooling всех слов и не классификационный CLS
двунаправленного BERT. У выпущенных авторами моделей стандартное
текстовое окно — 77 токенов вместе со служебными позициями.
Длинная подпись может не поместиться.

Causal mask ограничивает доступ к последующим позициям текста.
В обучении CLIP текстовая ветвь сравнивает готовые подписи
с изображениями, а не оптимизирует вероятность очередного слова.
Выходы функций `encode_image` и `encode_text` в
[оригинальном коде](https://github.com/openai/CLIP/blob/d05afc436d78f1c48dc0dbf8e5980a9d471f35f6/clip/model.py#L340)
дополнительно нормируются внутри `forward` перед вычислением сходств.
При самостоятельном использовании этих функций нормировку
нужно выполнить явно.

### Пакет пар и симметричная функция потерь

Пусть пакет содержит $B$ наблюдавшихся пар $(I_i,T_i)$.
После нормировки получены единичные векторы $v_i$ и $t_i$.
Матрица логитов имеет вид

$$
S_{ij}=a\,v_i^\top t_j,\qquad a=\exp(\gamma)>0.
$$

Масштаб $a$ обучается. Его также записывают как обратную
температуру $1/\tau$. Без него скалярное произведение единичных
векторов ограничено от −1 до 1 и softmax по большому числу
подписей трудно сделать достаточно различающим.

Диагональ соответствует исходным парам. Для каждой строки
нужно выбрать её диагональный элемент среди всех текстов:

$$
\ell_i^{I\to T}
=-S_{ii}+\log\sum_j\exp S_{ij}.
$$

Затем то же делается по столбцам, то есть для каждого текста
выбирается изображение:

$$
\ell_i^{T\to I}
=-S_{ii}+\log\sum_j\exp S_{ji}.
$$

Итоговая потеря усредняет оба направления и все исходные пары:

$$
\mathcal L_{\mathrm{CLIP}}
=\frac{1}{2B}\sum_i
\left(\ell_i^{I\to T}+\ell_i^{T\to I}\right).
$$

Для учебного пакета из трёх пар зададим уже масштабированные
логиты:

$$
S=\begin{pmatrix}
8.1&2.0&-0.4\\
1.7&7.3&0.9\\
-0.2&1.1&6.8
\end{pmatrix}.
$$

Первая строка даёт
$-8.1+\log(e^{8.1}+e^{2.0}+e^{-0.4})\approx0.002443$.
Первая потеря по столбцу получается немного другой:
$\approx0.001908$. В ней соперниками являются другие
изображения, а не другие подписи.

```python
import numpy as np

def logsumexp(x, axis):
    maximum = x.max(axis=axis, keepdims=True)
    return np.squeeze(
        maximum + np.log(np.exp(x - maximum).sum(axis=axis, keepdims=True)),
        axis=axis,
    )

def clip_loss(scores):
    scores = np.asarray(scores, dtype=float)
    if (scores.ndim != 2 or scores.shape[0] != scores.shape[1]
            or scores.shape[0] == 0 or not np.isfinite(scores).all()):
        raise ValueError("finite nonempty square matrix required")
    row = logsumexp(scores, 1) - np.diag(scores)
    col = logsumexp(scores, 0) - np.diag(scores)
    return (row.mean() + col.mean()) / 2

scores = np.array([[8.1, 2., -.4], [1.7, 7.3, .9], [-.2, 1.1, 6.8]])
loss = clip_loss(scores)
assert np.isclose(loss, .004070330028012345)
wrong = scores.copy()
wrong[0, 1] = 8.0
assert clip_loss(wrong) > loss
assert np.isclose(clip_loss(scores + 1000), loss)
assert np.isclose(clip_loss(np.zeros((2, 2))), np.log(2))
```

Увеличение $S_{01}$ создаёт сильного конкурента правильной
подписи первого изображения и одновременно неверную пару
для второго текста. Оба направления участвуют в градиенте.
Прибавление одной константы ко всем логитам ничего не меняет:
softmax определяется относительными оценками.

### Отрицательные пары и неоднозначные подписи

Внедиагональные сочетания считаются отрицательными потому,
что их не было среди исходных пар, а не потому, что человек
проверил их ложность. Две фотографии собак могут иметь
одинаковую подпись «собака на снегу». Если они стоят в одном
пакете, кодировщик получит два одинаковых текстовых вектора,
но диагональная цель потребует различить их номера.

При двух одинаковых подписях вероятности выбора текста
для каждого изображения равны $1/2$ независимо от качества
зрительных признаков. Потеря этого направления не станет
нулевой. Поэтому состав пакета, дубликаты и ложные отрицательные
примеры влияют на обучение. Увеличение пакета добавляет
как полезные трудные сравнения, так и неоднозначные пары.

### Почему задача выбора пары отличается от генерации подписи

Изображению может соответствовать несколько корректных текстов.
Одна подпись называет объект, другая — его действие, третья —
место съёмки. Для генеративной цели требуется предсказывать
конкретную последовательность слов. Контрастивная цель требует
отличить наблюдавшуюся подпись от остальных кандидатов пакета.
Это разные обучающие сигналы.

![[00 Учебник/Assets/Figures/curated/vision-encoders-review-2026-10/clip-objectives.png]]

*Alec Radford et al.,
[Learning Transferable Visual Models From Natural Language Supervision](https://proceedings.mlr.press/v139/radford21a.html),
рисунок 2, CC BY 4.0. В эксперименте 2021 года сравниваются
предсказание подписи, предсказание набора слов и контрастивная
цель. Горизонтальная ось — число обработанных изображений;
вертикальная — zero-shot accuracy на ImageNet.*

В этом эксперименте контрастивный вариант быстрее по числу
обработанных примеров достигает заданного качества классификации.
График не доказывает, что captioning всегда хуже: измеряется
именно zero-shot перенос на ImageNet, а не качество подписей.
Число обработанных изображений также не тождественно FLOPs
или времени обучения. Указанные на графике отношения нельзя
перенести на новые архитектуры и оборудование.

## 4. Как из CLIP получается zero-shot классификатор

Пусть нужны категории «кошка», «собака» и «велосипед».
Для каждой составляется описание, например
`a photo of a dog`, и вычисляется нормированный текстовый вектор.
Эти векторы становятся весами нового классификатора.
Для изображения с вектором $v$ оценка класса $c$ равна
$a\,v^\top t_c$, а выбранный класс имеет максимальную оценку.

Новые размеченные фотографии для построения таких весов
не используются. Но изображения и подписи участвовали
в предобучении, а пользователь всё равно задаёт названия
классов и шаблоны описания. Zero-shot не означает обучение
без данных вообще.

### Шаблоны описания и их усреднение

Голое слово `crane` может обозначать птицу или подъёмный кран.
Слово `boxer` — породу собаки или спортсмена.
В [полной версии CLIP, §3.1.4](https://arxiv.org/abs/2103.00020v1)
контекст названия и несколько шаблонов помогают задать,
что именно следует распознать.

Для одного класса можно получить векторы по нескольким
описаниям, нормировать каждый, усреднить и снова нормировать
результат. Такой ансамбль выполняется в пространстве
представлений. Один усреднённый вектор класса можно заранее
сохранить; прогонять каждый шаблон при каждом изображении
не требуется. Это отличается от усреднения softmax-вероятностей
нескольких классификаторов.

Рассмотрим учебные двумерные векторы. Для изображения
$v=(1,0)$ и классов с векторами $(0.8,0.6)$, $(0.6,0.8)$
и $(-0.8,0.6)$ cosine scores равны $0.8$, $0.6$, $-0.8$.
При масштабе 5 softmax даёт первому классу примерно 0.731.

```python
import numpy as np

def unit(x):
    x = np.asarray(x, dtype=float)
    norm = np.linalg.norm(x, axis=-1, keepdims=True)
    if not np.isfinite(x).all() or np.any(norm == 0):
        raise ValueError("finite nonzero vectors required")
    return x / norm

def class_probabilities(image, labels, scale):
    if not np.isfinite(scale) or scale <= 0:
        raise ValueError("positive finite scale required")
    logits = scale * (unit(labels) @ unit(image))
    exp = np.exp(logits - logits.max())
    return exp / exp.sum()

image = np.array([1., 0.])
labels = np.array([[.8, .6], [.6, .8], [-.8, .6]])
before = class_probabilities(image, labels, 5)
assert np.isclose(before[0], .730879336)
extra = np.array([[.9, np.sqrt(.19)]])
after = class_probabilities(image, np.concatenate([labels, extra]), 5)
assert after.argmax() == 3
assert np.isclose(after[0], .331462100)
templates = unit([[.8, .6], [1., 0.]])
prototype = unit(templates.mean(axis=0))
assert np.allclose(prototype, [.948683298, .316227766])
```

При добавлении четвёртого близкого класса вероятность первого
падает примерно до 0.331, хотя изображение и старые векторы
не менялись. Их исходные cosine scores тоже остались прежними.
Поэтому 0.731 нельзя читать как универсальную вероятность
«это действительно кошка». Softmax зависит от набора кандидатов,
масштаба и формулировок описания.

При поиске действует тот же способ сравнения: изображения
можно закодировать заранее, а в момент запроса вычислить
только его текстовый вектор. Для обратного поиска заранее
кодируют тексты. Независимость двух ветвей позволяет кешировать
представления, но исключает совместное перечитывание пары
внутри encoder. Cross-encoder решает другую вычислительную задачу.

### Zero-shot, linear probe и fine-tuning

При linear probe зрительный encoder заморожен, а новая
матрица классификации обучается на размеченных изображениях.
При fine-tuning изменяются также веса encoder.
У этих режимов разный доступ к данным новой задачи, поэтому
их результаты нельзя обозначать одним словом «точность CLIP»
без указания протокола.

![[00 Учебник/Assets/Figures/curated/vision-encoders-review-2026-10/clip-zero-shot-linear-probe.png]]

*Alec Radford et al.,
[Learning Transferable Visual Models From Natural Language Supervision](https://proceedings.mlr.press/v139/radford21a.html),
рисунок 5, CC BY 4.0. Звезда — zero-shot CLIP; линии —
классификаторы, обученные по разному числу размеченных примеров
на класс. Это усреднение по 20 наборам из эксперимента 2021 года,
а не результат для любой новой задачи.*

На этом наборе zero-shot вариант в среднем сопоставим
с линейным классификатором на тех же признаках, обученным
на четырёх примерах на класс. Текстовое описание напрямую
задаёт понятие класса; несколько фотографий допускают много
разных обобщений. При большем числе размеченных примеров
обученная голова на графике получает более высокий результат.
Расположение звезды не даёт общего правила, что отсутствие
примеров лучше их использования.

Шаблоны, названия категорий, их порядок, preprocessing,
модель, checkpoint и способ нормировки сохраняются вместе
с результатами. Подбор лучшего шаблона по тестовой выборке
уже использует информацию о тесте, даже если градиенты
по этой выборке не вычислялись.

## 5. Что именно выучивает контрастивная модель

Обучение требует отличать пары, но не задаёт единственного
способа представить изображение. Если в обучающем корпусе
подписи различаются прежде всего объектами и темой сцены,
распознавание этих признаков помогает уменьшать loss.
Точное число одинаковых предметов или порядок объектов
может получать гораздо меньше обучающего сигнала.

Глобальный вектор может хорошо находить «собаку на снегу»,
но не отличать два положения маленькой подписи на фотографии.
Это нужно проверять отдельной задачей, а не выводить
из среднего результата поиска. В
[§6 CLIP](https://proceedings.mlr.press/v139/radford21a.html)
обсуждаются ограничения переноса и влияние выбора задач
на оценку модели.

Для генеративной VLM часто нужны локальные выходы vision
encoder до итогового pooling, а не один финальный вектор
для контрастивного сравнения. Эти выходы имеют форму
$[N,D_v]$, тогда как глобальный embedding — $[d_e]$.
Наличие сотен позиций сохраняет возможность обратиться
к разным областям изображения, но само по себе
не гарантирует распознавание мелкого текста.

Выбор слоя, нормировки, удаления CLS и последующей проекции
является частью конкретной архитектуры. Нельзя считать,
что предпоследний слой любого CLIP всегда лучше последнего,
или механически заменить encoder только по совпадению
размерностей. Такие интерфейсы рассматриваются в
[[00 Учебник/16 Multimodal Models/64a Connectors и fusion|следующей главе]].

## CLIP и SigLIP: две формы контрастивного обучения

<!-- source_unit_id: lecture-17-clip-siglip-training-sequence -->

CLIP требует выбрать одно соответствие среди всех элементов
строки и столбца. [SigLIP](https://arxiv.org/abs/2303.15343v4)
вместо этого оценивает каждую пару отдельно: наблюдалась
ли пара изображения и текста в исходном пакете?

Для совпадающей пары метка $y_{ij}=+1$, для остальных — $-1$.
Пусть логит включает масштаб и обучаемое смещение:

$$
z_{ij}=a\,v_i^\top t_j+b.
$$

Потеря одной пары равна $\log(1+\exp(-y_{ij}z_{ij}))$.
Полная функция из Algorithm 1 нормируется по числу исходных
пар $B$, а не по числу всех сравнений $B^2$:

$$
\mathcal L_{\mathrm{SigLIP}}
=\frac1B\sum_{i,j}
\log\left(1+\exp(-y_{ij}z_{ij})\right).
$$

Фрагмент исходного псевдокода сохранён на языке оригинала:

```text
logits = dot(zimg, ztxt.T) * t + b
labels = 2 * eye(n) - ones(n) # -1 with diagonal 1
l = -sum(log_sigmoid(labels * logits)) / n
```

Источник: Zhai et al., Algorithm 1, CC BY 4.0.
Знак смещения здесь соответствует псевдокоду и
[reference implementation](https://github.com/google-research/big_vision/blob/0127fb6b337ee2a27bf4e54dea79cff176527356/big_vision/trainers/proj/image_text/siglip.py#L287):
оно добавляется к логиту перед сигмоидой.

### Расчёт на четырёх сравнениях

Для двух исходных пар пусть уже получены логиты

$$
Z=\begin{pmatrix}
2&-1\\
-2&1
\end{pmatrix}.
$$

Положительные пары находятся на диагонали. Для логита 2 положительной
пары потеря равна $\log(1+e^{-2})\approx0.126928$.
Для логита −1 отрицательной пары она равна
$\log(1+e^{-1})\approx0.313262$. Остальные два слагаемых
имеют те же значения в обратном порядке.
Сумма четырёх потерь, делённая на два, равна примерно 0.440190.

```python
import numpy as np

def siglip_loss(logits):
    logits = np.asarray(logits, dtype=float)
    if (logits.ndim != 2 or logits.shape[0] != logits.shape[1]
            or logits.shape[0] == 0 or not np.isfinite(logits).all()):
        raise ValueError("finite nonempty square matrix required")
    B = len(logits)
    labels = 2 * np.eye(B) - 1
    return np.logaddexp(0, -labels * logits).sum() / B

logits = np.array([[2., -1.], [-2., 1.]])
assert np.isclose(siglip_loss(logits), .4401896985611954)

B = 3
neutral = np.zeros((B, B))
prior_bias = -np.log(B - 1)
assert siglip_loss(neutral + prior_bias) < siglip_loss(neutral)
# Каждый прямоугольный блок вносит сумму; общий делитель остаётся B.
labels = 2 * np.eye(B) - 1
terms = np.logaddexp(0, -labels * (neutral + prior_bias))
blocks = [np.arange(2), np.arange(2, B)]
chunked = sum(terms[np.ix_(r, c)].sum() for r in blocks for c in blocks) / B
assert np.isclose(chunked, siglip_loss(neutral + prior_bias))
```

Значения CLIP loss и SigLIP loss нельзя напрямую сравнивать
как показатели того, какая модель лучше. У них разные цели
и разные масштабы. Если в SigLIP заменить деление на $B$
делением на $B^2$, все градиенты уменьшатся в $B$ раз.
Это может быть допустимым вариантом реализации,
но уже требует согласованной настройки оптимизации.

### Зачем нужно смещение

В пакете из $B$ исходных пар имеются $B$ положительных
и $B(B-1)$ отрицательных сочетаний. Если все логиты вначале
равны нулю, сигмоида выдаёт 0.5 каждому сочетанию.
Доля положительных примеров при этом равна только $1/B$.

Если временно принять все скалярные произведения равными нулю
и менять только $b$, оптимум удовлетворяет
$\sigma(b)=1/B$. При $B>1$ отсюда

$$
b=-\log(B-1).
$$

Для $B=3$ это примерно −0.693. Для пакета около 32 тысяч
исходных пар — около −10.4. В статье масштаб и смещение
инициализируются как $a=10$ и $b=-10$.
Так начальный logit лучше согласуется с сильным преобладанием
отрицательных пар; далее оба параметра обучаются.

Это рассуждение про частоту меток в обучающих сравнениях.
Оно не делает выход сигмоиды калиброванной вероятностью
соответствия любой новой подписи фотографии. Состав кандидатов,
распределение данных и частота подходящих подписей
при применении могут быть другими.

### Блочное и распределённое вычисление

Отдельному слагаемому SigLIP не нужны остальные элементы
строки, поэтому матрицу можно обрабатывать блоками:
вычислить логиты блока, накопить сумму потерь и перейти
к следующему блоку. В коде выше это проверено на пакете,
разделённом на части разного размера.

![[00 Учебник/Assets/Figures/curated/stanford-cs336-2026/multimodal/siglip-parallelism.png]]

*Xiaohua Zhai et al., [Sigmoid Loss for Language Image Pre-Training](https://arxiv.org/abs/2303.15343v4),
рисунок 1 в исходной копии Stanford CS336.
Три устройства держат по четыре изображения и текста.
Сначала вычисляются локальные пары; затем текстовые
представления передаются между устройствами. После полного
обхода обработаны все сочетания изображений и текстов,
а суммы потерь объединены.*

В примере на рисунке всего 12 исходных пар, поэтому требуется
144 сравнения. На первом шаге каждое устройство вычисляет
свой блок $4\times4$, то есть вместе они обрабатывают
48 сочетаний. Два следующих обмена текстовыми векторами
позволяют вычислить оставшиеся 96. Число сравнений
не уменьшилось; уменьшился объём одновременно хранимых логитов.

В схеме из §3.3 вместо хранения всей матрицы используется
локальный блок и обмен представлениями между устройствами.
Отсутствие all-gather в этой схеме не означает отсутствие
сетевого обмена: на рисунке показана передача текстовых векторов.
Конкретная реализация SigLIP может использовать и all-gather.

Для CLIP суммы в знаменателях softmax должны учитывать
всех кандидатов соответствующей строки или столбца.
Независимо усреднить cross-entropy отдельных блоков
и получить тот же глобальный loss нельзя. Его также можно
вычислять блочно, но нужно согласованно накопить
нормировочные суммы и градиенты.
Разница касается структуры вычисления loss, а не запрета
на эффективные kernels для CLIP.

![[00 Учебник/Assets/Figures/curated/vision-encoders-review-2026-10/siglip-batch-size.png]]

*Xiaohua Zhai et al., [Sigmoid Loss for Language Image Pre-Training](https://arxiv.org/abs/2303.15343v4),
средняя панель рисунка 2, CC BY 4.0. По горизонтали —
размер пакета в тысячах; по вертикали — zero-shot accuracy
на ImageNet. Это эксперимент SigLIP с 9 миллиардами
обработанных примеров, не соседние варианты SigLiT
и multilingual SigLIP из полного рисунка.*

В этом эксперименте SigLIP достигает высокого результата
при меньшем пакете, а очень большие пакеты не улучшают
ни sigmoid-, ни softmax-вариант. Из графика не следует,
что размер пакета перестал влиять на обучение.
Он меняет число отрицательных сравнений, частоту
обновления весов при фиксированном числе просмотренных
примеров и условия оптимизации.

SigLIP также не устраняет ложные отрицательные пары:
одинаковые или взаимозаменяемые подписи всё ещё могут
получить противоположные метки. Смена функции потерь
не заменяет подготовку корпуса.

## 6. Две разные задачи, которые часто называют VLM

Dual encoder вроде CLIP возвращает по одному глобальному
вектору для изображения и текста. Сравнение этих векторов
даёт оценку соответствия. Это удобно для поиска:
коллекцию можно закодировать заранее.

Генеративная vision-language model получает изображение
и вопрос и предсказывает текстовый ответ по токенам.
Она должна связать локальные признаки с языковыми
состояниями и обработать инструкцию. Высокий результат
контрастивного поиска ещё не доказывает, что модель умеет
это делать.

| Система | Результат | Обработка пары |
|---|---|---|
| Dual encoder | Векторы и сходство | Каждая ветвь вычисляется независимо |
| Cross-encoder | Оценка пары или выход отдельной задачи | Изображение и текст взаимодействуют внутри сети |
| Генеративная VLM | Распределение следующего токена ответа | Визуальные признаки служат условием генератора |

Для генеративного варианта нужен connector, например
projector, Q-Former или Perceiver Resampler, либо отдельные
cross-attention-блоки. Эти способы подключения меняют
число визуальных позиций и место взаимодействия с текстом.
Они не превращают непрерывные признаки автоматически
в обычные слова из текстового словаря.

## 7. Диагностические проверки

Классификация сцены, поиск изображения и чтение числа
в таблице требуют разных различий в представлении.
Для оценки сохраняют отдельные результаты по этим задачам,
а не только средний балл всех изображений.

Проверка пространственных отношений может использовать
пары изображений и пары подписей, содержащих одни и те же
слова в разном порядке. Например: «человек ведёт лошадь»
и «лошадь ведёт человека». Одинаковый набор слов
не задаёт одинаковое отношение между объектами.

Так построена постановка
[Winoground, §3.2](https://openaccess.thecvf.com/content/CVPR2022/html/Thrush_Winoground_Probing_Vision_and_Language_Models_for_Visio-Linguistic_Compositionality_CVPR_2022_paper.html).
Для одной группы сравниваются все четыре сочетания
двух изображений и двух подписей. Требуется одновременно
выбрать правильную подпись для каждого изображения
и правильное изображение для каждой подписи.

```python
import numpy as np

def paired_scores(scores):
    scores = np.asarray(scores, dtype=float)
    if scores.shape != (2, 2) or not np.isfinite(scores).all():
        raise ValueError("finite 2-by-2 scores required")
    # Строки — изображения, столбцы — подписи; правильна диагональ.
    text = scores[0, 0] > scores[0, 1] and scores[1, 1] > scores[1, 0]
    image = scores[0, 0] > scores[1, 0] and scores[1, 1] > scores[0, 1]
    return bool(text), bool(image), bool(text and image)

assert paired_scores([[3, 2], [1, 2.5]]) == (True, True, True)
assert paired_scores([[3, 2], [4, 5]]) == (True, False, False)
assert paired_scores(np.ones((2, 2))) == (False, False, False)
```

Во второй матрице обе строки предпочитают правильные
подписи. Но первая подпись получает более высокую оценку
для второго изображения, чем для своего. Группа целиком
не решена. Проверка только одного направления скрыла
бы эту ошибку. Все числа здесь заданы для разбора метрики,
а не являются результатами CLIP на Winoground.

Для документов полезны также изменения размера текста,
перестановки строк и столбцов, удаление области с ответом,
сохранение или обрезка краёв страницы. Если ответ можно
восстановить из контекста даже после закрытия числа,
неизменившийся результат ещё не доказывает,
что модель прочитала скрытую ячейку.
Нужны примеры, где ответ действительно зависит от этой области.

Проверяют исходное изображение, результат preprocessing,
сетку encoder, выбранный слой и то, что получит следующий
модуль. Иначе ошибку crop легко приписать языковой модели,
а потерю локальных деталей при pooling — недостаточному
разрешению исходного файла.

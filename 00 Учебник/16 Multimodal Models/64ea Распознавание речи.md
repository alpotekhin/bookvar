В записи сказано: «Алло, я слышу слабый шум». Для обучения
распознавателя можно дать запись и эту строку. Указывать, к каким
отсчётам относятся отдельные буквы, обычно не нужно.
Но модели всё равно предстоит связать короткий ряд букв или
субтокенов с гораздо более длинным рядом звуковых кадров.

<a id="asr-input"></a>

## Из звуковых отсчётов в текст

При 16 кГц половина секунды занимает 8 000 отсчётов. Возьмём окно
25 мс и шаг 10 мс: по 400 отсчётов в окне, сдвиг на 160. Без
дополнения краёв получится 48 полных окон. Для каждого можно
вычислить энергии в mel-полосах и взять их логарифмы. Так 8 000
отсчётов превращаются в последовательность из 48 векторов.
Шаги этого преобразования показаны в
[[02 Areas/ML & DL/00 Учебник/16 Multimodal Models/64e Видео, аудио и omni-модели|предыдущей главе об аудио]].
Числа здесь рассчитаны для окон без дополнения, а не для
конкретного кода подготовки входа Whisper.

Распознаватель может принимать уже рассчитанные признаки
или учить первый преобразователь на звуковой волне. У
[wav2vec 2.0](https://arxiv.org/abs/2006.11477v3) свёртки сначала
формируют признаки из волны. В предобучении модель восстанавливает
информацию для скрытых участков, отличая правильное квантованное
представление от отрицательных примеров. Затем на парах «аудио,
транскрипция» её дообучают с CTC. Предобучение и обучение
транскрипции используют разные цели.

Выходом могут быть буквы, фонемы или субтокены, в зависимости
от разметки и словаря. Чтобы проследить выравнивание, будем
считать выходными метками буквы. В примере возьмём часть
записи «алло», которой в тексте соответствуют две «л». Из
удвоенной буквы не следует, что в аудио есть два разделённых
звука. Участок выделен только для расчёта; при обучении
транскрипцию дают отрезку целиком.

<a id="asr-ctc"></a>

## Как CTC оставляет две одинаковые буквы

На каждом шаге энкодера CTC задаёт распределение по меткам и
служебному символу blank, который обозначим точкой. Blank
означает, что в этот момент в текст ничего не добавляется.
Он может появиться и на кадре, где речь хорошо слышна.

Путь содержит одну метку на каждый шаг энкодера. Чтобы получить
текст, сначала заменяем каждый непрерывный ряд одинаковых меток
одной, затем удаляем blank. Порядок операций меняет результат:
из «л л · л» получаются две «л», а из «л л л ·» — одна.
На схеме Awni Hannun показывает те же операции для *hello*:
две группы *l* отделены друг от друга знаком $\epsilon$.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/speech-recognition-2026-11-22/hannun-ctc-collapse.svg|Четыре строки исходного примера Distill: сырые метки, слияние соседних повторов, удаление epsilon и итоговое hello с двумя l.]]

*Awni Hannun, [Sequence Modeling With CTC](https://distill.pub/2017/ctc/#the-algorithm), [исходная схема свёртки меток](https://distill.pub/2017/ctc/assets/ctc_alignment_steps.svg), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).*

Соседним одинаковым буквам нужно больше шагов. Две «л» требуют
хотя бы трёх шагов: «л · л». Просто иметь столько же кадров,
сколько букв, недостаточно. Поэтому сокращение частоты
энкодера влияет не только на стоимость вычислений: при слишком
сильном сокращении для некоторых транскрипций не останется ни
одного допустимого пути.

<a id="asr-forward"></a>

## Как складываются вероятности путей

Для четырёх шагов зададим условные вероятности. В игрушечном
алфавите всего две метки: «л» и blank.

| Шаг | $p_t(\text{л})$ | $p_t(\text{blank})$ |
| ---: | ---: | ---: |
| 1 | 0,6 | 0,4 |
| 2 | 0,3 | 0,7 |
| 3 | 0,6 | 0,4 |
| 4 | 0,3 | 0,7 |

Если аудио $X$ фиксировано, в CTC вероятность пути
$\pi=(\pi_1,\ldots,\pi_T)$ равна произведению его вероятностей
по шагам. Это допущение относится к меткам при заданном аудио:
состояние энкодера может учитывать соседние или даже все кадры.
Цель обучения $Y$ задана транскрипцией. Для неё складывают пути,
которые сворачиваются в $Y$:

$$
P(Y\mid X)=\sum_{\pi:B(\pi)=Y}\prod_{t=1}^{T}p_t(\pi_t).
$$

Путь «л · л ·» даёт $0{,}6\cdot0{,}7\cdot0{,}6\cdot0{,}7=0{,}1764$.
Это не вся вероятность двух «л». Остальные пути получаются, если
сдвинуть одну букву или растянуть её, не убирая разделитель.

| Путь | Вероятность |
| --- | ---: |
| л · л · | 0,1764 |
| л · · л | 0,0504 |
| · л · л | 0,0144 |
| л л · л | 0,0216 |
| л · л л | 0,0756 |
| Сумма | 0,3384 |

Если эталон содержит две «л», функция потерь
$-\log P(Y\mid X)$ поощряет эту суммарную вероятность. Модели
не указывают, какой из пяти путей считать правильным.

### Сумма без перебора всех путей

У длинной фразы путей слишком много для прямого перебора.
CTC строит состояния из эталона, вставляя blank между метками,
до первой и после последней. Для двух «л» это «· л · л ·».
Две позиции «л» — разные состояния: одна относится к первой
букве, другая ко второй.

На схеме ниже эталон другой, *ab*. Столбцы — шаги $x_1,\ldots,x_6$,
строки — состояния «· a · b ·». Стрелки к одному узлу показывают,
какие предыдущие вероятности можно сложить. Переход прямо
из *a* в *b* допустим, потому что метки различаются. Из первой
«л» во вторую «л» таким переходом попасть нельзя.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/speech-recognition-2026-11-22/hannun-ctc-forward.svg|Граф состояний CTC для ab: шесть временных столбцов, пять строк blank, a, blank, b, blank и два отмеченных конечных состояния.]]

*Awni Hannun, [Sequence Modeling With CTC](https://distill.pub/2017/ctc/#the-algorithm), [схема прямого прохода](https://distill.pub/2017/ctc/assets/ctc_cost.svg), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).*

По одному шагу можно остаться в своём состоянии или перейти
из предыдущего. Переход через одно состояние разрешён, если
новая метка отлична от blank и от той, из которой сделан скачок.
Сумму входящих вероятностей умножают на вероятность текущей метки.
На втором шаге в разделяющий blank ведёт путь «л ·»
с массой $0{,}6\cdot0{,}7=0{,}42$. На третьем шаге он
переходит во вторую «л», и её масса равна $0{,}6\cdot0{,}42=0{,}252$.
На четвёртом шаге вторая «л» получает 0,162, а blank за ней —
0,1764. Это два возможных конца пути, и их сумма снова 0,3384.
Для цели из $U$ меток и $T$ кадров такой расчёт проходит по
таблице размера порядка $TU$.

### Почему лучший путь не всегда даёт самую вероятную строку

Жадное декодирование выбирает самую вероятную метку каждого
кадра, затем сворачивает путь. В таблице максимум по каждому
кадру даёт «л · л ·», то есть две «л». Но все пути для одной
«л» набирают 0,5832, против 0,3384 для двух. Одна «л» вероятнее
как строка, хотя ни один её путь не лучше самого сильного пути
для двух.

Поиск с лучом по префиксам CTC накапливает массу путей,
которые привели к одному тексту. Для префикса хранят отдельно
массу путей с blank на конце и без него: от этого зависит,
добавит ли следующая «л» новую букву или продлит прежнюю.
Можно также добавить оценку языковой модели.
В задаче принудительного выравнивания текст, напротив, уже
известен: среди путей для него ищут подходящие позиции во
времени, а не новый текст.

<a id="asr-transducer"></a>

## Как RNN-T учитывает уже выданный текст

У RNN-T состояние определяется не только шагом аудио $t$,
но и числом уже выданных токенов $u$. Акустический энкодер
вычисляет $h_t$. Сеть предсказания, *predictor*, кодирует
выходной префикс. Третья сеть, *joiner*, по обоим векторам
оценивает токены и blank. После каждой новой буквы
префикс меняется, поэтому меняются и оценки даже на том же кадре.

У пути два типа переходов. Blank переводит из $(t,u)$ в
$(t+1,u)$ и не меняет текст. Метка переводит в $(t,u+1)$
и не продвигает кадр. Повторные метки не сливают.
Например, на одном кадре модель может выпустить «л» с
вероятностью 0,6, затем ещё «л» при новом префиксе с вероятностью
0,7 и только потом blank с вероятностью 0,9. Вклад такого пути
равен $0{,}6\cdot0{,}7\cdot0{,}9=0{,}378$. При обучении RNN-T,
как и CTC, суммирует допустимые пути, но теперь это ходы по
двум координатам, а не шаги по одному ряду кадр за кадром.
В точку $(t,u)$ приходят либо по blank с предыдущего кадра,
либо по метке с предыдущего префикса на том же кадре.
Прямой проход складывает эти вклады. Даже когда все буквы
уже выданы, путь заканчивается только после blank,
который продвигает модель за последний кадр.

На верхней панели рисунка RNN-T продвигается по горизонтали
по кадрам: плоские участки не добавляют токенов. Внизу показан
тот же вход. Один шаг энкодера на верхних графиках соответствует
четырём кадрам спектрограммы. Средняя панель относится к
Token-and-Duration Transducer (TDT). Он отдельно предсказывает,
на сколько шагов продвинуть вход, и может пропускать кадры
вместо прохода по каждому из них. Например, участку спектрограммы
около кадра 400 соответствует область около $t=100$ на верхних
графиках. Над паузой у обычного RNN-T видна длинная
горизонтальная часть пути, а у TDT меньше отдельных шагов.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/speech-recognition-2026-11-22/xu-rnnt-tdt-fig1.png|Три панели Xu и соавторов: ступенчатое выравнивание RNN-T, более редкие переходы TDT и спектрограмма того же сигнала. На верхних панелях T — кадры энкодера, U — номер токена.]]

*Hainan Xu и соавторы, [Efficient Sequence Transduction by Jointly Predicting Tokens and Durations](https://proceedings.mlr.press/v202/xu23g.html), [рис. 1](https://proceedings.mlr.press/v202/xu23g/xu23g.pdf#page=2), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Полный график из PMLR.*

Название RNN-T не обязывает использовать рекуррентный
акустический энкодер. Для потока важно, сколько правого
контекста нужно для вычисления $h_t$. Если энкодер требует
всю запись, одни только переходы RNN-T не дадут вывода
в реальном времени.

<a id="asr-whisper"></a>

## Как Whisper задаёт задачу токенами

Для обучения исходного Whisper брали окна по 30 секунд.
Звук приводили к 16 кГц и вычисляли 80-канальную log-mel-спектрограмму
с шагом 10 мс. Две начальные свёртки подают признаки в
Transformer-энкодер; вторая уменьшает число шагов примерно
вдвое. Декодер читает выход энкодера перекрёстным вниманием
и предсказывает следующий токен с учётом уже выданного текста.
В отличие от CTC, обучающие метки здесь — выходная
последовательность для авторегрессионного декодирования.

На одной и той же записи токен задачи позволяет просить
разный вывод. Для «Алло, я слышу слабый шум» транскрипция
оставит русский текст, а режим перевода выдаст английский.
На схеме следом за токеном начала идут метка языка и указание
задачи. В режиме с временными отметками декодер ставит
перед и после текста отдельные токены времени с шагом 20 мс.
В режиме без них предсказывает только текст после префикса.
Для отрезка без речи при обучении предусмотрен специальный
токен no speech. Это метка для отрезка, а не CTC blank
на каждом кадре.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/speech-recognition-2026-11-22/radford-whisper-task-fig1.png|Нижняя панель Whisper: начало последовательности и язык ведут к транскрипции или переводу. Далее идут либо временные токены вокруг текста, либо текст без отметок времени. Отдельно указан случай без речи.]]

*Alec Radford и соавторы, [Robust Speech Recognition via Large-Scale Weak Supervision](https://proceedings.mlr.press/v202/radford23a.html), [нижняя панель рис. 1](https://proceedings.mlr.press/v202/radford23a/radford23a.pdf#page=3), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).*

Обучение исходного Whisper использовало записи с готовыми
транскрипциями и переводами из интернета. Название *weak
supervision* относится к качеству и происхождению этих меток;
это не предобучение только на звуке. А возможность выдавать
временные отметки не делает модель потоковой: отметка описывает
положение фразы внутри обработанного отрезка. Если обёртка
нарезает звук на окна и повторно распознаёт их, нужно отдельно
решить, когда выводить промежуточный текст и какие слова ещё
можно исправить.

<a id="asr-evaluation"></a>

## Ошибки транскрипции и время до текста

Для WER выравнивают эталон и распознанные слова с помощью
расстояния редактирования. $S$ — число замен, $D$ — удалений,
$I$ — вставок, $N$ — число слов в эталоне.

$$
\mathrm{WER}=\frac{S+D+I}{N}.
$$

Эталон — «алло я слышу слабый шум», ответ — «алло слышу
тихий шум снова». «Я» пропало, «слабый» заменено на «тихий»,
«снова» добавлено. Минимум составляет три правки на пять
слов, WER равен 60%. Если считать символы, «ало» вместо
«алло» — одна правка на четыре символа, CER равен 25%;
WER для одного такого слова равен 100%. Пунктуацию, регистр,
числа и разделение на слова нужно нормализовать по одинаковым
правилам у всех сравниваемых систем. Для корпуса складывают
правки и слова по записям; короткая запись не должна весить
как длинная только потому, что обе входят в выборку.

Два потоковых распознавателя с одинаковым WER могут вывести текст
с разной задержкой. Пусть для первой выдачи
нужно накопить 200 мс звука, ещё 80 мс правого контекста и
35 мс вычислять. При таком порядке первый частичный текст
появится через 315 мс от начала звука, без учёта сети и очереди.
Если каждый блок в 200 мс требует 35 мс расчёта, отношение
времени вычислений к длительности звука (RTF) равно 0,175.
Из RTF нельзя получить время появления первой строки.
Отдельно измеряют, когда система перестаёт править частичный
ответ и подтверждает окончательный текст после конца речи.

<details>
<summary>Проверить расчёты в Python</summary>

~~~python
from itertools import groupby, product
from math import isclose, prod

blank = "_"
p_l = [0.6, 0.3, 0.6, 0.3]
rows = [{"L": p, blank: 1 - p} for p in p_l]


def collapse(path):
    return "".join(symbol for symbol, _ in groupby(path) if symbol != blank)


mass = {}
for path in product((blank, "L"), repeat=len(rows)):
    y = collapse(path)
    prob = prod(row[symbol] for row, symbol in zip(rows, path))
    mass[y] = mass.get(y, 0.0) + prob
assert isclose(mass["LL"], 0.3384)
assert isclose(mass["L"], 0.5832)
assert collapse(max(row, key=row.get) for row in rows) == "LL"
assert max(mass, key=mass.get) == "L"


def ctc_forward(rows, target):
    z = [blank] + [s for char in target for s in (char, blank)]
    alpha = [1.0] + [0.0] * (len(z) - 1)
    for row in rows:
        nxt = []
        for s, symbol in enumerate(z):
            incoming = alpha[s] + (alpha[s - 1] if s >= 1 else 0)
            if s >= 2 and symbol != blank and symbol != z[s - 2]:
                incoming += alpha[s - 2]
            nxt.append(incoming * row[symbol])
        alpha = nxt
    return sum(alpha[-2:])


assert isclose(ctc_forward(rows, "LL"), mass["LL"])
assert isclose(0.6 * 0.7 * 0.9, 0.378)  # One RNN-T path


def edit_distance(ref, hyp):
    prev = list(range(len(hyp) + 1))
    for i, a in enumerate(ref, 1):
        nxt = [i]
        for j, b in enumerate(hyp, 1):
            nxt.append(min(prev[j] + 1, nxt[-1] + 1, prev[j - 1] + (a != b)))
        prev = nxt
    return prev[-1]


pairs = [
    ("алло я слышу слабый шум", "алло слышу тихий шум снова"),
    ("hello i hear faint noise", "hello hear quiet noise again"),
]
for ref, hyp in pairs:
    ref, hyp = ref.split(), hyp.split()
    assert edit_distance(ref, hyp) == 3 and len(ref) == 5
assert edit_distance("алло", "ало") == 1
assert 200 + 80 + 35 == 315 and isclose(35 / 200, 0.175)
~~~

# Как diffusion-модель превращает шум в изображение

По запросу «красная машина у моря» можно получить множество разных изображений. Текст задаёт содержание сцены, но оставляет неопределёнными ракурс, положение машины, освещение и детали фона. Генератор должен выбирать из распределения изображений, соответствующих описанию.

В диффузионной модели выбор начинается со случайного тензора. Нейросеть многократно получает его текущее состояние, уровень шума и условие, после чего численный алгоритм обновляет состояние. Последний тензор либо уже представляет изображение, либо декодируется из компактного латентного пространства в RGB. Обучение такой сети устроено иначе: настоящее изображение известно, и программа сама создаёт зашумлённый вход и целевой ответ.

## 1. Как создаётся учебный пример

### Прямой процесс и уровень шума

Обозначим чистое изображение через $x_0$. В [DDPM, §2](https://arxiv.org/abs/2006.11239v2) на каждом прямом шаге изображение немного ослабляется и к нему добавляется независимый гауссовский шум:

$$
x_t=\sqrt{\alpha_t}\,x_{t-1}+\sqrt{\beta_t}\,\xi_t,
\qquad \alpha_t=1-\beta_t.
$$

Здесь $\beta_t$ задаёт дисперсию добавляемого шума, а $\xi_t\sim\mathcal N(0,I)$. После двух шагов коэффициент при исходном изображении равен $\sqrt{\alpha_2\alpha_1}$. Два независимых шумовых слагаемых тоже можно объединить в гауссовский шум. Для произвольного шага получается:

$$
\begin{aligned}
\bar\alpha_t&=\prod_{s=1}^{t}\alpha_s,\\
x_t&=\sqrt{\bar\alpha_t}\,x_0
    +\sqrt{1-\bar\alpha_t}\,\epsilon,\\
\epsilon&\sim\mathcal N(0,I).
\end{aligned}
$$

По этой формуле можно сразу получить вход на любом уровне шума. В обучающем цикле не требуется сначала строить $x_1,x_2,\ldots,x_{t-1}$.

Пусть $\beta_1=\beta_2=0{,}1$. Тогда $\bar\alpha_2=0{,}81$, а коэффициент при $x_0$ равен $0{,}9$. Для координаты $x_0=1$ и реализации шума $\epsilon=-0{,}5$ получается примерно $0{,}6821$:

~~~python
from math import sqrt, isclose

alpha_bar = (1 - 0.1) ** 2
signal = sqrt(alpha_bar)
noise_scale = sqrt(1 - alpha_bar)
xt = signal * 1.0 + noise_scale * (-0.5)

assert isclose(alpha_bar, 0.81)
assert isclose(xt, 0.6820550528229663)
~~~

Эти два шага оставляют большую часть сигнала. Начинать генерацию такого процесса с чистого $\mathcal N(0,I)$ было бы необоснованно. Расписание шума выбирают так, чтобы конечное распределение было достаточно близко к используемому начальному распределению генератора. В экспериментах DDPM использованы тысяча шагов и другое расписание; числа выше нужны только для разбора формулы.

### Что предсказывает сеть

Во время обучения программа выбирает изображение $x_0$, уровень $t$ и шум $\epsilon$, вычисляет $x_t$ и передаёт сети $(x_t,t)$. В условной модели добавляются признаки текста $c$. Сеть выдаёт тензор той же формы, что и изображение, и сравнивается с выбранным шумом:

$$
\mathcal L_{\mathrm{simple}}
=\mathbb E_{x_0,t,\epsilon}
\left\|\epsilon-\epsilon_\theta(x_t,t,c)\right\|^2.
$$

Известен целевой ответ для конкретного обучающего примера, но это не означает, что сеть всегда может однозначно восстановить его по входу. Разные изображения и разные шумы могут давать одинаковый или почти одинаковый $x_t$. При квадратичной функции потерь оптимальное предсказание равно условному среднему:

$$
\epsilon_\theta^*(x_t,t,c)
=\mathbb E[\epsilon\mid x_t,t,c].
$$

Например, при равных коэффициентах сигнала и шума пары $(x_0,\epsilon)=(1,-1)$ и $(-1,1)$ дают $x_t=0$. Если они равновероятны и условие их не различает, лучшим общим ответом по MSE будет ноль. Ошибка на отдельных примерах при этом останется:

~~~python
import numpy as np

a = sigma = 1 / np.sqrt(2)
clean = np.array([1.0, -1.0])
noise = np.array([-1.0, 1.0])
noisy = a * clean + sigma * noise
assert np.allclose(noisy, 0)

def mse(prediction):
    return np.mean((noise - prediction) ** 2)

assert np.isclose(mse(0), 1.0)
assert np.isclose(mse(1), 2.0)
assert np.isclose(mse(-1), 2.0)
~~~

Поэтому denoiser не следует понимать как устройство, которое выделяет из тензора единственный спрятанный «истинный шум». Он оценивает статистику возможных исходных изображений и шумов с учётом текущего состояния.

Один шаг обучения условного генератора состоит из следующих действий:

1. Выбрать пары «изображение — подпись» и получить текстовые признаки.
2. Для каждого изображения независимо выбрать $t$ и $\epsilon$.
3. Построить $x_t$ непосредственно по формуле смешивания.
4. Вычислить $\epsilon_\theta(x_t,t,c)$ и среднюю квадратичную ошибку.
5. Выполнить backpropagation и шаг оптимизатора.

[![Алгоритмы DDPM](https://hojonathanho.github.io/diffusion/assets/img/algorithms.png)](https://hojonathanho.github.io/diffusion/assets/img/algorithms.png)

*Jonathan Ho, Ajay Jain, Pieter Abbeel, [Denoising Diffusion Probabilistic Models, Algorithms 1–2](https://hojonathanho.github.io/diffusion/). В оригинале показана безусловная модель: текста среди входов нет. Обучение использует один случайный уровень; генерация проходит обратные шаги последовательно.*

Равномерный случайный $t$ даёт несмещённую оценку среднего по уровням именно для записанной функции потерь. В [DDPM, §3.2–3.4](https://arxiv.org/abs/2006.11239v2) исходная вариационная граница содержит дополнительные веса ошибок. Авторы убирают эти веса в $\mathcal L_{\mathrm{simple}}$. Нельзя одновременно назвать такую функцию точной исходной границей и считать выбор весов несущественным.

Эти веса возникают при сравнении двух гауссовских переходов: известного при обучении $q(x_{t-1}\mid x_t,x_0)$ и предсказанного $p_\theta(x_{t-1}\mid x_t)$. При фиксированной дисперсии предсказанного перехода KL-дивергенция сводится к квадратичной ошибке их средних с коэффициентом. После выражения среднего через шум коэффициент при MSE для внутренних шагов равен

$$
\lambda_t=
\frac{\beta_t^2}
{2\sigma_t^2\alpha_t(1-\bar\alpha_t)}.
$$

В полной границе есть также начальный prior и конечный decoder. Упрощённая функция с одинаковыми весами ошибок по уровням остаётся осмысленным способом обучения, но иначе распределяет внимание модели между уровнями шума.

Если ошибки двух уровней равны $1$ и $4$, равномерное среднее равно $2{,}5$. При вероятностях выбора $0{,}8$ и $0{,}2$ без поправки получается $1{,}6$. Чтобы оценивать прежнее равномерное среднее, нужны веса, обратные вероятности выбора:

~~~python
import numpy as np

losses = np.array([1.0, 4.0])
probabilities = np.array([0.8, 0.2])
uniform_objective = losses.mean()
changed_objective = probabilities @ losses
importance_corrected = probabilities @ (losses / (2 * probabilities))

assert np.isclose(uniform_objective, 2.5)
assert np.isclose(changed_objective, 1.6)
assert np.isclose(importance_corrected, uniform_objective)

from math import erf, log, sqrt
central_logit_normal_probability = erf(log(3) / sqrt(2))
assert central_logit_normal_probability > 0.72
~~~

## 2. Почему локальное предсказание позволяет генерировать целую картинку

### От оценки шума к распределению следующего состояния

При генерации исходного изображения нет. Начальное состояние $x_T$ выбирают из гауссовского распределения, а обученная модель задаёт последовательность обратных переходов. В DDPM переход имеет вид

$$
p_\theta(x_{t-1}\mid x_t)
=\mathcal N\bigl(\mu_\theta(x_t,t),\sigma_t^2I\bigr).
$$

Среднее выражается через предсказание шума:

$$
\begin{gathered}
\mu_\theta(x_t,t)=\\
\frac{1}{\sqrt{\alpha_t}}
\left(
x_t-\frac{\beta_t}{\sqrt{1-\bar\alpha_t}}
\epsilon_\theta(x_t,t)
\right).
\end{gathered}
$$

Затем выбирается $x_{t-1}=\mu_\theta+\sigma_t\xi$. В последнем шаге алгоритма DDPM дополнительный случайный шум не добавляется. После перехода сеть вызывается заново, уже на новом состоянии и с новым уровнем шума. Одна и та же оценка $\epsilon_\theta$ не используется для всех последующих шагов.

При учебных $\alpha_t=0{,}9$, $\bar\alpha_t=0{,}81$, $x_t=0{,}8$ и предсказании $0{,}2$ среднее следующего состояния примерно равно $0{,}79491$. Если взять вариант $\sigma_t^2=\beta_t=0{,}1$, дополнительный шум с реализациями $-1,0,1$ даст три разных результата:

~~~python
import numpy as np

alpha, alpha_bar, beta = 0.9, 0.81, 0.1
x, predicted_noise = 0.8, 0.2
mean = (x - beta / np.sqrt(1 - alpha_bar) * predicted_noise) / np.sqrt(alpha)
outcomes = mean + np.sqrt(beta) * np.array([-1.0, 0.0, 1.0])

assert np.allclose(outcomes - mean, [-np.sqrt(.1), 0, np.sqrt(.1)])
assert np.isclose(outcomes[1], mean)
assert np.isclose(mean, 0.7949089593709004)
~~~

Чистое изображение на каждом промежуточном шаге по-прежнему неизвестно. Обучение обратных переходов приближает обращение процесса зашумления всего распределения данных. Оно не требует, чтобы случайный начальный шум соответствовал одной заранее назначенной фотографии.

### Связь с score function

Направление изменения состояния можно описать через градиент логарифма плотности:

$$
s_t(x)=\nabla_x\log p_t(x).
$$

Он указывает, в какую сторону плотность увеличивается быстрее всего. Для нормального распределения со средним $m$ и дисперсией $\sigma^2$ score равен $-(x-m)/\sigma^2$. Например, при $m=2$, $\sigma=0{,}5$ и $x=1{,}5$ он равен $2$: направление ведёт вправо, к центру распределения.

В [Stanford EE367, Lecture 12, слайды 62–68](https://web.stanford.edu/class/ee367/slides/lecture12.pdf) связь с denoising выводится через формулу Твиди для аддитивного шума. Для используемого здесь $x_t=a_tx_0+\sigma_t\epsilon$ она принимает вид

$$
\begin{aligned}
\mathbb E[x_0\mid x_t]
&=\frac{x_t+\sigma_t^2s_t(x_t)}{a_t},\\
s_t(x_t)
&=-\frac{\mathbb E[\epsilon\mid x_t]}{\sigma_t}.
\end{aligned}
$$

Это объясняет, почему оценка шума содержит информацию о направлении изменения распределения. В формуле нужен средний шум при данном входе, а не известный только обучающей программе шум одного примера.

~~~python
from math import isclose

a, sigma, x = 0.8, 0.6, 0.8
predicted_noise = 0.2
score = -predicted_noise / sigma
estimated_clean = (x + sigma**2 * score) / a

assert isclose(score, -1 / 3)
assert isclose(estimated_clean, 0.85)
assert isclose(-(1.5 - 2) / 0.5**2, 2.0)
~~~

Движение только к ближайшему максимуму плотности само по себе не обеспечивает правильных частот разных изображений. Для генерации нужен согласованный процесс: обратные переходы DDPM, подходящее дифференциальное уравнение или другой sampler с соответствующим обучением. Score не является самостоятельным правилом «повторять градиентный подъём до красивой картинки».

### Один численный обратный шаг

В детерминированном [DDIM, §4.1–4.2](https://arxiv.org/abs/2010.02502v4) сначала оценивается чистое состояние, затем строится состояние на выбранном менее шумном уровне $s<t$:

$$
\begin{aligned}
\hat x_0&=
\frac{x_t-\sqrt{1-\bar\alpha_t}\,\epsilon_\theta}
{\sqrt{\bar\alpha_t}},\\
x_s&=\sqrt{\bar\alpha_s}\,\hat x_0
+\sqrt{1-\bar\alpha_s}\,\epsilon_\theta.
\end{aligned}
$$

Пусть $x_t=0{,}8$, $\bar\alpha_t=0{,}64$, $\bar\alpha_s=0{,}81$, а сеть выдала $0{,}2$. Тогда оценка чистого состояния равна $0{,}85$, а новое состояние примерно равно $0{,}85218$:

~~~python
from math import sqrt, isclose

x, noise_hat = 0.8, 0.2
alpha_t, alpha_s = 0.64, 0.81
clean_hat = (x - sqrt(1 - alpha_t) * noise_hat) / sqrt(alpha_t)
next_x = sqrt(alpha_s) * clean_hat + sqrt(1 - alpha_s) * noise_hat

assert isclose(clean_hat, 0.85)
assert isclose(next_x, 0.8521779788708135)
~~~

DDIM позволяет выбирать подмножество уровней обученного процесса, а не обязательно проходить все тысячу. Уменьшение числа вызовов обычно увеличивает ошибку приближения; допустимое число шагов зависит от модели и sampler. Детерминированность означает отсутствие дополнительного шума при фиксированном начальном состоянии, а не отсутствие разнообразия между разными начальными состояниями.

## 3. Latent diffusion: denoising не в RGB

Изображение $512\times512$ содержит $786\,432$ RGB-координаты. Если автоэнкодер уменьшает каждую пространственную ось в восемь раз и использует четыре латентных канала, представление имеет форму $[4,64,64]$ и содержит $16\,384$ координаты. Разница равна $48$ разам по числу элементов:

~~~python
pixels = 3 * 512 * 512
latent = 4 * (512 // 8) * (512 // 8)
assert (pixels, latent, pixels / latent) == (786432, 16384, 48.0)
~~~

Это не обещание ускорения в $48$ раз: число каналов внутри сети, attention, автоэнкодер и устройства также влияют на стоимость.

В [Latent Diffusion Models, §3.1–3.3](https://arxiv.org/abs/2112.10752v2) обучение разделено на две стадии. Сначала автоэнкодер учится получать латентное представление $z=E(x)$ и реконструировать $D(z)$. Помимо пиксельной ошибки используются перцептивные и adversarial-компоненты; в статье исследуются KL- и VQ-регуляризация.

Затем автоэнкодер фиксируется, а denoiser обучается на зашумлённых латентных представлениях. Его функция потерь относится к шуму в латентном пространстве. При генерации encoder изображения не нужен: латентное состояние получается из шума, а decoder один раз преобразует окончательный результат в RGB.

[![Архитектура Latent Diffusion Models](https://ommer-lab.com/wp-content/uploads/2022/08/article-Figure3-1-1024x508.png)](https://ommer-lab.com/wp-content/uploads/2022/08/article-Figure3-1-1024x508.png)

*Robin Rombach et al., [High-Resolution Image Synthesis with Latent Diffusion Models, Figure 3](https://ommer-lab.com/research/latent-diffusion-models/). Области Pixel Space и Latent Space разделяют автоэнкодер и генератор; Conditioning показывает способы передать внешнее условие.*

Форму тензора, его масштаб и возможный сдвиг необходимо брать из конфигурации конкретного автоэнкодера и pipeline. Расписание, рассчитанное на один масштаб латентных переменных, нельзя без проверки переносить на другой. Название «VAE» тоже не означает, что агрегированное распределение всех закодированных изображений в точности равно стандартному гауссовскому.

Сжатие ограничивает достоверность реконструкции. Пусть encoder сохраняет среднее двух пикселей. Пары $(0,1)$ и $(1,0)$ обе превращаются в $0{,}5$. Decoder может выбрать одну из них или усреднить, но по одному числу не узнает, какая пара была исходной:

~~~python
import numpy as np

images = np.array([[0.0, 1.0], [1.0, 0.0]])
codes = images.mean(axis=1)
assert np.allclose(codes, [0.5, 0.5])
mean_reconstruction = np.array([0.5, 0.5])
assert np.allclose(((images - mean_reconstruction)**2).mean(axis=1), 0.25)
~~~

Генератор способен достроить правдоподобную деталь на основе выученного распределения или текста. Это не делает деталь достоверно восстановленной из утраченной информации. При выборе сжатия сравнивают и качество реконструкции автоэнкодера, и качество генерации, и стоимость всей системы.

## 4. Как текст влияет на пространственные признаки

### Cross-attention к тексту

Текстовый encoder превращает подпись в последовательность векторов. Промежуточные пространственные признаки denoiser образуют queries, а текстовые векторы образуют keys и values. На каждой пространственной позиции вычисляется взвешенная сумма текстовых values:

$$
\begin{aligned}
Q&=HW_Q,\\
K&=CW_K,\qquad V=CW_V,\\
A&=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}\right),\\
H_{\mathrm{text}}&=AV.
\end{aligned}
$$

Здесь $H$ содержит пространственные признаки, $C$ содержит текстовые токены, а $d_h$ — размерность одной головы. Для $N$ пространственных позиций и $M$ текстовых токенов матрица $A$ имеет форму $[N,M]$.

В учебном примере два текстовых токена обозначают машину и море. Первая пространственная позиция имеет больший logit для машины, вторая — для моря. Получаются разные смеси текстовых признаков:

~~~python
import numpy as np

logits = np.array([[2.0, 0.0], [0.0, 2.0]])
weights = np.exp(logits - logits.max(axis=1, keepdims=True))
weights /= weights.sum(axis=1, keepdims=True)
values = np.array([[1.0, 0.0], [0.0, 1.0]])
mixed = weights @ values

assert np.allclose(weights.sum(axis=1), 1)
assert np.allclose(mixed[:, 0], [0.8807970779778823, 0.11920292202211755])
~~~

Реальные текстовые векторы не являются такими двухмерными метками. Attention также не гарантирует сегментацию предметов: значение отдельной карты зависит от слоя, головы и текущего уровня шума. В LDM условие может передаваться и конкатенацией, например вместе с пространственной картой; cross-attention нужен для более общего последовательностного условия.

### Classifier-free guidance

Сеть можно обучить работать как с текстом, так и без него. Для части обучающих примеров подпись заменяют специальным пустым условием $\varnothing$, оставляя изображение и целевой шум прежними. Это удаление условия отличается от обычного dropout внутри сети.

При генерации на одном и том же $(x_t,t)$ вычисляются два предсказания. [Classifier-free guidance](https://arxiv.org/abs/2207.12598) использует их разность:

$$
\hat\epsilon
=\epsilon_{\varnothing}
+s(\epsilon_c-\epsilon_{\varnothing}).
$$

При $s=0$ остаётся безусловное предсказание; при $s=1$ — обычное условное. При $s>1$ разность усиливается. Например, если предсказания равны $(0{,}2,-0{,}1)$ и $(0{,}5,0{,}1)$, то при $s=3$ получается $(1{,}1,0{,}5)$:

~~~python
import numpy as np

unconditional = np.array([0.2, -0.1])
conditional = np.array([0.5, 0.1])
def cfg(scale):
    return unconditional + scale * (conditional - unconditional)

assert np.allclose(cfg(0), unconditional)
assert np.allclose(cfg(1), conditional)
assert np.allclose(cfg(3), [1.1, 0.5])
~~~

Это экстраполяция предсказаний. Большой коэффициент не гарантирует лучшего изображения: возможны потеря разнообразия, пересыщение и другие искажения. При $s>1$ результирующий процесс уже не обязан воспроизводить исходное условное распределение данных. Вывод и ограничения подробно разобраны в [MIT 6.S184, §5.2](https://arxiv.org/abs/2506.02070v3).

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/diffusion-flow-2026-10/mit-cfg-mnist.png]]

*Peter Holderrieth, Ezra Erives, [An Introduction to Flow Matching and Diffusion Models, Figure 13](https://arxiv.org/abs/2506.02070v3), MIT 6.S184. Оригинальный рисунок и английская подпись приведены без изменений. [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/).*

Два предсказания можно вычислять одним вызовом сети на удвоенном batch, но арифметическая работа двух ветвей от этого не исчезает. Поэтому число шагов sampler и число обработанных сетью состояний нужно указывать раздельно. Методы с дистиллированным guidance могут обходиться без такой пары вызовов, но требуют соответствующего обучения.

## 5. U-Net, DiT и целевая величина

### U-Net и пространственные масштабы

Denoiser должен выдавать пространственный тензор, а не одну метку класса. В U-Net нисходящая ветвь уменьшает разрешение признаков и увеличивает число каналов. Восходящая ветвь возвращает разрешение. Связи между соответствующими масштабами передают более подробные пространственные признаки, которые иначе пришлось бы восстанавливать только из нижнего уровня.

Для входа $[4,64,64]$ условная последовательность форм может выглядеть как $[32,64,64]\to[64,32,32]\to[128,16,16]$ и обратно. Если при возврате к $32\times32$ объединяются два тензора по $64$ канала, следующий блок получает $128$ каналов:

~~~python
up = (64, 32, 32)
skip = (64, 32, 32)
assert up[1:] == skip[1:]
concatenated = (up[0] + skip[0], *up[1:])
assert concatenated == (128, 32, 32)
~~~

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/diffusion-flow-2026-10/mit-unet.png]]

*Peter Holderrieth, Ezra Erives, [An Introduction to Flow Matching and Diffusion Models, Figure 15](https://arxiv.org/abs/2506.02070v3). Учебная U-Net из курса MIT; схема и английская подпись сохранены без изменений. [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/).*

В этой схеме связи между масштабами показаны сложением, а в примере форм выше использована конкатенация. Это разные допустимые реализации, а не взаимозаменяемые операции. BatchNorm и блок Midcoder на рисунке относятся к конкретной учебной схеме; Midcoder — авторское название нижнего блока, не общепринятый отдельный тип слоя. В diffusion U-Net могут использоваться другие нормировки, residual-блоки и attention.

Слова encoder и decoder внутри U-Net также не обозначают VAE из предыдущего раздела. U-Net целиком выполняется на каждом шаге denoising; внешний автоэнкодер переводит между RGB и латентным пространством.

### Patchify и DiT

[DiT, §3.1–3.2](https://arxiv.org/abs/2212.09748v2) заменяет U-Net на Transformer над латентными patches. Для тензора $[4,32,32]$ и patch $2\times2$ получается $256$ токенов. До линейной проекции каждый содержит $4\cdot2\cdot2=16$ чисел. При patch $4\times4$ токенов всего $64$:

~~~python
def patch_spec(channels, height, width, patch):
    assert height % patch == width % patch == 0
    return (height // patch) * (width // patch), channels * patch**2

assert patch_spec(4, 32, 32, 2) == (256, 16)
assert patch_spec(4, 32, 32, 4) == (64, 64)
assert (256**2) / (64**2) == 16
~~~

Уменьшение patch вдвое увеличивает число токенов в четыре раза, а число пар в полном attention — в шестнадцать. Стоимость всей модели не обязана вырасти ровно в шестнадцать раз: проекции и MLP зависят от длины последовательности линейно.

После линейного embedding добавляются пространственные позиции. Transformer обновляет все токены текущего зашумлённого состояния, а выходная проекция и unpatchify возвращают тензор исходной пространственной формы. Это параллельное предсказание для всего состояния; causal mask языкового декодера ему не требуется.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/diffusion-flow-2026-10/dit-architecture.png]]

*William Peebles, Saining Xie, [Scalable Diffusion Models with Transformers, Figure 3](https://arxiv.org/abs/2212.09748v2). Показаны полный DiT и варианты подачи условия: adaLN-Zero, cross-attention, дополнительные токены. Из страницы выделена исходная схема. [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).*

В исходной работе DiT условие — класс изображения, а не длинная подпись. На рисунке embedding класса складывается с embedding времени. В adaLN это условие порождает поканальные сдвиги и масштабы нормированных признаков; в adaLN-Zero дополнительно управляет вкладом residual-ветвей. Нулевые начальные множители residual-ветвей делают блок в начале обучения тождественным:

~~~python
import numpy as np

hidden = np.array([[1.0, 3.0], [2.0, 4.0]])
normalized = (hidden - hidden.mean(axis=-1, keepdims=True))
normalized /= np.sqrt(hidden.var(axis=-1, keepdims=True) + 1e-6)
shift = np.array([0.2, -0.1])
scale = np.array([0.5, 0.0])
modulated = normalized * (1 + scale) + shift
branch = 2 * modulated
gate = np.zeros(2)

assert np.allclose(hidden + gate * branch, hidden)
assert not np.allclose(modulated, normalized)
~~~

Конкретное обозначение масштаба зависит от записи: $1+\gamma$ при нулевом $\gamma$ и непосредственно $\gamma$ при единичном $\gamma$ могут описывать одну операцию. Название adaLN-Zero не означает, что нормированные признаки всегда равны нулю.

В исходном DiT выход содержит оценки шума и диагональной ковариации обратного перехода. Поэтому при $C$ латентных каналах выходная patch-проекция имеет $2C$ каналов. У генератора с другой целевой величиной и фиксированной дисперсией выход может содержать только $C$ каналов. Нельзя переносить размер выходной головы между ними по одному слову DiT.

### Noise prediction, clean prediction и v-prediction

Backbone определяет устройство вычисляющей сети; целевая величина определяет, что означают её выходные числа. Для $x_t=a_tx_0+\sigma_t\epsilon$ при $a_t^2+\sigma_t^2=1$ часто используются три параметризации: шум $\epsilon$, чистое состояние $x_0$ и

$$
\begin{aligned}
v_t&=a_t\epsilon-\sigma_tx_0,\\
x_0&=a_tx_t-\sigma_tv_t,\\
\epsilon&=\sigma_tx_t+a_tv_t.
\end{aligned}
$$

При $a_t=0{,}8$, $\sigma_t=0{,}6$, $x_0=0{,}85$ и $\epsilon=0{,}2$ зашумлённое состояние равно $0{,}8$, а $v_t=-0{,}35$. Обратные формулы возвращают исходные значения:

~~~python
from math import isclose

a, sigma, clean, noise = 0.8, 0.6, 0.85, 0.2
noisy = a * clean + sigma * noise
v = a * noise - sigma * clean
assert isclose(noisy, 0.8) and isclose(v, -0.35)
assert isclose(a * noisy - sigma * v, clean)
assert isclose(sigma * noisy + a * v, noise)
~~~

Алгебраическая переводимость не делает MSE по разным целям одинаковой функцией потерь: коэффициенты зависят от уровня шума, а значит меняется вес ошибок. Сопоставление параметризаций и весов приведено в [Esser et al., §3](https://proceedings.mlr.press/v235/esser24a.html). Символ $v$ в этой записи также не следует автоматически отождествлять со скоростью прямолинейного пути следующего раздела.

## 6. Flow matching: путь распределений и поле скоростей

### Обучающий путь

Для flow matching удобно направить время от шума к данным. Чтобы не смешивать его с индексом DDPM, обозначим это время через $\tau\in[0,1]$. Пусть $\epsilon$ — начальный шум, $z$ — пример данных или его латентное представление. Выберем прямолинейный путь

$$
y_\tau=(1-\tau)\epsilon+\tau z.
$$

При $\tau=0$ получаем шум, при $\tau=1$ — данные. Скорость выбранной прямой равна $z-\epsilon$. Для $\epsilon=(-1,1)$ и $z=(3,5)$ точка при $\tau=0{,}25$ равна $(0,2)$, а скорость равна $(4,4)$:

~~~python
import numpy as np

noise = np.array([-1.0, 1.0])
data = np.array([3.0, 5.0])
tau = 0.25
point = (1 - tau) * noise + tau * data
target_velocity = data - noise
assert np.allclose(point, [0.0, 2.0])
assert np.allclose(target_velocity, [4.0, 4.0])
assert np.allclose(point + 0.25 * target_velocity, [1.0, 3.0])
~~~

Программа может создать такую точку и скорость без решения дифференциального уравнения. Сеть получает только текущую точку, время и доступное условие, после чего обучается по

$$
\mathcal L_{\mathrm{CFM}}
=\mathbb E\left\|
u_\theta(y_\tau,\tau,c)-(z-\epsilon)
\right\|^2.
$$

Это условное flow matching: целевая скорость известна для выбранной обучающей пары. Условие $c$, например текст, следует отличать от конечного обучающего примера $z$. При генерации текст известен, а выбранная целевая картинка неизвестна.

### Почему прямые обучающие пути дают общее поле

Если зафиксировать одну картинку $z$, распределение $y_\tau$ постепенно сжимается к ней. Если каждый раз выбирать новое $z$ из набора данных, получается путь от шума ко всему распределению изображений. Эти два случая в [MIT 6.S184, §3.1](https://arxiv.org/abs/2506.02070v3) называются conditional и marginal probability path:

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/diffusion-flow-2026-10/mit-conditional-marginal.png]]

*Peter Holderrieth, Ezra Erives, [An Introduction to Flow Matching and Diffusion Models, Figure 5](https://arxiv.org/abs/2506.02070v3). Полный исходный рисунок с английской подписью, без изменений. [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/).*

В одной области пространства могут проходить обучающие пути с разными конечными изображениями и скоростями. Сеть не получает идентификатор такой пары. Как и при предсказании шума, MSE обучает её среднему ответу при данном входе:

$$
u^*(y,\tau,c)
=\mathbb E[z-\epsilon\mid y_\tau=y,c].
$$

Среднее здесь берётся по совместимым с текущим состоянием парам, а не по всем изображениям с одинаковыми весами. Из равенства $y=(1-\tau)\epsilon+\tau z$ следует

$$
u^*(y,\tau,c)
=\frac{\mathbb E[z\mid y,\tau,c]-y}{1-\tau},
\qquad \tau<1.
$$

Пример для двух возможных конечных точек $z=-2$ и $z=2$ с равными вероятностями и гауссовским шумом позволяет вычислить это среднее явно. При $\tau=0{,}5$ и $y=0{,}25$ положительная конечная точка вероятнее. Получаются среднее примерно $1{,}5232$ и скорость примерно $2{,}5464$:

~~~python
import numpy as np

tau, y = 0.5, 0.25
endpoints = np.array([-2.0, 2.0])
sigma = 1 - tau
log_weights = -0.5 * ((y - tau * endpoints) / sigma)**2
weights = np.exp(log_weights - log_weights.max())
weights /= weights.sum()
mean_endpoint = weights @ endpoints
velocity = (mean_endpoint - y) / (1 - tau)

assert np.isclose(mean_endpoint, 1.5231883119115297)
assert np.isclose(velocity, 2.5463766238230594)
assert weights[1] > weights[0]
~~~

По мере движения меняется текущее состояние, а вместе с ним — веса возможных конечных изображений и направление среднего поля. Поэтому траектория общего поля может изгибаться, хотя путь каждой отдельной обучающей пары был прямым:

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/diffusion-flow-2026-10/mit-conditional-marginal-trajectories.png]]

*Peter Holderrieth, Ezra Erives, [An Introduction to Flow Matching and Diffusion Models, Figure 6](https://arxiv.org/abs/2506.02070v3). Исходные панели и английская подпись сохранены без изменений. [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/).*

Изменение плотности при движении частиц описывает уравнение непрерывности:

$$
\partial_\tau p_\tau(y)
=-\nabla_y\cdot\bigl(p_\tau(y)u_\tau(y)\bigr).
$$

Левая часть показывает, как меняется плотность в точке. Правая учитывает приток и отток вероятностной массы вдоль поля. В [§3.2–3.3 курса](https://arxiv.org/abs/2506.02070v3) условные распределения смешиваются по конечным примерам. Благодаря линейности уравнения полученная смесь удовлетворяет ему с усреднённым полем. При необходимых условиях регулярности и корректном решении ОДЕ это даёт нужный путь распределений. Конечная нейросеть и численный solver вносят ошибки приближения; результат не является гарантией для произвольной обученной сети.

Обучение по скоростям отдельных пар имеет тот же градиент, что и обучение по их условному среднему. Для квадратичной ошибки это следует из разложения

$$
\begin{gathered}
\mathbb E\|U-f(X)\|^2=\\
\mathbb E\|U-\mathbb E[U\mid X]\|^2\\
+\mathbb E\|\mathbb E[U\mid X]-f(X)\|^2.
\end{gathered}
$$

Первая часть не зависит от параметров $f$. Если при одном входе встречаются скорости $1$ и $3$, среднее равно $2$. Потери для предсказания $p$ равны $1+(p-2)^2$: неизбежная дисперсия не меняет оптимальное предсказание и градиент.

~~~python
import numpy as np

targets = np.array([1.0, 3.0])
for prediction in [-2.0, 0.0, 2.0, 5.0]:
    direct = np.mean((targets - prediction)**2)
    decomposition = np.var(targets) + (targets.mean() - prediction)**2
    assert np.isclose(direct, decomposition)
~~~

Такое обучение не требует просчитывать всю траекторию генератора для каждого примера. Результат после обучения, однако, проверяют именно генерацией: низкая ошибка на отдельных обучающих точках сама по себе не доказывает хорошее конечное распределение.

### Численное интегрирование и число вызовов

При генерации решают

$$
\frac{dy}{d\tau}=u_\theta(y,\tau,c),
\qquad y(0)\sim\mathcal N(0,I).
$$

Метод Эйлера берёт текущее направление и делает шаг $h$: $y_{\tau+h}=y_\tau+h\,u_\theta(y_\tau,\tau,c)$. Метод Хойна сначала вычисляет пробный шаг Эйлера, затем усредняет направления в начале и в пробной конечной точке. На интервал он обычно требует два вычисления поля.

Для уравнения $dy/d\tau=y$, $y(0)=1$, точный результат в $\tau=1$ равен $e$. Два шага Эйлера дают $2{,}25$, два шага Хойна — $2{,}640625$. Это пример ошибки solver на известном поле, а не измерение качества генерации изображений:

~~~python
from math import e, isclose

def integrate(method, steps):
    x, calls = 1.0, 0
    h = 1 / steps
    for _ in range(steps):
        first = x
        calls += 1
        if method == "euler":
            x += h * first
        else:
            second = x + h * first
            calls += 1
            x += h * (first + second) / 2
    return x, calls

euler, euler_calls = integrate("euler", 2)
heun, heun_calls = integrate("heun", 2)
assert isclose(euler, 2.25) and euler_calls == 2
assert isclose(heun, 2.640625) and heun_calls == 4
assert abs(heun - e) < abs(euler - e)
~~~

Прямолинейное построение обучающих пар не гарантирует генерацию одним шагом. Для этого общее поле должно быть достаточно просто вдоль фактических траекторий либо модель должна быть специально обучена или дистиллирована для больших шагов.

Flow matching допускает и другие пути, не только $(1-\tau)\epsilon+\tau z$. При гауссовском пути $y_\tau=a_\tau z+b_\tau\epsilon$ целевая скорость равна $\dot a_\tau z+\dot b_\tau\epsilon$. Поэтому общее определение flow matching шире регрессии постоянного $z-\epsilon$. Подробный вывод приведён в [Lipman et al., Flow Matching Guide and Code, §4](https://arxiv.org/abs/2412.06264).

### Stable Diffusion 3: путь, обучение и MM-DiT

[Stable Diffusion 3, §3–4](https://proceedings.mlr.press/v235/esser24a.html) сочетает латентное представление, прямолинейный путь rectified flow и мультимодальный Transformer. В статье время направлено от данных к шуму: $z_t=(1-t)x_0+t\epsilon$, а целевая скорость равна $\epsilon-x_0$. При замене $\tau=1-t$ получается использованное выше направление и противоположный знак скорости.

Авторы также исследуют неравномерный выбор обучающего времени. При logit-normal sampling сначала выбирается нормальная величина $g$, затем $t=\operatorname{sigmoid}(g)$. Например, при $g\sim\mathcal N(0,1)$ вероятность попасть в центральный интервал $0{,}25<t<0{,}75$ равна примерно $0{,}73$, тогда как при равномерном выборе она равна $0{,}5$. Это следует из равенства $|g|<\log 3$; расчёт есть в примере первого раздела. Другие среднее и дисперсия дают другое распределение времени. Изменение вероятностей выбора без компенсирующих весов меняет акценты функции потерь. Прямой путь не обязывает использовать равномерный выбор времени.

Слева на схеме текст передаётся двумя способами. В [Appendix B.2](https://proceedings.mlr.press/v235/esser24a.html) pooled-векторы CLIP-L и OpenCLIP bigG размерностей $768$ и $1280$ объединены в вектор из $2048$ чисел для модуляции блоков вместе со временем. Их последовательности скрытых состояний объединены по каналам в $77\times2048$, дополнены нулями до $77\times4096$ и соединены по оси последовательности с $77$ состояниями T5-XXL. В результате контекст содержит $154$ токена. Pooled-вектор передаёт общее условие, а последовательность сохраняет отдельные текстовые позиции.

Для изображений в статье используется пространственное сжатие в восемь раз; авторы сравнивают разные числа латентных каналов и для масштабирования выбирают $16$. Поэтому пример с четырьмя каналами из раздела о LDM не является конфигурацией SD3.

В MM-DiT текстовые и пространственные токены имеют отдельные параметры проекций, нормировок и MLP. Для attention их queries, keys и values объединяются по оси последовательности, поэтому оба вида токенов могут взаимодействовать. После attention результаты снова обрабатываются соответствующими ветвями.

Для четырёх image tokens и трёх text tokens получаются семь queries и семь keys. Полная матрица attention имеет $49$ элементов: $16$ image–image, $9$ text–text и по $12$ в двух перекрёстных направлениях:

~~~python
image_tokens, text_tokens = 4, 3
joint = image_tokens + text_tokens
parts = [image_tokens**2, text_tokens**2,
         image_tokens * text_tokens, text_tokens * image_tokens]
assert joint**2 == sum(parts) == 49
assert parts == [16, 9, 12, 12]
~~~

Это отличается от отдельного cross-attention, где обновлялись только image queries по текстовым keys и values. В MM-DiT меняются и внутренние текстовые состояния. При этом выход генератора по-прежнему является пространственным тензором скорости, а не следующим текстовым токеном. Термин multimodal здесь не означает автоматически, что модель умеет отвечать на вопросы об изображениях.

## 7. Полный цикл генерации

Полный text-to-image pipeline сначала получает текстовые признаки, затем создаёт начальный шум нужной латентной формы. На каждом шаге он вычисляет предсказание denoiser, при необходимости применяет CFG и передаёт результат solver. После последнего шага латентное представление приводится к масштабу decoder и преобразуется в RGB.

Для условных $20$ шагов Эйлера нужны $20$ вычислений поля. При двухветочном CFG обрабатываются $40$ состояний; два прохода можно объединить по batch. Если вместо Эйлера взять два вычисления поля на каждый из $20$ интервалов, получится $40$ вычислений поля и $80$ обработанных состояний при таком же CFG:

~~~python
def work(intervals, evaluations_per_interval, cfg_branches):
    field_evaluations = intervals * evaluations_per_interval
    processed_states = field_evaluations * cfg_branches
    return field_evaluations, processed_states

assert work(20, 1, 1) == (20, 20)
assert work(20, 1, 2) == (20, 40)
assert work(20, 2, 2) == (40, 80)
~~~

Это подсчёт алгоритмической работы, не прогноз задержки GPU. Для воспроизводимого сравнения фиксируют модель и её prediction target, автоэнкодер и масштаб латентов, разрешение, sampler, сетку времени, CFG, начальный шум и точность вычислений. Совпадение одного seed между разными реализациями не гарантирует одинакового начального тензора или результата.

| Компонент | Что определяет | Чего одного недостаточно узнать |
|---|---|---|
| Автоэнкодер | Пространство генерации, форму и масштаб латентов | Только названия VAE |
| Denoiser | Вычисление предсказания по состоянию, времени и условию | Только слова Transformer |
| Целевая величина | Смысл выхода: шум, чистое состояние, $v$ или скорость пути | Только формы выходного тензора |
| Обучающий путь и выбор времени | Распределение промежуточных состояний и вес их ошибок | Только слова diffusion или flow |
| Guidance | Способ усиления условия | Только текста prompt |
| Solver | Последовательность обновлений и число вычислений поля | Только числа «шагов» |

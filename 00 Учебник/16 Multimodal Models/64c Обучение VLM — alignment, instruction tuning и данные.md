# Обучение VLM: alignment, instruction tuning и данные

В обучающем примере к фотографии автомобиля приложены вопрос «Какого цвета
машина?» и правильный ответ «Красная». Модель получает изображение и вопрос,
а затем предсказывает токены ответа. Во время обучения предыдущие токены
ответа берутся из разметки. Ошибка предсказания меняет параметры тех
компонентов, которые разрешено обучать на текущем этапе.

Одна и та же фотография допускает разные задания. Подпись «Красная машина
стоит у дома» учит описанию. Вопрос о номере на машине требует прочитать
символы. Запрос «Укажи машину» связывает текст с координатами. Разметка
определяет, какие сведения требуется извлечь; функция потерь задаёт ошибку,
а маска и набор обучаемых параметров определяют, куда пойдёт градиент.

Предполагается, что устройство
[[02 Areas/ML & DL/00 Учебник/16 Multimodal Models/64a Connectors и fusion|connector и языкового decoder]]
и подготовка
[[02 Areas/ML & DL/00 Учебник/16 Multimodal Models/64b Разрешение, tiling и пространственные позиции|визуальной последовательности]]
уже знакомы. Здесь рассматривается обучение моделей, которые принимают
изображения и генерируют текст. Генерация изображений и аудио требует
других выходных представлений и разобрана отдельно.

## 1. Что происходит на последовательных стадиях

У исходной [LLaVA, §4.2](https://arxiv.org/abs/2304.08485v2) есть два
этапа. Сначала модель получает изображение и короткую просьбу описать его;
правильным ответом служит готовая подпись. Зрительный encoder и LLM
заморожены, обучается только проекция между ними. После этого projector
и LLM обучаются на визуальных инструкциях, а зрительный encoder
по-прежнему остаётся замороженным.

Цель предсказания следующего токена на этих этапах не меняется.
Меняются данные, запросы, длина ответов и обучаемые параметры.
Сначала подпись помогает подобрать входные векторы для уже обученной
LLM. Затем диалоги задают формат ответа, зависимость от вопроса,
несколько ходов беседы и задания, которых в короткой подписи нет.

В первой стадии LLaVA использовано 595 тысяч отфильтрованных пар CC3M.
Для диалогового варианта второй стадии авторы подготовили
LLaVA-Instruct-158K. Эти числа относятся к исходной LLaVA; у LLaVA-1.5
и OneVision другие наборы и программы обучения. Название семейства
без версии не определяет обучающую смесь.

«Alignment» также может обозначать разные функции потерь. В CLIP это
контрастивное обучение двух представлений, в первой стадии LLaVA
генерация подписи через замороженную LLM. BLIP-2 сначала обучает
Q-Former с contrastive, matching и generation objectives, затем
подключает замороженную языковую модель. Маски и примеры трёх
целей BLIP-2 разобраны в
[[02 Areas/ML & DL/00 Учебник/16 Multimodal Models/64a Connectors и fusion|главе о connectors]].
Называть все эти процедуры одной операцией «сблизить embeddings»
было бы неточно.

## 2. Alignment: научить LLM читать визуальный вход

Для изображения $I$ зрительный encoder $f_\psi$ возвращает сетку
признаков $Z=f_\psi(I)$. Connector $g_\phi$ переводит её в
последовательность $H=g_\phi(Z)$, которую можно подать языковой
модели. Для подписи из токенов $y_1,\ldots,y_T$ используется
условная вероятность

$$
p(y\mid I,q)=
\prod_{t=1}^{T}p_\theta(y_t\mid H,q,y_{<t}).
$$

Здесь $q$ — текстовая просьба описать изображение. При teacher forcing
модель предсказывает очередной токен, зная правильные предыдущие
токены подписи. Например, для ответа «Красная машина» первый
токен предсказывается по изображению и запросу, следующий по тем
же данным и уже известному «Красная». В обучение входит также
предсказание завершения ответа.

Отрицательный логарифм этой вероятности даёт сумму ошибок:

$$
\mathcal L=
-\sum_{t=1}^{T}\log p_\theta(y_t\mid H,q,y_{<t}).
$$

У замороженной LLM параметры $\theta$ не обновляются. Однако её
вычисления остаются частью пути от ошибки к $\phi$:

$$
\nabla_\phi\mathcal L
=
\left(\frac{\partial H}{\partial\phi}\right)^\top
\nabla_H\mathcal L.
$$

Проекция получает градиент через языковую модель. Входные векторы
подбираются так, чтобы фиксированный decoder повышал вероятность
нужных слов. Не требуется, чтобы каждый visual embedding совпал
покоординатно с embedding какого-либо слова.

### Один шаг обучения проекции

Возьмём уменьшенный пример с двумя возможными ответами: «красная»
и «синяя». Зрительный признак равен $(1,0)$. Фиксированная выходная
матрица равна единичной, а обучаемая проекция сначала нулевая.
Оба logits тогда равны нулю, вероятности ответов равны $0.5$,
ошибка правильного ответа «красная» равна $-\log0.5\approx0.6931$.

Градиент cross-entropy по двум logits равен $(-0.5,0.5)$.
Шаг SGD с learning rate 0.2 изменяет первый столбец проекции на
$(0.1,-0.1)$. Новые logits равны $(0.1,-0.1)$, вероятность
правильного ответа около 0.5498, ошибка около 0.5981.

```python
import torch
import torch.nn.functional as F

projector = torch.nn.Linear(2, 2, bias=False, dtype=torch.float64)
frozen_head = torch.nn.Linear(2, 2, bias=False, dtype=torch.float64)
with torch.no_grad():
    projector.weight.zero_()
    frozen_head.weight.copy_(torch.eye(2))
frozen_head.requires_grad_(False)

visual = torch.tensor([[1., 0.]], dtype=torch.float64)
target = torch.tensor([0])  # «красная»
optimizer = torch.optim.SGD(projector.parameters(), lr=.2)
before = F.cross_entropy(frozen_head(projector(visual)), target)
before.backward()
assert frozen_head.weight.grad is None
assert torch.allclose(
    projector.weight.grad,
    torch.tensor([[-.5, 0.], [.5, 0.]], dtype=torch.float64),
)
optimizer.step()
after = F.cross_entropy(frozen_head(projector(visual)), target)
assert abs(before.item() - .69314718) < 1e-7
assert abs(after.item() - .59813887) < 1e-7
```

Это один условный токен и линейная выходная часть вместо настоящей
LLM. Пример показывает обновление projector, а не способность
распознавать цвета. В большой модели между visual embeddings и logits
стоят decoder blocks; тот же chain rule проходит через них.

Запуск всей замороженной LLM под `torch.no_grad()` разорвал бы
этот путь. Для её весов отключают накопление градиентов, но сохраняют
дифференцирование по входу. Визуальные признаки замороженного encoder
можно вычислить без графа, если перед ним нет обучаемых модулей.

## 3. Какие параметры размораживать

Обучение projector оставляет исходные веса зрения и языка неизменными.
Для них не нужны градиенты параметров и состояния оптимизатора.
Но для передачи градиента через LLM всё ещё могут понадобиться её
активации. Поэтому заморозка сокращает память оптимизатора, но
не превращает forward и backward по входам в бесплатные операции.

Если нужная информация не представлена в выходе ViT, projector не
может получить её из ниоткуда. Размораживание ViT позволяет изменить
зрительные признаки под OCR, диаграммы и геометрию. Изменение LLM
адаптирует обработку этих признаков и поведение в диалоге. При этом
обучение может ухудшить прежние способности, поэтому качество
контролируют также на text-only и других сохранённых задачах.

### Три этапа InternVL и перенос зрительного encoder

В [InternVL 2.5, §3.2–3.3](https://arxiv.org/abs/2412.05271v1)
начальный MLP warmup обучает projector при замороженных ViT и LLM.
Следующий, необязательный этап 1.5 обучает ViT вместе с projector,
оставляя LLM замороженной. На последнем этапе обновляется вся модель.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/vlm-2026/internvl25-figure4-training-pipeline.png]]

*Zhe Chen et al., [InternVL 2.5, Figure 4](https://arxiv.org/abs/2412.05271v1),
PDF p. 6. Панель (a) показывает три набора обучаемых компонентов.
В панели (b) уже дообученный InternViT используется с более крупной
LLM; для новой пары снова обучается projector.*

Например, ViT можно адаптировать с меньшей языковой моделью, затем
перенести его веса в систему с большей LLM. Её входное пространство
и размерность могут отличаться, поэтому connector для новой пары
нужно согласовать заново. Необязательность этапа 1.5 относится к
повторному использованию подготовленного ViT, а не к возможности
удалить любое обучение зрения без последствий.

Даже при одинаковом наборе обучаемых модулей learning rates могут
различаться. В [Molmo, §4](https://arxiv.org/abs/2409.17146v2)
отдельный connector-only warmup вообще пропущен: на PixMo-Cap
сразу обучаются все компоненты. Для connector задан learning rate
$2\cdot10^{-4}$ и warmup 200 шагов, для ViT $6\cdot10^{-6}$
и для LLM $2\cdot10^{-5}$, с warmup 2000 шагов у обоих.
Это конкретная программа Molmo, не общая рекомендация для любой VLM.

Обратный пример даёт InternVL 2.5: на этапе полного instruction
tuning авторы используют один learning rate для всей модели.
Из фразы «предобученные компоненты обычно учат медленнее» нельзя
восстановить параметры чужого эксперимента.

## 4. Как устроен loss mask в диалоге

В одном входе находятся изображение, вопрос и правильный ответ.
При causal attention каждый токен может читать только предыдущие
позиции и себя. Отдельная маска targets определяет, за какие
предсказания начисляется ошибка. Эти две маски выполняют разные задачи.

Для вопроса о сумме в чеке условная последовательность выглядит так.
Одна строка таблицы обозначает здесь одну позицию; реальный tokenizer
может делить числа и слова иначе.

| Позиция | Вход | Label |
|---:|---|---|
| 0 | `<user>` | ignore |
| 1 | visual A | ignore |
| 2 | visual B | ignore |
| 3 | вопрос | ignore |
| 4 | `<assistant>` | ignore |
| 5 | `12` | `12` |
| 6 | `480` | `480` |
| 7 | `₽` | `₽` |
| 8 | `<eos>` | `<eos>` |

Logits позиции 4 предсказывают токен позиции 5, то есть `12`.
Позиция 5 предсказывает `480`, позиция 6 предсказывает `₽`,
позиция 7 предсказывает завершение. Нельзя сравнивать logits
позиции 5 с токеном `12`, уже поданным на той же позиции.

Маскированные visual positions не исключены из контекста.
Ответ может обращаться к их keys и values, а градиент ошибки
может дойти до visual embeddings. Отсутствует только требование
предсказывать сами визуальные векторы как текстовые token IDs.

В учебном примере правильные вероятности четырёх targets равны
0.5, 0.25, 0.125 и 0.5. Их отрицательные логарифмы приблизительно
равны 0.6931, 1.3863, 2.0794 и 0.6931. Сумма ошибок около
4.8520, средняя ошибка составляет

$$
\mathcal L\approx4.8520/4=1.2130.
$$

```python
import torch
import torch.nn.functional as F

# Четыре условных token IDs: 12, 480, ₽ и eos.
labels = torch.tensor([-100] * 5 + [0, 1, 2, 3])
prob = torch.full((9, 4), .25, dtype=torch.float64)
for row, target, p in [(4, 0, .5), (5, 1, .25),
                       (6, 2, .125), (7, 3, .5)]:
    prob[row].fill_((1 - p) / 3)
    prob[row, target] = p
logits = prob.log().requires_grad_()
loss = F.cross_entropy(logits[:-1], labels[1:], ignore_index=-100)
loss.backward()
active_rows = logits.grad.abs().sum(dim=1).nonzero().flatten().tolist()
assert active_rows == [4, 5, 6, 7]
assert abs(loss.item() - 1.21300757) < 1e-7
```

Нулевой градиент по *logits* замаскированной строки в этом коде
не означает нулевого градиента по её входному embedding в настоящем
Transformer: более поздние ответы используют этот вход через attention.

В multi-turn примере ошибку можно считать на каждом ответе assistant.
Второй ответ видит первый, поскольку они принадлежат одному диалогу,
но первый не видит второй. В исходной LLaVA обучаются также токены
завершения ответа. У Qwen-VL (§3.3) supervision распространяется
на ответы и предусмотренные форматом специальные токены, но не на
имена ролей и пользовательские вопросы. Детали границ зависят от
chat template; общий лозунг «только assistant» их не заменяет.

### Packing и несколько разметок одного изображения

Независимые диалоги можно уложить в один длинный тензор. Обычная
causal mask тогда позволила бы второму диалогу читать ответы первого.
Для независимых примеров добавляют ограничение по номеру примера.
У двух последовательностей длины 5 и 4 начала равны 0 и 5;
массив границ имеет вид `[0,5,9]`, позиции внутри каждой
последовательности начинаются с нуля.

В мультимодальном packing есть ещё бюджет ViT. При пределе
2048 позиций и восьми плитках запросы на 700 позиций/3 плитки
и 1000 позиций/6 плиток помещаются по длине, но требуют девять
плиток и не помещаются по зрительному бюджету. Запрос на
600 позиций/4 плитки можно объединить с первым: получится
1300 позиций и семь плиток. Такой двойной бюджет описан в
[InternVL 2.5, §4.2](https://arxiv.org/abs/2412.05271v1).

```python
import numpy as np

sample = np.repeat([0, 1], [5, 4])
index = np.arange(9)
allowed = ((sample[:, None] == sample[None, :]) &
           (index[:, None] >= index[None, :]))
assert not allowed[5:, :5].any()
assert allowed.sum() == 5 * 6 // 2 + 4 * 5 // 2
assert 700 + 1000 <= 2048 and 3 + 6 > 8
assert 700 + 600 <= 2048 and 3 + 4 <= 8

# Общий prefix изображения и две независимые аннотации.
branch = np.array([-1, -1, -1, 0, 0, 1, 1])
causal = np.arange(7)[:, None] >= np.arange(7)[None, :]
shared = causal & ((branch[:, None] == branch[None, :]) |
                   (branch[None, :] == -1))
assert shared[5:, :3].all()
assert not shared[5:, 3:5].any()
assert shared.sum() == 24
```

Последняя маска иллюстрирует другой случай из [Molmo, §2](https://arxiv.org/abs/2409.17146v2):
одно изображение имеет несколько независимых вопросов. Его prefix
кодируется один раз. Каждая аннотация читает этот prefix и свою
предшествующую часть, но не соседние аннотации. В примере позиции
5–6 видят изображение 0–2, но не аннотацию 3–4. Это отличается
от настоящего multi-turn диалога, где история первого ответа
нужна для второго.

При упаковке необходимо согласовать также image indices,
границы targets и знаменатель loss. Модель не должна случайно
подставить признаки картинки соседнего примера или обучаться
предсказывать первый токен нового примера по последнему токену
предыдущего.

## 5. Какие данные создают какие способности

В короткой подписи обычно указаны несколько заметных объектов.
Она может не содержать номера дома, мелкой надписи и положения
всех предметов. Если эти детали нужны в ответе, обучающая разметка
должна хотя бы в части примеров требовать их восстановления.
Длинные описания, буквальный OCR, вопросы к таблице и координаты
дают разные виды supervision даже для одного изображения.

### PixMo: от устного описания до точек и документов

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/vlm-2026/molmo-figure1-data-and-capabilities.png]]

*Deitke et al., [Molmo and PixMo, Figure 1](https://arxiv.org/abs/2409.17146v2),
PDF p. 2. Слева показаны способы получения разметки, справа
примеры заданий. Нижний ряд объединяет детекции, вопросы по
подписям, синтетические часы и генерацию документов из кода.*

В [PixMo-Cap, §3](https://arxiv.org/abs/2409.17146v2) люди сначала
описывали изображение голосом не менее минуты; позднее использовался
один разметчик с минимумом 90 секунд. Записи транскрибировали,
а языковая модель приводила текст к формату подписи. Авторы сообщают
712 тысяч изображений, 1.3 млн транскриптов и подписей, средняя длина
готовой подписи около 196 слов. Сама длительность записи не
гарантирует качество: она описывает процедуру сбора, после которой
ещё нужны транскрипция и обработка текста.

Для PixMo-AskModelAnything человек выбирал изображение и задавал вопрос.
Языковая модель получала OCR и подробную подпись, предлагала ответ,
затем человек принимал или исправлял его. Пиксели видел человек;
текстовый помощник зависел от переданных ему сведений.
Проверка человеком не сводилась к оценке стиля: нужно было
исправить фактический ответ по картинке.

PixMo-Points собирался иначе: разметчик указывал объекты точками.
Для запроса «Все стулья» целевым ответом становится список координат.
В counting-примерах модель сначала перечисляет точки, затем число.
Три разные точки дают проверяемый счёт 3, но только если разметчик
нашёл все объекты и не отметил один дважды. Правильный формат
координат не доказывает полноту разметки.

В синтетических PixMo-Docs языковая модель генерирует код страницы
с таблицей или диаграммой; изображение получается рендерингом.
Код даёт доступ к значениям и структуре, из которых строятся вопросы.
В PixMo-Clocks время задаётся при создании циферблата. В PixMo-Count
используются детекции объектов, а в PixMo-CapQA вопросы строятся
по готовой подписи. Это разные источники правильного ответа:
для кода и часов он задан генератором, у detector и caption
он ограничен ошибками предыдущей модели или разметки.

Метки задачи помогают не смешивать требования к ответам.
Например, DocVQA требует извлечения текста, а свободный диалог
допускает пояснения. В Molmo для части academic datasets
используются style tags. Они позволяют явно запросить короткий
benchmark-формат, не делая его обязательным для всех разговоров.

### LLaVA: что видит текстовый учитель

GPT-4 в исходной LLaVA не получал пиксели COCO-изображения.
Ему передавали несколько подписей, классы объектов и bounding boxes,
после чего он создавал разговоры, подробные описания и вопросы
с рассуждением. Источник: [Visual Instruction Tuning, §3](https://arxiv.org/abs/2304.08485v2).

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/stanford-cs336-2026/multimodal/llava-gen.png]]

*Stanford CS336, Lecture 17; пример из Table 1 работы
Liu et al., [Visual Instruction Tuning](https://arxiv.org/abs/2304.08485v2).
Фото справа показано читателю, но не передавалось текстовому GPT-4.
В оригинале сохранены входные captions/boxes и три вида ответов.*

Из фразы «люди укладывают багаж в чёрный SUV» можно построить
вопрос о типе автомобиля. Номер машины по этой фразе определить
нельзя. Учитель способен сгенерировать строку, похожую на номер,
но она не будет подтверждена входом. Такой пример нельзя считать
правильной OCR-разметкой без дополнительного источника.

Разметка с учителем-VLM даёт ему доступ к пикселям, но также
не гарантирует верности. В OneVision для повторного описания
изображений использовался LLaVA-NeXT-34B; часть данных получалась
через GPT-4V. Это отличается от текстового учителя ранней LLaVA.
При воспроизведении указывают, видел ли учитель картинку,
какую версию использовали и как проверяли ответы.

### Фильтрация и связь изображения с ответом

[InternVL 2.5, §4.3](https://arxiv.org/abs/2412.05271v1)
описывает несколько фильтров: оценку качества текста, поиск
повторяющихся фрагментов и эвристики для аномальных ответов.
Отмеченные примеры проверялись вручную. Для мультимодальных
данных авторы не переносили весь text-only quality scoring
без изменений: акцент сделан на повторах и эвристиках.

Повторяющиеся ответы могут обучить модель повторяться, но
правило «удалить любую повторяющуюся строку» удалит и часть
корректного OCR, например одинаковые строки бланка. Кандидаты
на удаление требуют проверки по задаче. Отдельно проверяется
сама связь: изображение действительно соответствует вопросу,
номер страницы сохранён, рамка относится к нужному объекту,
а правильный ответ не попал в обучающий prompt из служебных
метаданных.

Разделение train и test делают до преобразования одного оригинала
в десятки crops, вопросов и recaptions. Иначе один документ может
оказаться в обеих частях под разными именами. Сходство исходных
изображений и документов проверяют отдельно от текстовых
дубликатов ответов; эти проверки находят разные утечки.

## 6. Как смешивать неодинаковые наборы

Пусть есть 10 млн caption-примеров, 1 млн document QA и
100 тысяч grounding-примеров. При случайном выборе строки
из объединённого корпуса доли составят около 90.1%, 9.0%
и 0.9%. На 10 тысяч выбранных примеров grounding получит
в среднем лишь около 90 предъявлений, причём не обязательно
90 уникальных изображений.

Температурное сглаживание задаёт вероятность выбрать набор:

$$
p_k=\frac{n_k^\alpha}{\sum_j n_j^\alpha}.
$$

При $\alpha=1$ сохраняются пропорции объёмов. При $\alpha=0$
наборы выбираются равновероятно; это не равновероятный выбор
каждой отдельной строки общего корпуса. При $\alpha=0.5$
доли нашего примера становятся примерно 70.6%, 22.3% и 7.1%.
Grounding получает около 706 предъявлений на 10 тысяч случайных выборов.

В Molmo (§4) используется выбор пропорционально квадратному
корню объёма с дополнительными ручными поправками: часть
крупных синтетических наборов ослаблена, pointing усилен.
В зафиксированном
[InternVL training script](https://github.com/OpenGVLab/InternVL/blob/2410d1dbf208f0e799459aff9376e5747dbf41a2/internvl_chat/internvl/train/internvl_chat_finetune.py#L749-L784)
при включённом `use_data_resampling` также используется
$\sqrt{n_k}$. Сам флаг и коэффициенты нужно сохранять
в конфигурации эксперимента.

Одинаковые доли примеров не означают одинаковых долей токенов.
Зададим для трёх наборов средние полные длины 200, 2000 и 1000
позиций. При $\alpha=0.5$ document QA составляет около 22.3%
примеров, но около 67.8% входных токенов. Это ещё не доля
FLOPs: длина visual prefix, число плиток ViT и вид attention
могут различаться.

```python
import numpy as np

sizes = np.array([10_000_000, 1_000_000, 100_000], dtype=float)
weights = np.sqrt(sizes)
example_share = weights / weights.sum()
mean_length = np.array([200, 2000, 1000])
token_mass = example_share * mean_length
token_share = token_mass / token_mass.sum()
assert np.allclose(example_share, [.706101, .223289, .070610], atol=1e-6)
assert .677 < token_share[1] < .679
assert 705 < 10_000 * example_share[2] < 707
```

### Нормировка loss по длине ответа

Вероятность выбора примера и его вес в loss задаются отдельно.
В одном batch может быть короткий ответ из четырёх target-токенов
со средней ошибкой 2 и длинный из 16 со средней ошибкой 1.

При token averaging среднее равно
$(4\cdot2+16\cdot1)/20=1.2$.
При sample averaging сначала усредняют ошибку каждого примера,
затем примеры: $(2+1)/2=1.5$.
В первом случае длинный ответ имеет в четыре раза больший
суммарный вес, во втором веса примеров равны.

В [InternVL 2.5, §3.4](https://arxiv.org/abs/2412.05271v1)
используется промежуточный вариант: каждому target-токену
примера длины $n_i$ присваивается вес $1/\sqrt{n_i}$.
Суммарный вес примера тогда равен $\sqrt{n_i}$.
У двух ответов выше веса 2 и 4, среднее равно
$(2\cdot2+4\cdot1)/6=4/3$.

Общая запись для этих трёх способов:

$$
\mathcal L_\gamma=
\frac{\sum_i n_i^{-\gamma}\sum_{t=1}^{n_i}\ell_{it}}
{\sum_i n_i^{1-\gamma}}.
$$

$\gamma=0$ даёт token averaging, $\gamma=1$ sample averaging,
$\gamma=1/2$ square averaging. Здесь $n_i$ считает только
обучаемые targets. Visual positions, вопросы и padding в
этот знаменатель не входят. В реализации InternVL
для multi-turn примера учитывается общее число его
немаскированных labels.
Примеры без обучаемых targets требуют отдельной обработки:
при нулевом суммарном весе делить loss на этот знаменатель нельзя.

```python
import numpy as np

length = np.array([4., 16.])
mean_loss = np.array([2., 1.])

def length_weighted_loss(gamma):
    mass = length ** (1 - gamma)
    return mean_loss @ mass / mass.sum()

assert np.isclose(length_weighted_loss(0), 1.2)
assert np.isclose(length_weighted_loss(1), 1.5)
assert np.isclose(length_weighted_loss(.5), 4 / 3)
```

В коде
[`len2weight`](https://github.com/OpenGVLab/InternVL/blob/2410d1dbf208f0e799459aff9376e5747dbf41a2/internvl_chat/internvl/train/internvl_chat_finetune.py#L786-L795)
строит веса, а
[packed collator](https://github.com/OpenGVLab/InternVL/blob/2410d1dbf208f0e799459aff9376e5747dbf41a2/internvl_chat/internvl/train/dataset_packed.py#L517-L545)
считает targets внутри исходных примеров. Перед передачей
модели веса ignored labels обнуляются. При gradient accumulation
нужно согласовать знаменатель между microbatches: среднее двух
уже нормированных losses не обязано совпадать с нормировкой
по всем target-токенам шага.

Qwen3-VL тоже сообщает о square-root reweighting, но один
термин не доказывает совпадения всех деталей реализации.
Приведённая точная формула и код относятся к InternVL.
Параметры другой модели нельзя восстанавливать по названию
этого приёма.

## 7. Curriculum по разрешению и типам задач

При переходе к длинным документам меняются не только допустимые
позиции. В обучающих примерах должны появиться страницы,
вопросы к удалённым фрагментам и ответы, требующие их сопоставить.
Если собрать длинную последовательность из несвязанных
картинок, ограничив attention между ними, это повысит
эффективность packing, но само по себе не обучит рассуждению
через весь документ.

### LLaVA и OneVision как два конкретных curriculum

У LLaVA два этапа, описанные выше. У
[LLaVA-OneVision, §5 и Table 1](https://arxiv.org/abs/2408.03326v1)
программа длиннее. На этапе 1 projector обучается на 558 тысячах
пар с базовым изображением $384\times384$. Этап 1.5 обновляет
всю модель на примерно четырёх миллионах примеров более
подробных описаний, OCR и языковых заданий.

Далее идут 3.2 млн инструкций с одним изображением и смесь
OneVision с одиночными изображениями, несколькими изображениями
и видео. Для последней стадии в тексте перечислены 560 тысяч
multi-image, 350 тысяч video и 800 тысяч single-image примеров.
Их сумма около 1.71 млн и не совпадает с названием «1.6M»
в отчёте. По сводным числам нельзя восстановить точный состав:
для воспроизведения нужны фактический manifest и версии наборов.

### Какие способности переносятся между сценариями

В работе показаны ответы на задачи, которые комбинируют несколько
изображений. В одном случае модель должна прочитать радиус и угол
на геометрическом рисунке, найти цену в таблице и выполнить расчёт.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/stanford-cs336-2026/multimodal/llava-onevision-transfer-s1.png]]

*Li et al., LLaVA-OneVision; [оригинальная иллюстрация Stanford CS336](https://github.com/stanford-cs336/lectures/blob/8b59b50730766695c2ffedd1a79c50cd09b9eb91/images/llava-onevision-transfer-s1.png).
Сохранён ответ модели из источника. В нём есть арифметические
ошибки; правильный расчёт приведён ниже.*

На рисунке $r=11$, угол $40^\circ$, цена Allstate равна 63.
Площадь сектора:

$$
A=\frac{40}{360}\pi\,11^2\approx42.24.
$$

При вычислении стоимости без промежуточного округления получается
около 2660.93. Если сначала округлить площадь до 42.24, затем
умножить на 63, получится 2661.12. Напечатанные в ответе
модели 38.01 и 2386.03 не согласуются с этими данными.

```python
import math

area = 40 / 360 * math.pi * 11**2
assert round(area, 2) == 42.24
assert round(area * 63, 2) == 2660.93
assert round(round(area, 2) * 63, 2) == 2661.12
assert round(38.01 * 63, 2) == 2394.63
```

По этому примеру можно обсуждать формат совместного использования
двух картинок, но нельзя объявить весь ответ правильным. Для
оценки переноса нужны проверенные задачи и сравнение вариантов
обучения при контроле данных, бюджета и исходных компонентов.
Качественная демонстрация не выделяет причинный вклад одной стадии.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/stanford-cs336-2026/multimodal/llava-onevision-transfer-s2.png]]

*Li et al., LLaVA-OneVision; [оригинальная иллюстрация Stanford CS336](https://github.com/stanford-cs336/lectures/blob/8b59b50730766695c2ffedd1a79c50cd09b9eb91/images/llava-onevision-transfer-s2.png).

### Qwen-VL: почему меняются и данные, и замороженные модули

В [Qwen-VL, §3.1–3.3](https://arxiv.org/abs/2308.12966v1)
на первом этапе обновляются ViT и adapter, а LLM заморожена.
Используются 1.4 млрд очищенных image–text pairs; входное
разрешение равно $224\times224$. Это другой выбор, чем
connector-only стадия LLaVA.

На втором этапе обновляется вся модель, разрешение повышается
до $448\times448$, добавляются семь типов заданий: подписи,
VQA, варианты grounding, OCR и генерация текста. На третьем
этапе ViT снова заморожен, а LLM и adapter дообучаются на
350 тысячах диалоговых примеров, включая text-only data.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/stanford-cs336-2026/multimodal/qwen-vl-stages.png]]

*Bai et al., [Qwen-VL, Figure 2](https://arxiv.org/abs/2308.12966v1),
копия Stanford CS336 Lecture 17. Заморозка ViT на последнем
этапе относится к Qwen-VL этой версии, не ко всей линии Qwen-VL.*

Число 1.4 млрд описывает размер очищенного корпуса.
При batch size 30 720 и 50 тысячах шагов число предъявлений
равно 1.536 млрд, а не 1.4 млрд уникальных изображений на
каждом шаге или эпохе. Размер набора и объём потреблённых
примеров нужно различать.

### Qwen3-VL: четыре этапа pre-training и post-training

В [Qwen3-VL, §3.1](https://arxiv.org/abs/2511.21631v1)
сначала обновляется только merger, затем все компоненты.
Первые два этапа имеют одинаковый предел 8192 позиции:
само размораживание не требует изменения context length.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/stanford-cs336-2026/multimodal/qwen3-vl-pretraining.png]]

*Bai et al., [Qwen3-VL, Table 1](https://arxiv.org/abs/2511.21631v1),
копия Stanford CS336 Lecture 17. В таблице приведены token
budgets и длины четырёх этапов, а не четыре размера модели.*

На S0 merger обучается на 67 млрд токенов: captions,
визуальные знания и OCR. На S1 все компоненты обучаются
примерно на триллионе токенов при тех же 8192 позициях.
Смесь содержит также text-only данные.

S2 повышает предел до 32 768, добавляет больше видео и
agent-oriented data, а также увеличивает долю text-only.
На S3 используются 100 млрд токенов с контекстом до
262 144; акцент сделан на длинных документах и видео.
Предел 256K не означает, что каждый пример имеет эту длину.

После этого идут SFT, strong-to-weak distillation и RL.
В отчёте SFT тоже имеет две фазы: 32K, затем 256K, а
thinking и non-thinking варианты получают разные форматы
целевых ответов. Перечислять всё это как одну стадию
«добавили длинные рассуждения» недостаточно для воспроизведения.

## 8. Post-training должен проверять опору на изображение

SFT повышает вероятность данного ответа. Если все вопросы
о цвете машины в наборе имеют ответ «красная», модель может
хорошо использовать частоту ответа даже без чтения цвета.
Проверка требует примеров с тем же вопросом и другими
изображениями, где правильный ответ меняется.

Для координатного задания можно вычислить IoU предсказанной
рамки с разметкой. Если правильная рамка $[0,0,2,2]$, то
точное совпадение даёт 1, рамка $[1,0,3,2]$ даёт $1/3$,
непересекающаяся рамка даёт 0. Для иллюстративного reward
с порогом 0.5 только первая получает награду. И порог,
и правило границ рамок являются частью задания.

```python
import numpy as np

def iou(box, target):
    box, target = np.array(box), np.array(target)
    lo = np.maximum(box[:2], target[:2])
    hi = np.minimum(box[2:], target[2:])
    intersection = np.maximum(hi - lo, 0).prod()
    a = np.maximum(box[2:] - box[:2], 0).prod()
    b = np.maximum(target[2:] - target[:2], 0).prod()
    return float(intersection / (a + b - intersection))

target = [0, 0, 2, 2]
scores = [iou(box, target) for box in
          [[0, 0, 2, 2], [1, 0, 3, 2], [3, 0, 5, 2]]]
assert np.allclose(scores, [1, 1 / 3, 0])
assert [s >= .5 for s in scores] == [True, False, False]
```

Этот reward оценивает геометрию уже выбранного объекта.
Он не проверяет, что модель выбрала нужный класс, корректно
прочитала подпись или вернула допустимый JSON. Эти условия
нужно включать в проверку отдельно. OCR exact match также
зависит от нормировки пробелов, регистра и чисел; лишнее
объяснение может нарушить строгий формат, хотя сам текст
распознан верно.

В [Qwen3-VL, §4.4](https://arxiv.org/abs/2511.21631v1)
reasoning RL использует задания с проверкой правилами
или исполнением кода. В этой версии отчёта назван
алгоритм SAPO; приписывать ей GRPO по сходству с другими
reasoning-моделями нельзя. В General RL сочетаются
rule-based и model-based rewards. Judge помогает оценивать
открытые ответы, но его оценку тоже нужно проверять
на ошибочных деталях, многословии и форматных обходах.

### Дистилляция ответов и распределений

В off-policy дистилляции ученик учится на ответах, заранее
сгенерированных учителем. В on-policy варианте ученик
сам порождает продолжение, а учитель оценивает его префиксы.
Это позволяет обучать ученика на состояниях, которые
возникают у него самого, включая несовершенные продолжения.

В Qwen3-VL (§4.3) сначала используется response distillation,
затем on-policy согласование logits через KL divergence.
Авторы отдельно указывают text-only данные для strong-to-weak
стадии. Из этого не следует, что учитель в этой процедуре
проверял пиксели каждого изображения.

Пусть у следующего токена два варианта. Учитель задаёт
$p=(0.8,0.2)$, ученик $q=(0.6,0.4)$. Согласование полного
распределения даёт

$$
D_{\mathrm{KL}}(p\Vert q)
=\sum_jp_j\log\frac{p_j}{q_j}
\approx0.0915.
$$

Здесь важны обе вероятности. Если оставить только самый
вероятный токен учителя, второй вариант исчезнет из target,
и получится другое задание. Этот числовой пример иллюстрирует
направление teacher-to-student KL; он не задаёт неизвестные
температуру и reduction конкретной закрытой training pipeline.

```python
import numpy as np

teacher = np.array([.8, .2])
student = np.array([.6, .4])
kl = np.sum(teacher * np.log(teacher / student))
assert abs(kl - .09151622) < 1e-7
assert np.isclose(np.sum(teacher * np.log(teacher / teacher)), 0)
```

Улучшение text-only reasoning после такой дистилляции не
является самостоятельным доказательством улучшения OCR
или локализации. Для каждой визуальной способности нужны
свои контрольные примеры и измерения до и после обучения.

## 9. Карточка воспроизводимости

Для повторения эксперимента сохраняют версии ViT, connector,
LLM и chat template; исходные checkpoints; обучаемые модули
и learning rates по этапам. Из конфигурации должно быть
видно, какое изображение действительно подано модели:
resize, tiling, число кадров и visual token budget.

Для данных нужны версии наборов, происхождение разметки,
лицензии, split по исходным документам, фильтры и сведения
об учителе. Для смеси сохраняют sampling weights, повторения
наборов, число предъявлений и потреблённых токенов. Размер
скачанного корпуса не равен объёму обучения.

Отдельно фиксируют labels и их сдвиг, ignored positions,
веса target-токенов и знаменатель loss, маски packing,
границы исходных примеров, microbatch size, gradient
accumulation и distributed reduction. По нескольким
обезличенным примерам полезно сохранять итоговую
последовательность, маску и список соответствий
«изображение → visual positions».

Для контроля качества сохраняют text-only retention,
OCR, grounding, вопросы к нескольким изображениям и
длинным документам. Тестовые оригиналы и их производные
не должны попадать в смесь обучения. Случай, где ответ
правилен при замене картинки на нерелевантную, проверяют
отдельно: он может решаться текстовой подсказкой или
утечкой, а не извлечением нужного визуального факта.

# Рекомендательные системы

У двух посетителей магазина один каталог, но разные истории покупок.
Рекомендательная система должна выбрать объекты для каждого посетителя
и расположить их в порядке показа. Для этого она использует взаимодействия,
описания объектов и контекст запроса. Какие данные были доступны к этому
моменту и какие объекты вообще можно было показать, определяет постановку
задачи наряду с моделью.

<a id="почему-это-отдельная-дисциплина"></a>
## Какие данные использует модель

Совместная фильтрация, или *collaborative filtering*, ищет закономерности
во взаимодействиях пользователей с объектами. Например, покупатели,
интересовавшиеся одними книгами, часто интересуются и другими общими книгами.
Методы на основе содержимого используют описания: автора, жанр, текст
или изображение обложки. Эти сигналы можно объединить в одной модели.

![[Assets/Sources/Dive into Deep Learning — Recommender Systems/rec-intro.svg]]

*Zhang et al., исходная схема взаимодействия пользователя с приложением из
[D2L, Overview of Recommender Systems](https://d2l.ai/chapter_recommender-systems/recsys-intro.html).
[CC BY-SA 4.0](https://github.com/d2l-ai/d2l-en/blob/23d7a5aecceee57d1292c56e90cce307f183bb0a/LICENSE-SUMMARY).
Покупки, лайки, просмотры и дизлайки поступают в рекомендательную систему,
которая возвращает приложению список объектов. Схема показывает цикл
обратной связи, а не классификацию методов.*

Внутри совместной фильтрации различаются методы, которые непосредственно
сравнивают пользователей или объекты, и методы, которые обучают параметры,
например латентные векторы. Применение нейронной сети не задаёт источник
сигнала: сеть может получать только идентификаторы либо дополнительно
использовать текст, изображение и признаки контекста.

## Как модель становится выдачей

Оценка $s(u,i,c)$ относится к одному объекту. Система должна ещё найти
объекты, которые стоит оценить, и собрать из них допустимый список.
Если ограничено число товаров одной категории, следующий выбор зависит
от уже добавленных товаров; независимой сортировки scores недостаточно.

![[00 Учебник/Assets/Figures/curated/recommender-data-2026-10-25/google-process.svg]]

*Google, [Recommendation systems overview](https://developers.google.com/machine-learning/recommendation/overview/types).
Исходная схема трёх этапов без изменений:
candidate generation, scoring и re-ranking.
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Части страницы воспроизведены из материалов, созданных и
[предоставленных Google](https://developers.google.com/terms/site-policies).*

Поиск кандидатов сокращает каталог, ранжирование оценивает найденные объекты,
а последующая обработка учитывает ограничения на выдачу. Затем приложение
показывает список и регистрирует события. Модель не сможет ранжировать
релевантный товар, который был потерян при поиске кандидатов.

Версия алгоритма показа, позиция и состав списка определяют, по каким
объектам появятся новые отклики. Например, объект на первой позиции может
собирать больше кликов из-за заметности, а объект вне выдачи не получит
кликов вообще. При следующем обучении эти различия попадут в данные.
Офлайн-метрика на логах прежней версии сама по себе не устанавливает эффект
новой выдачи на пользователей.

<a id="минимальный-сквозной-dataset"></a>
## Таблицы и время

Для сквозного примера нужны пользователи, каталог, показы и отклики.
История взаимодействий строится из этих записей, а обучающие признаки —
из версий, которые уже были доступны на момент решения.

| Данные | Что необходимо восстановить |
| --- | --- |
| Пользователи | Идентификатор и доступные тогда признаки; отсутствие истории у нового пользователя |
| Каталог | Объекты и версии описаний, доступность в момент запроса |
| Показы | Запрос, позицию, версию алгоритма и факт доставки или просмотра по принятому определению |
| Отклики | Тип действия, время события, связь с показом и окно формирования метки |

MovieLens содержит оценки и timestamps, но не полный журнал показов,
доступности каталога и отрицательных откликов. Его удобно использовать
для факторизации матрицы и сравнения протоколов, однако по нему нельзя
восстановить все четыре таблицы как у действующего магазина.

Одна и та же покупка может стать положительным объектом для поиска,
целевым следующим событием или откликом на ранее показанную рекомендацию.
Эти варианты дают разные строки обучения и разные множества сравнения.

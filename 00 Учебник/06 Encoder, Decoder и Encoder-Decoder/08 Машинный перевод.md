«Не закрывайте клапан до полудня» можно перевести как *Do not close the
valve before noon* или *Before noon, do not shut the valve*. Вторая
версия меняет порядок слов и выбирает другой глагол, но сохраняет
смысл. Если из первой версии убрать *not*, почти все слова совпадут
с эталоном, хотя указание станет противоположным.

<a id="mt-parallel-data"></a>

## Откуда берутся пары предложений

Для обучения с учителем нужны пары $(x,y)$: исходный текст $x$ и
его перевод $y$. У двуязычной инструкции можно сопоставить разделы
по номерам, но предложения внутри раздела ещё нужно выровнять.
Переводчик мог соединить два предложения в одно, вынести пояснение
в сноску или пропустить строку. Если взять одинаковые номера
предложений, после одного пропуска все последующие пары сместятся.

Из независимых коллекций пары можно искать с помощью
[[02 Areas/ML & DL/00 Учебник/15 Embeddings, Retrieval и RAG/60 Embeddings и metric learning|эмбеддингов]].
Энкодер строит один вектор на предложение, затем система ищет
соседей среди предложений другого языка. Пусть для русской строки
с *клапаном* нашлись два английских кандидата: правильный запрет
закрывать клапан и напоминание его открыть. Высокая близость обоих
не делает их переводами. При отборе используют дополнительные
признаки, сравнивают близость с другими соседями и фильтруют пары.
Среди проверок полезны язык, длины, совпадение обозначений или чисел
и отсутствие повторов. Например, пару с «до 12:00» и *before 2 PM*
стоит проверить, даже если остальной текст совпал.

LASER3 решает задачу, которая предшествует поиску: как сопоставлять
векторы разных языков, если новый язык плохо представлен у
старого энкодера. Ученик получает предложение на новом языке,
учитель — его перевод. Обучение сближает два вектора по
косинусной близости. Когда ученик уже умеет помещать новые
предложения в общее пространство, можно искать пары и среди строк
без готового перевода.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/machine-translation-2026-11-22/heffernan-laser3-fig1.png|Справа в LASER3 ученик и учитель кодируют две части пары, а косинусная потеря сближает векторы. Слева ученик восстанавливает замаскированный токен.]]

*Kevin Heffernan, Onur Çelebi и Holger Schwenk,
[Bitext Mining Using Distilled Sentence Representations for Low-Resource Languages, рис. 1](https://aclanthology.org/2022.findings-emnlp.154.pdf#page=3),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Схема из PDF без окружающего текста.*

На правой панели одна пара состоит из турецкого вопроса о часах
и его английского перевода. Другая использует одно английское
предложение с обеих сторон, чтобы привязать ученика к известному
пространству. На левой панели ученик получает турецкое предложение
с пропуском и предсказывает замаскированный токен. На этом шаге
перевод не нужен. Обе потери обучают энкодер для поиска пар;
он не выдаёт перевод.

<a id="mt-objective"></a>

## Чему учится энкодер–декодер

[[02 Areas/ML & DL/00 Учебник/05 Attention и Transformer/03 Полный Transformer|В Transformer]]
энкодер читает всё исходное предложение и возвращает по одному
контекстному вектору на токен. На каждом шаге декодер видит
предыдущие целевые токены через причинную маску, а через
перекрёстное внимание обращается к выходам энкодера. Так, при
выборе *not* декодеру уже известно, что перевод начался с *do*,
и доступна исходная строка с «не». Карта внимания может показать,
какие позиции использует одна голова на данном шаге, но сама по
себе не доказывает, что модель сохранила отрицание.

Вероятность целой последовательности получается перемножением
условных вероятностей. При обучении удобнее складывать их
логарифмы и менять знак:

$$
\mathcal L=-\sum_{t=1}^{T}\log p_\theta(y_t\mid y_{<t},x).
$$

Здесь $T$ включает токен конца. Для краткости условимся, что в
учебном примере одно слово равно одному токену; реальные
токенизаторы могут разбить его на несколько частей. Целевую
последовательность подают на вход декодера со сдвигом. Стартовый
токен в таблице условный; например, у T5 на этой позиции используется
`pad_token_id`.

| Шаг | Что уже есть на входе декодера | Цель на этом шаге |
| ---: | --- | --- |
| 1 | `<start>` | `do` |
| 2 | `<start> do` | `not` |
| 3 | `<start> do not` | `close` |
| Последний | `<start> do not close the valve before noon` | `<eos>` |

На втором шаге при $p_\theta(\text{not}\mid\text{do},x)=0{,}4$
вклад в потерю равен $-\log(0{,}4)\approx0{,}916$. В обучающей
строке третий шаг всё равно получает правильный префикс `do not`:
это обучение с эталонным префиксом (teacher forcing). Маска не
даёт третьей позиции посмотреть на свою цель. При генерации
эталона нет; третий шаг зависит от выбора, который модель сделала
на втором. После ошибочного `do close` ей уже некуда вставить
`not` перед `close`.

<a id="mt-decoding"></a>

## Что сохраняет поиск лучом

Рассмотрим два шага после фиксированного начала `do`. Вероятности ниже
вымышлены. Они показывают, как выбор с более низкой вероятностью
на одном шаге даёт более вероятный полный перевод.

| Префикс | Условные вероятности продолжений |
| --- | --- |
| `do` | `close`: $0{,}60$; `not`: $0{,}40$ |
| `do close` | `the`: $0{,}40$; `that`: $0{,}35$; `this`: $0{,}25$ |
| `do not` | `close`: $0{,}95$; `open`: $0{,}05$ |

Жадный поиск оставит `do close` и на следующем шаге возьмёт
`the`. Вероятность полученного префикса $0{,}60\cdot0{,}40=0{,}24$.
Луч шириной 2 сохранит и `do not`. После расширения обоих
вариантов у `do not close` вероятность $0{,}40\cdot0{,}95=0{,}38$,
поэтому он выйдет на первое место. В этом примере считаем все
дальнейшие продолжения до `<eos>` однозначными, так что порядок
после второго шага больше не изменится.

В реальном поиске сравнивают суммы логарифмов, а гипотеза
может закончиться раньше других. У длинных переводов в сумме
больше неположительных слагаемых.
Поэтому при ранжировании законченных строк часто учитывают длину;
параметр настраивают на отложенных переводах. Увеличение луча
помогает искать высокую оценку *модели*. Оно не исправит ситуацию,
в которой полный перевод без отрицания оценён выше верного.
Поиск с ограничениями может потребовать заданный термин, но
само наличие слова *valve* не проверит, запретила модель закрывать
его или разрешила.

<a id="mt-back-translation"></a>

## Зачем переводить в обратную сторону

Для направления русский → английский может быть мало готовых
пар, зато много хороших английских текстов. Возьмём человеческую
строку *Do not close the valve before noon*. Временная модель
английский → русский создаёт для неё искусственный исходник,
например «Не перекрывайте клапан раньше полудня». В обучении
прямой модели этот русский текст становится входом, а
первоначальная английская строка — целью. Искусственным здесь
является источник, а не целевой текст. Такие пары смешивают с
человеческим битекстом. Ошибки обратной модели остаются
в данных: если она потеряла «не», модель увидит противоречивый
пример.

Способ сгенерировать искусственный источник влияет на обучение.
На графике Edunov и соавторов по горизонтали показано количество
обучающих пар, по вертикали — качество уже обученных моделей
на `newstest2012` для английского → немецкого. Кривые различаются
тем, как раньше получили синтетический **вход**. При равном
общем объёме в правой части графика сэмплирование и луч с
добавленным шумом дали более высокий BLEU, чем чистый луч. Это
сравнение способов подготовки данных в конкретном эксперименте,
а не совет сэмплировать итоговый перевод для пользователя.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/machine-translation-2026-11-22/edunov-backtranslation-fig1.png|Пять кривых WMT: после добавления синтетических пар sampling и beam plus noise поднимаются выше greedy и beam на newstest2012.]]

### Как указать целевой язык

Многоязычная модель может использовать общие параметры для
нескольких направлений. Для одного и того же источника нужно
указать целевой язык: иначе «переведи эту строку» не задаёт
правильный выход. В работе Johnson и соавторов язык назначения
задаёт особый токен во входе. Такие модели можно пробовать на
парах языков, которые не встречались вместе при обучении
(zero-shot), но результат нужно измерять отдельно для каждого
направления. Высокий балл для английского → немецкого мало говорит
о качестве между двумя языками с небольшими корпусами. В работе
[NLLB-200](https://doi.org/10.1038/s41586-024-07335-x) добыча
битекста, многоязычное обучение и проверка направлений на FLORES-200
решают разные части этой задачи.

<a id="mt-evaluation"></a>

## Как проверить, что сохранился смысл

Сравним два перевода с одним эталоном. Считаем без знаков
препинания и регистра; отдельный токенизатор в этом расчёте
не используется.

| Роль | Строка |
| --- | --- |
| Эталон | `do not close the valve before noon` |
| Смысл изменён | `do close the valve before noon` |
| Смысл сохранён | `before noon do not shut the valve` |

У неверной строки совпадают все 6 униграмм; для более длинных
n-грамм доли совпадений равны $4/5$, $3/4$ и $2/3$.
Штраф за краткость равен $\exp(1-7/6)$. Обычное геометрическое
среднее четырёх точностей со штрафом даёт около $67{,}3$ на шкале
0–100. Верный вариант переставляет слова и меняет глагол; общей
триграммы с эталоном нет. Без сглаживания учебный BLEU-4 для этой
строки равен нулю. Это расчёт на коротких строках. В
[[02 Areas/ML & DL/00 Учебник/18 Evaluation и методология/59 Оценивание моделей и контаминация#bleu-reference-overlap|главе об оценивании]]
совпадения и длины сначала суммируются по корпусу.
Для повторяемого результата сохраняют данные, направление перевода
и сигнатуру настроек sacreBLEU.

chrF использует символьные n-граммы и может лучше переносить
изменения окончания или близкое написание слова. Как и совпадение
слов, он не проверяет, что модель сохранила запрет. Оценщик COMET
может учитывать источник вместе с переводом и эталоном. В
варианте *estimator* из статьи Rei и соавторов общий энкодер
кодирует три строки по отдельности. Из объединённых представлений
и их попарных признаков регрессионная сеть предсказывает оценку;
при обучении её сравнивают с размеченной оценкой качества.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/machine-translation-2026-11-22/rei-comet-estimator-fig1.png|В нижней части COMET estimator три входа: Hypothesis, Source, Reference. Общий энкодер и пуллинг дают векторы для регрессионной сети; MSE относится к обучению.]]

*Ricardo Rei, Craig Stewart, Ana C Farinha и Alon Lavie,
[COMET: A Neural Framework for MT Evaluation, рис. 1](https://aclanthology.org/2020.emnlp-main.213.pdf#page=3),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Схема из PDF без окружающего текста.*

На схеме оценщик с эталонным переводом на входе; другие версии
COMET могут обходиться без него. Результат зависит от обученного чекпойнта. Он
не выдаёт правила «в каждом запрете должно быть *not*»: запрет можно
выразить иначе. При ручной проверке по [MQM](https://aclanthology.org/2021.tacl-1.87/)
эксперт отмечает конкретную ошибку и её тяжесть. Потеря отрицания
здесь относится к точности передачи смысла, а замена *close* на
*shut* может быть допустима. Отдельные срезы по отрицаниям,
числам, именам и терминологии выявляют сбои, которые общий
балл по корпусу может скрыть. Для перевода документов добавляют
контекст соседних предложений: он нужен, например, чтобы правильно
перевести местоимение или последовательно назвать одну деталь.

<details>
<summary>Проверка двух шагов поиска и расчёта BLEU на Python</summary>

~~~python
from collections import Counter
from math import exp, isclose, log

# The prefix "do" is fixed. The remaining tails are deterministic in this toy.
edges = {
    ("do",): [("close", 0.60), ("not", 0.40)],
    ("do", "close"): [("the", 0.40), ("that", 0.35), ("this", 0.25)],
    ("do", "not"): [("close", 0.95), ("open", 0.05)],
}
def beam(width):
    active = [(("do",), 1.0)]
    for _ in range(2):
        candidates = [(seq + (word,), p * q)
                      for seq, p in active for word, q in edges[seq]]
        active = sorted(candidates, key=lambda item: -item[1])[:width]
    return active

assert beam(1)[0][0] == ("do", "close", "the")
assert isclose(beam(1)[0][1], 0.24)
assert beam(2)[0][0] == ("do", "not", "close")
assert isclose(beam(2)[0][1], 0.38)
assert round(-log(0.40), 3) == 0.916

def grams(words, n):
    return Counter(tuple(words[i:i+n]) for i in range(len(words) - n + 1))

def toy_bleu4(candidate, reference):
    cand, ref = candidate.split(), reference.split()
    precision = []
    for n in range(1, 5):
        counts = grams(cand, n)
        matches = sum((counts & grams(ref, n)).values())
        precision.append(matches / sum(counts.values()))
    bp = exp(min(0, 1 - len(ref) / len(cand)))
    score = (bp * exp(sum(log(p) for p in precision) / 4)
             if all(precision) else 0)
    return precision, 100 * score

ref = "do not close the valve before noon"
wrong = "do close the valve before noon"
safe = "before noon do not shut the valve"
precision, score = toy_bleu4(wrong, ref)
assert precision == [1, 4/5, 3/4, 2/3]
assert round(score, 1) == 67.3
assert toy_bleu4(safe, ref)[1] == 0
~~~

</details>

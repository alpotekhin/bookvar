В 2021 году биолог Анна Левина пришла работать в Институт Севера.
Через два года она возглавила институт.

Два предложения сообщают разные факты об одном человеке и одной
организации: Левина начала работать в институте и позже
стала его руководителем. Чтобы записать второй факт, нужны оба
предложения. Во втором нет ни имени Левиной, ни названия института,
ни календарного года.

<a id="ie-mentions"></a>

## Упоминания и объекты

[[02 Areas/ML & DL/00 Учебник/06 Encoder, Decoder и Encoder-Decoder/03a Распознавание именованных сущностей|Распознавание именованных сущностей]] может выделить
*Анна Левина* как имя человека и *Институт Севера* как название
организации. В задаче кореференции нужны ещё *она* и *институт*
во втором предложении. Это тоже упоминания: у каждого своё место в тексте, хотя они
указывают на уже названные объекты.

| Упоминание | Фрагмент | Предложение | Объект в документе |
| --- | --- | ---: | --- |
| $m_1$ | Анна Левина | 1 | `person:1` |
| $m_2$ | Институт Севера | 1 | `org:1` |
| $m_3$ | она | 2 | `person:1` |
| $m_4$ | институт | 2 | `org:1` |

В рабочем наборе у каждого упоминания хранят границы в исходном
документе: например, номера символов, а не только строку. Два
одинаковых слова на разных позициях могут обозначать разные объекты.
Идентификаторы `person:1` и `org:1` пока действуют внутри этого
документа. Чтобы объединить сведения из разных документов, можно
сопоставить такие объекты с записями каталога.

<a id="ie-coreference"></a>

## Как модель связывает «она» с именем

Антецедентом называют предшествующее упоминание, к которому
отсылает другое. Для `она` модель сравнивает `Анна Левина`,
`Институт Севера` и вариант «предшественника нет».
Для `институт` она может отдельно выбрать `Институт Севера`.
В результате получаются группы $\{m_1,m_3\}$ и $\{m_2,m_4\}$.

В модели Lee и соавторов входом служит документ, а не готовый
список имён. Модель рассматривает фрагменты ограниченной длины и
строит вектор каждого фрагмента из контекстных векторов его
границ, взвешенной суммы слов внутри и признака длины. Оценка
$s_m(i)$ показывает, насколько фрагмент похож на упоминание.
Фрагменты с низкими оценками отбрасываются до сравнения пар:
при $n$ токенах и максимальной длине $L$ уже на первом шаге
кандидатов порядка $nL$, если $L\le n$.

Для оставшейся пары $(i,j)$, где $j$ находится раньше $i$, модель
отдельно оценивает совместимость $s_a(i,j)$. К ней прибавляются
оценки обоих упоминаний:

$$
s(i,j)=s_m(i)+s_m(j)+s_a(i,j).
$$

Пусть для `она` $s_m=0{,}4$, для имени $0{,}7$, для названия
института $0{,}5$. Модель дала первой паре совместимость $1{,}1$,
второй $-1{,}2$. Итоговые баллы равны $2{,}2$ и $-0{,}3$.
У пустого антецедента балл равен нулю. После softmax на этих трёх
вариантах имя получает вероятность около $0{,}838$. Баллы здесь
учебные; в обученной модели они зависят от контекста, расстояния
между фрагментами и выученных параметров.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/information-extraction-2026-11-22/lee-antecedents-fig2.png|Для the company модель сравнивает General Electric, the Postal Service и пустой антецедент. Оценки двух упоминаний и пары сходятся перед softmax.]]

*Kenton Lee, Luheng He, Mike Lewis и Luke Zettlemoyer,
[End-to-end Neural Coreference Resolution, рис. 2](https://aclanthology.org/D17-1018.pdf#page=3),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Схема из PDF без окружающего текста.*

На рисунке эту же роль играет *the company*. Два пути снизу
прибавляют баллы пары и её фрагментов, третий подаёт фиксированный
ноль. Пустой антецедент нужен, в частности, для первого упоминания
нового объекта. При обучении не обязательно объявлять единственно
правильным ближайшее упоминание: если объект уже упоминался
несколько раз, Lee и соавторы суммируют вероятности всех его
допустимых предшественников и увеличивают эту суммарную вероятность.
При предсказании выбранные связи образуют группы: если $m_5$ ссылается
на $m_3$, а $m_3$ на $m_1$, все три входят в одну группу.

Политика разметки определяет, что считать одним объектом.
«Институт» относится к организации, но «его лаборатория» может
обозначать отдельное подразделение. Связь части и целого нельзя
превращать в кореференцию даже при близком соседстве слов.

<a id="ie-linking"></a>

## Как найти Анну Левину в каталоге

У двух людей может быть одно имя. Пусть в учебном каталоге
`P17` — биолог Анна Левина, `P54` — архитектор с тем же именем,
`P81` — спортсменка с похожим именем. В документе эти записи не
перечислены. Задача связывания сущностей (entity linking) — вернуть
`P17`, используя имя и контекст «биолог … пришла работать в Институт
Севера». Для `она` можно использовать ID, найденный по более
информативному упоминанию из той же группы.

В BLINK первый энкодер вычисляет вектор контекста упоминания $q$,
а второй — вектор $e$ из названия и описания записи. Векторы каталога
можно вычислить заранее. По скалярному произведению $q^\top e$
выбирают первые $K$ кандидатов. Возьмём $q=(0{,}8;\,0{,}6)$ и три
двумерных вектора каталога:

| Запись | Вектор | Балл первого этапа |
| --- | --- | ---: |
| `P54`, архитектор | $(0{,}8;\,0{,}6)$ | $1{,}00$ |
| `P17`, биолог | $(0{,}6;\,0{,}8)$ | $0{,}96$ |
| `P81`, спортсменка | $(0;\,1)$ | $0{,}60$ |

При $K=2$ правильная запись пока вторая. На следующем этапе
кросс-энкодер читает контекст и описание вместе. Он может
сопоставить слово «биолог» из текста со специальностью в карточке.
При логитах $1{,}1$ для `P54` и $2{,}7$ для `P17` запись `P17`
выходит на первое место. После softmax по двум кандидатам она
получает примерно $0{,}832$. При $K=1$ система получила бы только `P54`.
Переранжирование не может вернуть правильную запись, если первый
этап её отсеял.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/information-extraction-2026-11-22/wu-blink-fig1.png|Слева отдельные энкодеры помещают контекст Jaguar и карточки в одно пространство; справа совместный энкодер сравнивает контекст с карточками аттракциона и автомобиля.]]

*Ledell Wu, Fabio Petroni, Martin Josifoski, Sebastian Riedel и Luke Zettlemoyer,
[Scalable Zero-shot Entity Linking with Dense Entity Retrieval, рис. 1](https://aclanthology.org/2020.emnlp-main.519.pdf#page=2),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Схема из PDF без окружающего текста.*

В примере из статьи оба значения *Jaguar* проходят поиск, а
совместный энкодер предпочитает аттракцион. В отличие от модели
кореференции, здесь сравниваются фрагмент документа и карточка
из внешнего каталога. Wu и соавторы оценивали случаи, в которых
границы упоминаний заданы и эталонная карточка есть в каталоге.
Совпадение внутри документа можно установить и без внешней карточки.
В системе с неполным каталогом
для такого случая нужен результат `NIL` или решение отдать запись
на проверку. Softmax по найденным карточкам сам по себе не
показывает, есть ли среди них правильная: с одним кандидатом он дал
бы единицу даже для ошибочной записи.

<a id="ie-relations"></a>

## От пары сущностей к отношению

Пусть в схеме базы есть отношения `works_for`, `heads` и
`founded`. Текст подтверждает первые два для пары «Левина,
Институт Севера». В нём не сказано, что она основала институт. Порядок
аргументов фиксирован схемой: `heads(Левина, Институт Севера)`,
а не `heads(Институт Севера, Левина)`.

Первый факт можно извлечь из одного предложения. Локальное
правило найдёт конструкцию «пришла работать в» между именем
человека и названием организации. [[02 Areas/ML & DL/00 Учебник/02 Представление текста и токенизация/04 Синтаксический разбор|Синтаксический разбор]] помогает
сохранить аргументы при изменении порядка слов. Но даже правильное
дерево зависимостей не отличит утверждение от его отрицания без
интерпретации «не»: «Левина не работала в Институте Севера» содержит
те же имена. Формы «может возглавить» и «возглавила» тоже дают
разные записи. Если в схеме нет статуса планов и предположений,
их нельзя добавлять как состоявшиеся события.

Для второго факта текст о назначении содержит только `она` и
`институт`. Модель уровня документа сравнивает группы
упоминаний, поэтому может найти `heads` для той же пары локальных
объектов. При сохранении записи укажем предложение 2 как место,
где сказано о назначении, и предложение 1 как место, откуда
восстановлены аргументы и время. В [DocRED](https://aclanthology.org/P19-1074/)
разметка различает тройки и предложения, которые их подтверждают.
Присутствие двух имён в предложении ещё не делает его доказательством
конкретного отношения.

Обучаемый классификатор может взять контекстные векторы
упоминаний, объединить векторы каждой группы и построить оценки
для направленной пары. Если для пары верны несколько предикатов,
модель может выдавать на каждый предикат логит и оценку после
сигмоиды. При обучении бинарную кросс-энтропию считают отдельно
для каждого предиката. Классификатор с одной меткой на пару
потерял бы одно из двух верных отношений. Фильтр типов сокращает число пар: для `heads` первый
аргумент должен быть человеком, второй организацией. Фильтр не
устанавливает сам факт и не заменяет проверку контекста.

<a id="ie-events"></a>

## Событие, его участники и время

Тройка `heads(Левина, Институт Севера)` не отличает назначение
в 2023 году от сообщения о текущем руководителе. Если в базе
нужно хранить изменения во времени, удобно выделить событие с
триггером `возглавила`. У события есть роли: новый руководитель,
организация и время начала. Значение `2023` получается из
фразы «через два года» и опорного 2021 года в предыдущем
предложении. В тексте нет месяца, дня или даты окончания работы.

~~~yaml
event: assume_directorship
person: P17
organization: O01
year: 2023
evidence_sentences: [1, 2]
~~~

`O01` здесь означает карточку Института Севера в том же
учебном каталоге. Выражения времени могут обозначать интервалы
и требовать привязки к контексту. Например, для «на прошлой неделе»
может понадобиться дата публикации, а без неё календарное
значение останется неизвестным. [SUTime](https://aclanthology.org/L12-1122/)
разделяет распознавание выражения и его нормализацию; результат может
зависеть от опорного времени. Связывание «через два года» с
событием из предыдущего предложения — ещё одна задача, которую
нельзя решить по форме выражения без контекста.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/information-extraction-2026-11-22/wadden-dygie-fig1.png|В DyGIE++ предложения поступают в BERT, затем модель перечисляет фрагменты и обновляет их в графе; отдельные выходы отвечают за сущности, отношения, события и вспомогательную кореференцию.]]

*David Wadden, Ulme Wennberg, Yi Luan и Hannaneh Hajishirzi,
[Entity, Relation, and Event Extraction with Contextualized Span Representations, рис. 1](https://aclanthology.org/D19-1585.pdf#page=1),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Схема из PDF без окружающего текста.*

DyGIE++ использует общие представления фрагментов для нескольких
задач. BERT кодирует предложение вместе с соседними,
затем модель выделяет фрагменты-кандидаты. Предсказанные
связи могут обновлять их векторы через граф. Отдельные головы
оценивают типы сущностей, отношения, триггеры и роли аргументов;
кореференция служит вспомогательной задачей. В статье выход
классификатора отношений ограничен парами фрагментов внутри
предложения. Межфразовый контекст в представлениях не отменяет
это ограничение. Привязка к внешнему каталогу и нормализация
календарной даты тоже не следуют из схемы DyGIE++.

<a id="ie-evaluation"></a>

## Как раздельно считать ошибки

Если верны границы четырёх упоминаний, но `она` оставили в одиночной
группе, метрика NER по именам не заметит ошибку. Для $B^3$ у
каждого упоминания сравнивают предсказанную группу $C$ и эталонную
$G$. Точность для этого упоминания равна $|C\cap G|/|C|$, полнота
$|C\cap G|/|G|$. Затем усредняют по упоминаниям. В примере у всех
четырёх точность 1, а полнота равна $1/2$ для каждого упоминания
Левиной и 1 для каждого упоминания института. Получаем
$P=1$, $R=3/4$ и $F_1=6/7$. Это расчёт на заранее совпадающих
границах. При предсказанных упоминаниях важны правила выравнивания
и учёта одиночных групп; для сравнения с CoNLL нужен его официальный
протокол, а не один этот показатель.

Для связывания сперва считают, есть ли эталонная карточка в
результатах поиска (recall@$K$), затем проверяют выбор первого
кандидата. Пусть из десяти упоминаний с эталонным ID нужная
карточка попала в список для восьми, а на первое место попала
для шести. Тогда recall@$K$ равна $8/10$; точность ранжирования
при успешном поиске — $6/8$; точность всей связки — $6/10$.
Отдельно оценивают случаи без эталонной карточки и
ошибки границ упоминаний.

При оценке отношений на фиксированных сущностях сравнивают
множества троек. Пусть классификатор дал $0{,}86$ для `works_for`,
$0{,}75$ для `heads` и $0{,}58$ для `founded`. Порог $0{,}7$
оставит две истинные тройки. Порог $0{,}5$ добавит неподтверждённую:
точность станет $2/3$, полнота останется 1 и $F_1=0{,}8$.
В показателе для всей системы ошибочный ID может превратить
верное отношение в лишнюю тройку и одновременно в пропуск.
Поэтому полезно сравнить прогон с эталонными сущностями и прогон
с предсказанными. Для событий можно раздельно проверять триггер,
роли участников и нормализованное время.

<summary>Проверка оценок, групп и троек на Python</summary>

~~~python
from math import exp, isclose

def softmax(scores):
    shift = max(scores)
    weights = [exp(s - shift) for s in scores]
    return [w / sum(weights) for w in weights]

# m3: rank m1, m2, and the empty antecedent.
p = softmax([0.4 + 0.7 + 1.1, 0.4 + 0.5 - 1.2, 0.0])
assert round(p[0], 3) == 0.838

q = (0.8, 0.6)
catalog = {"P17": (0.6, 0.8), "P54": (0.8, 0.6), "P81": (0.0, 1.0)}
dense = {k: sum(a * b for a, b in zip(q, v)) for k, v in catalog.items()}
assert isclose(dense["P17"], 0.96)
top2 = sorted(dense, key=dense.get, reverse=True)[:2]
assert top2 == ["P54", "P17"]
cross = dict(zip(top2, softmax([1.1, 2.7])))
assert max(cross, key=cross.get) == "P17"
assert round(cross["P17"], 3) == 0.832

def f1(p, r):
    return 2 * p * r / (p + r) if p + r else 0

gold_clusters = [{1, 3}, {2, 4}]
pred_clusters = [{1}, {3}, {2, 4}]
def membership(groups):
    return {m: group for group in groups for m in group}
g, c = membership(gold_clusters), membership(pred_clusters)
bp = sum(len(c[m] & g[m]) / len(c[m]) for m in g) / len(g)
br = sum(len(c[m] & g[m]) / len(g[m]) for m in g) / len(g)
assert (bp, br) == (1.0, 0.75) and isclose(f1(bp, br), 6 / 7)

pair = ("P17", "O01")
gold = {(pair[0], r, pair[1]) for r in ("works_for", "heads")}
scores = dict(zip(("works_for", "heads", "founded"), (0.86, 0.75, 0.58)))
for threshold, expected in [(0.7, (1, 1, 1)), (0.5, (2 / 3, 1, 0.8))]:
    pred = {(pair[0], r, pair[1]) for r, score in scores.items() if score >= threshold}
    p, r = len(pred & gold) / len(pred), len(pred & gold) / len(gold)
    assert all(isclose(a, b) for a, b in zip((p, r, f1(p, r)), expected))

# The second sentence provides the offset; the first provides its anchor.
records_by_mention = {1: "P17", 2: "O01"}
def verified_ids(groups):
    result = {}
    for group in groups:
        ids = {records_by_mention[m] for m in group if m in records_by_mention}
        if len(ids) == 1:
            result.update({m: next(iter(ids)) for m in group})
~~~

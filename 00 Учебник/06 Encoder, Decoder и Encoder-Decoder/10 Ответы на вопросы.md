Сколько заявок направили подрядчику в четверг? В журнале мастерской
есть запись: «В четверг специалисты передали две заявки подрядчику».
Из неё достаточно извлечь «две заявки». Если вопрос задали через
поиск по всем журналам, системе ещё предстоит найти эту запись.
Она может быть в архиве и не попасть в выдачу. А название подрядчика
может отсутствовать даже в правильном документе.

<a id="qa-task"></a>

## Вопрос, отрывок и ответ

В задаче чтения системе дают пару «вопрос, отрывок». В
[SQuAD 1.1](https://aclanthology.org/D16-1264/) ответом служит
непрерывный фрагмент этого отрывка. В разметку входят текст ответа и
его смещение. Смещение нужно, если одна и та же строка встречается
несколько раз. «Две заявки» из записи в четверг годится, а такая же
фраза из журнала за предыдущую неделю не относится к вопросу.

В open-domain QA отрывок заранее не дан: его ищут в коллекции.
[DrQA](https://aclanthology.org/P17-1171/) сначала находила статьи
Википедии, а затем извлекала ответ из их текста. При разборе
ошибки можно проверить по отдельности, нашла ли система
подходящий текст и правильно ли прочла его модель.

<a id="qa-retrieval"></a>

## Как нужная запись попадает в выдачу

Пусть для вопроса о четверге в архиве есть три фрагмента:

| Фрагмент | Текст |
| --- | --- |
| A. Инструкция | «Приём заявок в четверг. Перед тем как направить заявку подрядчику, проверьте адрес». |
| B. Запись о передаче | «В четверг специалисты передали две заявки подрядчику». |
| C. Запись о закрытии | «К среде мастерская закрыла восемь заявок из той же партии». |

При поиске с BM25 совпадения терминов повышают оценку. Инструкция A
содержит слова из формулировки вопроса, но в ней нет числа
отправленных заявок. Если A заняла первое место, то при одном
возвращаемом фрагменте модель чтения до B не дойдёт. При двух
фрагментах она увидит B, если тот стоит вторым.

В [Dense Passage Retrieval](https://aclanthology.org/2020.emnlp-main.550/)
отдельные энкодеры строят векторы вопроса и фрагмента. Векторы
фрагментов вычисляют и индексируют заранее. При запросе достаточно
закодировать вопрос и искать фрагменты с большим скалярным
произведением. При обучении DPR оценка пары «вопрос, подходящий
фрагмент» конкурирует в softmax с оценками отрицательных фрагментов.
Авторы берут отрицательные примеры, среди прочего, из выдачи BM25:
слова совпадают, а нужного ответа в тексте нет.

Для ручного расчёта возьмём условные двумерные векторы. У вопроса
$v_q=(1;0{,}50)$, у B — $v_B=(0{,}30;0{,}84)$. Их скалярное
произведение равно $1\cdot0{,}30+0{,}50\cdot0{,}84=0{,}72$.

| Фрагмент | Вектор | Оценка поиска |
| --- | --- | ---: |
| A | (0,40; 0,20) | 0,50 |
| B | (0,30; 0,84) | 0,72 |
| C | (0,28; 0,36) | 0,46 |

Теперь первым стоит B. Значение 0,72 задаёт его место среди
кандидатов, но не показывает вероятность правильного ответа.

Если в трёх вопросах нужный фрагмент оказался на местах 2, 1 и 3,
поиск попал в первый результат в $1/3$ случаев, а в первые два —
в $2/3$. На графике DPR по вертикали показана доля вопросов, для
которых хотя бы в одном из первых $k$ фрагментов встретилась
эталонная строка ответа. Такая строка не всегда служит
доказательством: те же «две заявки» могли относиться к другой неделе.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/question-answering-2026-11-22/karpukhin-dpr-fig1.png|График DPR на Natural Questions: по горизонтали число найденных фрагментов k, по вертикали доля вопросов с ответом в первых k. Линии показывают BM25 и DPR с разным объёмом обучения.]]

*Vladimir Karpukhin и соавторы, [Dense Passage Retrieval for Open-Domain Question Answering, рис. 1](https://aclanthology.org/2020.emnlp-main.550.pdf#page=5), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Полный график из статьи, без исходной подписи.*

Движение вдоль одной линии показывает, что изменится, если
увеличить $k$ при той же модели. Разные линии при одном $k$
сравнивают BM25 и варианты DPR. Это результаты поиска на
валидационной части Natural Questions. Даже если поиск нашёл
подходящий фрагмент, модель чтения ещё может ошибиться. Чем больше
текста передано на чтение, тем дороже этот этап и тем больше у
модели похожих кандидатов.

<a id="qa-span"></a>

## Как BERT выбирает начало и конец

Для чтения BERT получает вопрос и фрагмент в одной
последовательности: [CLS], токены вопроса, [SEP], токены текста,
[SEP]. В отличие от двух энкодеров DPR, здесь представление
каждого токена текста может зависеть от вопроса. Один и тот же
токен «четверг» будет представлен по-разному для вопросов «в какой
день передали заявки?» и «сколько заявок передали?».

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/question-answering-2026-11-22/devlin-bert-qa-fig4c.png|Панель BERT для SQuAD 1.1: вопрос и отрывок разделены SEP. Выходы над токенами отрывка используются, чтобы оценить начало и конец ответа.]]

*Jacob Devlin, Ming-Wei Chang, Kenton Lee и Kristina Toutanova, [BERT, рис. 4(c)](https://aclanthology.org/N19-1423.pdf#page=15), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Показана панель для извлечения ответа.*

В оригинальном BERT два обучаемых вектора дают для каждого
выходного состояния $h_i$ две оценки: $a_i=w_s^\top h_i$ для
начала и $b_i=w_e^\top h_i$ для конца. На обучении нормируют
каждый набор оценок отдельно через softmax. Если эталонные
границы — $i^\star$ и $j^\star$, потеря равна

$$
\mathcal L=-\log p_s(i^\star)-\log p_e(j^\star).
$$

Для вывода оценивают пары. В одном окне сумма логитов $a_i+b_j$
даёт тот же порядок пар, что и сумма двух логарифмов вероятностей:
нормировочные константы не зависят от пары. Пара допустима,
если оба края лежат во фрагменте, $i\le j$ и
$j-i+1\le L_{\max}$. Нельзя выбрать токен из вопроса или склеить
края из разных окон.

Посчитаем пару для записи B. Для примера считаем слова токенами
и нумеруем слова фрагмента отдельно от вопроса. Первые четыре
слова — «В четверг специалисты передали». В таблице показаны
три сильных кандидата; у остальных позиций оценки ниже.

| Позиция | Слово | Начало $a_i$ | Конец $b_i$ |
| ---: | --- | ---: | ---: |
| 5 | две | 2,8 | 1,6 |
| 6 | заявки | 1,2 | 2,4 |
| 7 | подрядчику | 3,1 | 0,5 |

Лучшее начало отдельно от конца — 7, лучший конец — 6.
Пару $(7,6)$ нужно отбросить. При пределе в три токена
$(5,6)$ получает $2{,}8+2{,}4=5{,}2$, а $(5,5)$ — 4,4.
Одинокое «подрядчику» получает 3,6. Система возвращает $(5,6)$,
то есть «две заявки».

В рабочей модели позиции относятся к субтокенам. Чтобы вернуть
строку статьи, индексы переводят обратно в символьные смещения
исходного текста. Длинные документы делят на перекрывающиеся
окна: иначе начало и конец короткого ответа могут оказаться
по разные стороны границы.

<a id="qa-no-answer"></a>

## Когда в отрывке нет ответа

Сменим вопрос: «Как называлась компания-подрядчик?» В B есть
слово «подрядчику», но имени нет. Если обязать модель всегда
возвращать диапазон, слово с хорошим совпадением по теме может
стать ответом. В [SQuAD 2.0](https://aclanthology.org/P18-2124/)
разметчики добавляли такие правдоподобные вопросы без ответа
в отрывке. Одних совпадающих слов для решения недостаточно.

В варианте BERT для SQuAD 2.0 [CLS] обозначает отсутствие
ответа. Для такого примера обе обучающие метки указывают на
[CLS]. На выводе сравнивают сумму логитов на [CLS], $s_\varnothing$,
с оценкой лучшего допустимого диапазона $s_{\mathrm{span}}$.
В [реализации авторов](https://github.com/google-research/bert/blob/master/run_squad.py)
вывод пуст, если $s_\varnothing-s_{\mathrm{span}}>\tau$.
Порог выбирают на отложенных данных. При большем пороге
система чаще возвращает диапазон, в том числе для вопросов,
на которые в тексте ответа нет.

| Вопрос к B | Лучший диапазон | Оценка диапазона | Оценка [CLS] | Разница |
| --- | --- | ---: | ---: | ---: |
| Сколько заявок передали? | две заявки | 5,2 | 2,0 | −3,2 |
| Как назывался подрядчик? | подрядчику | 3,3 | 4,1 | 0,8 |

При $\tau=0{,}5$ первый ответ остаётся, второй заменяется
на пустой. При $\tau=1$ система выдала бы «подрядчику».
Эти значения относятся к одному окну и заданы для примера;
логиты не являются процентами уверенности. При нескольких
окнах нужно определить, как сравнивать диапазоны и сигналы
отказа между окнами.

Пустой ответ сообщает о решении системы по доступным ей
фрагментам. Из него нельзя вывести, что имени нет во всём
архиве. Сначала проверьте, был ли в выдаче отрывок с ответом.
Если его не было, подставьте его и запустите чтение ещё раз.
Так можно выяснить, достаточно ли исправить поиск. Если отрывок
уже был в выдаче, ошибку надо искать в чтении или отборе ответа.

<a id="qa-metrics"></a>

## Что показывают Exact Match и F1

В SQuAD после нормализации Exact Match равен единице, если
ответ совпал хотя бы с одним из эталонов. Английский
[скрипт оценки](https://rajpurkar.github.io/SQuAD-explorer/)
игнорирует регистр, пунктуацию, артикли и лишние пробелы.
Склонение русских слов эта процедура не учитывает: для
другой коллекции правила нормализации задают отдельно.

Пусть единственный эталон — «две заявки». Ответ «две» не
совпадает с ним целиком, но его единственный токен присутствует
в эталоне. Точность равна $1/1$, полнота $1/2$, F1 равен $2/3$.
В разговоре «две» может быть вполне естественным ответом.
Балл ниже единицы здесь отражает выбор эталона.

| Предсказание | Эталон | Exact Match | F1 |
| --- | --- | ---: | ---: |
| две заявки | две заявки | 1 | 1 |
| две | две заявки | 0 | 0,667 |
| восемь | две заявки | 0 | 0 |
| пусто | пусто | 1 | 1 |

При нескольких эталонах берут лучший результат по каждой
метрике, затем усредняют оценки по вопросам. В SQuAD 2.0
баллы для вопросов с ответом и без него можно посмотреть
отдельно. Иначе одна цифра может скрыть, что модель часто
угадывает ответ или, наоборот, слишком часто отказывается.
Для задачи с поиском дополнительно измеряют попадание
подходящего фрагмента и качество итогового ответа.

<a id="qa-generation"></a>

## Ответ из нескольких записей

Генеративной модели можно задать вопрос и без документов. В таком
режиме, который называют [closed-book QA](https://aclanthology.org/2020.emnlp-main.437/), ответ зависит от сведений,
усвоенных при обучении. Модель могла выучить известную дату, но
из одного вопроса она не узнает, что записали в журнале мастерской
в четверг. Для вопроса к журналу документ нужно передать на вход.

На вопрос «Сколько заявок закрыли к среде и сколько передали
в четверг?» нужны B и C. Одного непрерывного диапазона
здесь нет. Из двух отрывков можно составить ответ:
«К среде закрыли восемь [C], в четверг подрядчику передали две [B]».

В [Fusion-in-Decoder](https://aclanthology.org/2021.eacl-main.74/)
вопрос присоединяют к каждому найденному фрагменту отдельно.
Авторы добавляют и заголовок фрагмента. Один и тот же энкодер
обрабатывает эти входы независимо. На схеме блок «concat»
объединяет выходные последовательности скрытых состояний,
а декодер через перекрёстное внимание читает их совместно.
Токены ответа он предсказывает по одному, как в
[[02 Areas/ML & DL/00 Учебник/06 Encoder, Decoder и Encoder-Decoder/09 Суммаризация текста#sum-generation|главе о суммаризации]].

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/question-answering-2026-11-22/izacard-fid-fig2.png|Слева отдельные пары вопрос плюс фрагмент проходят общий энкодер независимо. Скрытые состояния объединяются и поступают в декодер, который выдаёт ответ.]]

*Gautier Izacard и Edouard Grave, [Leveraging Passage Retrieval with Generative Models for Open Domain Question Answering, рис. 2](https://aclanthology.org/2021.eacl-main.74.pdf#page=2), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Исходная схема.*

Так энкодеру не приходится считать самовнимание сразу между
токенами всех документов. Зато декодер видит больше состояний:
с ростом числа фрагментов растёт стоимость перекрёстного
внимания. Схема даёт декодеру доступ к обеим записям, но не
гарантирует, что он возьмёт восемь из C и две из B.
Буквы в примере — ссылки на подтверждения, добавленные для
разбора. Оригинальная модель обучалась выдавать строку ответа
без этих ссылок. Проверку утверждений и ссылок подробнее
разбирает [[02 Areas/ML & DL/00 Учебник/15 Embeddings, Retrieval и RAG/63 RAG — полный конвейер|глава о RAG]].

<details>
<summary>Проверить поиск, границы и метрики в Python</summary>

~~~python
from collections import Counter
from math import isclose


def dot(q, p):
    return sum(a * b for a, b in zip(q, p))


q = (1.0, 0.50)
passages = {"A": (0.40, 0.20), "B": (0.30, 0.84), "C": (0.28, 0.36)}
scores = {key: round(dot(q, vector), 2) for key, vector in passages.items()}
assert scores == {"A": 0.50, "B": 0.72, "C": 0.46}
assert sorted(scores, key=scores.get, reverse=True) == ["B", "A", "C"]
ranks = (2, 1, 3)
assert [sum(r <= k for r in ranks) for k in (1, 2)] == [1, 2]


def select_span(start, end, threshold=0.5):
    # Position 0 encodes no answer. Other keys are passage positions.
    score, span = max(
        (a + b, (i, j))
        for i, a in start.items() for j, b in end.items()
        if 0 < i <= j and j - i + 1 <= 3
    )
    difference = start[0] + end[0] - score
    return (None if difference > threshold else span), score, difference


span, score, delta = select_span(
    {0: 1.0, 5: 2.8, 6: 1.2, 7: 3.1},
    {0: 1.0, 5: 1.6, 6: 2.4, 7: 0.5},
)
assert span == (5, 6) and isclose(score, 5.2) and isclose(delta, -3.2)
missing_ru = ({0: 2.1, 7: 1.4}, {0: 2.0, 7: 1.9})
missing_en = ({0: 2.1, 4: 1.4}, {0: 2.0, 4: 1.9})
for missing, distractor in ((missing_ru, (7, 7)), (missing_en, (4, 4))):
    span, score, delta = select_span(*missing)
    assert span is None and isclose(score, 3.3) and isclose(delta, 0.8)
    assert select_span(*missing, threshold=1)[0] == distractor


def token_f1(answer, gold):
    if not answer or not gold:
        return float(answer == gold)
    hits = sum((Counter(answer) & Counter(gold)).values())
    return 2 * hits / (len(answer) + len(gold))


assert isclose(token_f1(["two"], ["two", "requests"]), 2 / 3)
assert token_f1(["two", "requests"], ["two", "requests"]) == 1
assert token_f1([], []) == 1
print("top B; span 5–6; null margin 0.8; partial F1 0.667")
~~~

</details>

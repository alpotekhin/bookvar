# Выбор токенов и генерация

После прямого прохода языковая модель выдаёт распределение вероятностей, но для
продолжения текста нужен один конкретный токен. Правило выбора называется
стратегией декодирования. Оно не меняет знания модели: из одного и того же
распределения можно детерминированно взять максимум, случайно выбрать один из
правдоподобных вариантов или сохранить несколько конкурирующих продолжений.

Стратегия должна соответствовать задаче. В переводе полезно искать
последовательность с высокой общей вероятностью; в творческом тексте такой поиск
часто приводит к шаблонным фразам. В программировании можно позволить несколько
случайных попыток, если затем ответы проверяются тестами. Поэтому параметры
генерации нельзя обсуждать вне процедуры оценки результата.

## Жадный выбор

На каждом шаге выбирается token с максимальной вероятностью:

$$
x_t=\arg\max_x P(x\mid x_{<t}).
$$

Метод детерминирован и удобен для проверки, но локально лучший токен не обязан
вести к лучшей полной последовательности. В открытой генерации жадный выбор часто повторяется и
делает текст однообразным.

## Температура

Перед softmax logits делятся на $T$:

$$
P_i=\operatorname{softmax}(z_i/T).
$$

- $T<1$ делает распределение резче;
- $T>1$ выравнивает варианты;
- при $T\to0$ выбор приближается к greedy.

Температура не добавляет знания и не «делает модель умнее». Она меняет
случайность выбора из уже рассчитанного распределения. При $T=0$ формулу с
делением использовать нельзя; на практике это обозначение жадного выбора.

## Top-k

Оставляются только $k$ наиболее вероятных токенов, остальные получают нулевую
вероятность, а оставшееся распределение нормируется заново. Фиксированное $k$
не учитывает форму распределения: иногда два первых варианта несут почти всю
вероятность, а иногда она распределена между десятками продолжений. Поэтому
одинаковое $k$ может быть слишком свободным на уверенном шаге и слишком жёстким
на неоднозначном.

## Top-p

Ядерная выборка (nucleus sampling) сортирует токены по убыванию вероятности и
оставляет минимальный префикс списка, чья сумма не меньше $p$. Если модель
уверена, ядро может состоять из одного-двух токенов; при плоском распределении
оно расширяется. После отсечения вероятности снова нормируются.

Обычно температуру применяют к ненормированным оценкам, затем фильтруют top-k
или top-p и только после этого выполняют случайный выбор. Порядок важен:
температура меняет вероятности и тем самым состав ядра top-p.

## Лучевой поиск

Лучевой поиск хранит несколько лучших незавершённых последовательностей. Он
полезен, когда:

- результат должен быть близок к одному каноническому ответу;
- важна вероятность полной последовательности;
- задача похожа на перевод или распознавание речи.

Для открытого диалога лучевой поиск часто предпочитает безопасные, повторяющиеся
фразы. Также нужна поправка на длину: произведение вероятностей систематически
уменьшается с каждым новым токеном и без коррекции предпочитает короткие ответы.

## Что требуется для воспроизводимости

Случайный выбор использует псевдослучайный генератор. Для воспроизводимости нужны:

- фиксированное начальное состояние генератора;
- точная версия модели;
- одинаковые токенизатор и шаблон диалога;
- одинаковые вычислительные ядра и точность;
- одинаковые параметры декодирования.

На GPU полная битовая воспроизводимость не всегда гарантируется.

## Несколько траекторий

Для math/code/reasoning часто полезно сгенерировать несколько candidates:

1. независимо сгенерировать несколько решений;
2. проверить их тестами, верификатором или моделью награды;
3. выбрать лучшее либо majority answer.

Self-consistency улучшает шанс получить правильную траекторию, но почти линейно
увеличивает вычисления во время инференса.

## Когда использовать что

| Задача | Разумная отправная точка |
|---|---|
| классификация через генерацию | greedy / низкая temperature |
| код с тестами | несколько samples + tests |
| творческий текст | temperature + top-p |
| перевод | beam search |
| строгий JSON | constrained decoding |
| исследование вероятностей | без sampling, смотреть logits |

## Минимальный sampling loop

```python
for _ in range(max_new_tokens):
    logits = model(tokens)[:, -1]
    logits = logits / temperature
    logits = top_p_filter(logits, top_p)
    probs = logits.softmax(dim=-1)
    next_token = torch.multinomial(probs, 1)
    tokens = torch.cat([tokens, next_token], dim=1)
```

Промышленная генерация добавляет KV-кэш, динамическое объединение запросов в
батчи, стоп-последовательности, штрафы за повторения и ограничения грамматикой.

# Post-training и Alignment

Базовая языковая модель учится продолжать документы. На вопрос пользователя
она может ответить, но может и продолжить список вопросов или написать
реплику за другого участника разговора. При post-training модель дообучают
отвечать в заданном формате и использовать обратную связь о качестве ответа.
Для этого нужны демонстрации, сравнительные оценки либо задачи с проверяемым
результатом. От вида данных зависит, какую ошибку можно исправить обучением.

## Что меняется между prompting, SFT, preference learning и RLVR

<!-- source_unit_id: meeting-02-slides-posttraining-and-prompting -->

Предположим, базовая модель уже умеет породить несколько правдоподобных ответов
на один запрос. Четыре режима используют эту способность по-разному.

| метод | данные и способ их использования |
|---|---|
| Prompting | Инструкция и примеры добавляются в контекст. Во время генерации параметры не обновляются. |
| SFT | На образцовых ответах минимизируют кросс-энтропию: модель учится предсказывать каждый следующий токен демонстрации. |
| Обучение по предпочтениям | Для одного запроса сравнивают ответы. DPO использует готовые пары; в RLHF модель награды оценивает новые ответы, которыми обучают модель-генератор, например с помощью PPO. |
| RLVR | Текущая модель генерирует попытки, а проверяющая программа оценивает результат: ответ задачи, выполнение тестов или соблюдение проверяемых условий. |

Например, демонстрация SFT может научить отвечать на вопрос о TCP в пределах
90 слов. Пара предпочтений показывает, какой из двух допустимых ответов
понятнее новичку. Тест проверяет, запускается ли сгенерированная программа;
он не устанавливает, хорошо ли она объяснена. Если обучать по числу прошедших
тестов, качество объяснения само по себе не входит в награду.

Эти режимы не образуют обязательную последовательность. Prompting применяют
и к дообученным моделям, а RLVR можно начать без предварительного DPO.

Сопоставление prompting и дообучения есть на слайдах 24–26 лекции Jason Weston
[Learning to Self-Improve & Reason with LLMs](https://rdi.berkeley.edu/adv-llm-agents/slides/Jason-Weston-Reasoning-Alignment-Berkeley-Talk.pdf#page=24)
из курса
[Berkeley Advanced LLM Agents, Spring 2025](https://rdi.berkeley.edu/adv-llm-agents/sp25).

## Пример полного процесса: Tülu 3

<!-- source_unit_id: meeting-04-slides-tulu-recipe -->
<!-- source_unit_id: meeting-04-reading-01-catalogue-record -->

[Tülu 3](https://arxiv.org/html/2411.15124v5#S2.SS3) — опубликованный пример
последовательности SFT, DPO и RLVR на базе Llama 3.1. Авторы выпустили данные,
код, промежуточные модели и наборы оценки. Это позволяет сравнить результат
каждой стадии с предыдущей, а не только базовую модель с готовым помощником.

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/sft-2026-10-23/tulu3-overview.png]]

*Полный процесс Tülu 3: подготовка запросов, SFT, DPO и RLVR.
Нижняя часть отделяет оценки, по которым подбирали обучение, от задач,
не использованных при разработке. Nathan Lambert et al.,
[Tülu 3, Figure 1, v5](https://arxiv.org/html/2411.15124v5#S0.F1),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Оригинальный PNG сохранён без перерисовки, перевода и обрезки.*

На первом шаге собирают запросы под выбранные навыки: обычный диалог,
математику, программирование, знание фактов и безопасное поведение.
Для SFT к запросам добавляют образцовые ответы. Для DPO получают пары
ответов с предпочтениями; в этой работе используют вариант DPO с
нормированием логарифмической вероятности по длине ответа. Наконец,
RLVR обучает модель на новых попытках решить задачи с проверяемым результатом.
Каждый переход сравнивают с предыдущей моделью по одной системе оценивания.

Стрелки от development evals означают, что результаты оценки влияют
на выбор данных и настроек. Поэтому эти задачи уже участвуют в разработке,
хотя градиент по ним не вычисляют. Unseen evals нужны для отдельной проверки
того, переносится ли улучшение на задачи, по которым процесс не подбирали.
Повторно настраивать смесь по unseen-результатам и продолжать называть их
независимой проверкой нельзя.

Этот же процесс разбирает Hannaneh Hajishirzi на
[слайдах 29, 60 и 90](https://rdi.berkeley.edu/adv-llm-agents/slides/OLMo-Tulu-Reasoning-Hanna.pdf#page=29).
Состав смеси и результаты относятся к конкретному эксперименту Tülu 3.

## Минимальная воспроизводимая последовательность

<!-- source_unit_id: meeting-04-slides-minimal-posttraining-recipe -->

Для воспроизводимого эксперимента сохраняют исходную модель, данные,
настройки обучения и правила оценки.

1. Зафиксировать целевые способности и отложенные наборы оценки до сбора
   обучающих примеров.
2. Собрать запросы из предполагаемого пользовательского распределения;
   записать происхождение, лицензию, способ дедупликации и удаления пересечений
   с оценочными задачами.
3. Обучить SFT-модель и проверить регрессии по отдельным способностям.
4. Для обучения по предпочтениям записать, кто породил каждый ответ,
   кто сравнил пару и насколько генератор отличается от обучаемой модели.
5. При PPO проверить модель награды и оценку ценности. При DPO проверить
   опорную модель, шаблон диалога и вычисление вероятностей ответов.
6. Для RLVR отделить извлечение ответа от проверки его правильности,
   зафиксировать версию проверяющей программы и исследовать ложные принятия
   до первого обновления модели.
7. Повторить исходную оценку с теми же запросами, настройками генерации
   и правилами подсчёта. Обучающая награда не заменяет независимую оценку.

Короткая последовательность обучения приведена
[на слайдах 121–125](https://rdi.berkeley.edu/adv-llm-agents/slides/OLMo-Tulu-Reasoning-Hanna.pdf#page=121).

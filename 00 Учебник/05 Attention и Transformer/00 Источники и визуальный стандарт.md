# Источники и визуальный стандарт

Эта страница — редакционный паспорт трёх глав модуля. Учебник задуман не как
полностью авторский пересказ, а как **редактируемая антология лучших объяснений**:
мы собираем сильные рисунки, формулировки, примеры, код и первичные источники,
а собственным текстом связываем их в последовательный маршрут.

## Главный редакционный принцип

Порядок выбора материала:

1. найти лучшее существующее объяснение;
2. сохранить его сильную часть с автором и прямой ссылкой;
3. добавить пояснение, зачем этот фрагмент находится именно здесь;
4. сопоставить его с paper и кодом;
5. писать собственный заменитель только тогда, когда готового материала нет,
   он устарел или несколько источников противоречат друг другу.

Не нужно пересказывать удачный абзац «своими словами» только ради оригинальности.
Не нужно перерисовывать сильную схему более слабой схемой только ради единого
стиля. Ценность учебника — в отборе, последовательности, сопоставлении и
перекрёстных ссылках.

## Иерархия источников

### Первичные источники

| Тема | Источник | Что подтверждает |
|---|---|---|
| Seq2Seq | [Sutskever et al., 2014](https://arxiv.org/abs/1409.3215) | encoder-decoder с фиксированным представлением |
| Additive attention | [Bahdanau et al., 2014](https://arxiv.org/abs/1409.0473) | annotations, soft alignment, отдельный context на каждом шаге |
| Luong attention | [Luong et al., 2015](https://arxiv.org/abs/1508.04025) | dot/general/concat, global и local attention |
| Transformer | [Vaswani et al., 2017](https://arxiv.org/abs/1706.03762) | scaled dot-product, multi-head, encoder-decoder |
| GPT | [Radford et al., 2018](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf) | causal decoder-like stack и generative pre-training |
| BERT | [Devlin et al., 2018](https://arxiv.org/abs/1810.04805) | bidirectional encoder и masked language modeling |
| LLaMA | [Touvron et al., 2023](https://arxiv.org/abs/2302.13971) | RMSNorm, SwiGLU, RoPE в decoder-only LLM |

## Педагогический контракт главы

Каждая полноценная глава должна содержать:

1. конкретную задачу, которую механизм решает;
2. наивное решение и место, где оно ломается;
3. постепенный вывод механизма;
4. одну ориентирующую и несколько пошаговых иллюстраций;
5. формулы после введения всех сущностей;
6. tensor shapes и хотя бы один вычислимый пример;
7. минимальный код и связь к production API;
8. границы применимости и типичные ошибки;
9. первичные и объясняющие источники отдельно.

## Quality gate: когда страница действительно является главой

Страница не считается готовой только потому, что у неё валидный Markdown и нет
битых ссылок. Перед статусом `canonical` она должна пройти содержательную
проверку относительно глав
[[02 Areas/ML & DL/00 Учебник/05 Attention и Transformer/01 От Seq2Seq к Transformer|Seq2Seq → Attention]]
и
[[02 Areas/ML & DL/00 Учебник/05 Attention и Transformer/02 Self-Attention — Q, K, V|Self-Attention]].

Обязательный минимум:

| Критерий | Требование |
|---|---|
| Повествование | одна проблема развивается от примера к механизму, а не список терминов |
| Объём | обычно 200–400 строк; отклонение объясняется темой, а не экономией времени |
| Иллюстрации | 3–8 содержательных figures; каждая подписана и разобрана в тексте |
| Источники | primary paper/code и 2–5 сильных педагогических источников |
| Пример | один сквозной пример, который возвращается в разных разделах |
| Математика | определения до формул, все symbols и shapes объяснены |
| Код | минимальная реализация либо точная ссылка на reference code с разбором |
| Сравнение | варианты механизма и причины выбора, а не только названия |
| Ошибки | отдельный раздел с распространёнными неверными объяснениями |
| Практика | наблюдаемый эксперимент или маршрут воспроизведения |
| Связность | понятный переход из предыдущей главы и в следующую |

Автоматические проверки frontmatter, ссылок и fences выполняются только после
этого gate и не заменяют его.

## Визуальный язык

| Сущность | Цвет | Дополнительный маркер |
|---|---|---|
| token / embedding | синий | прямоугольник |
| query | фиолетовый | `Q` |
| key | зелёный | `K` |
| value | оранжевый | `V` |
| score / weight | жёлтый | число или толщина связи |
| mask | красный | штриховка / `−∞` |
| residual stream | тёмно-синий | толстая горизонтальная линия |
| FFN | бирюзовый | двухступенчатый блок |

Цвет никогда не является единственным носителем смысла: у каждого элемента есть
подпись, форма или численное значение.

## Политика изображений

- Сначала проверяется `raw`: в базе уже есть большой локальный архив paper
  figures, course slides, GIF и иллюстраций сильных объясняющих статей.
- Для личного Obsidian-конспекта можно хранить и показывать полезную внешнюю
  иллюстрацию с явной подписью автора и ссылкой на исходную страницу.
- Чужая картинка не объявляется нашей и не лишается подписи.
- Собственный SVG нужен для нового сравнения, объединения нескольких источников
  или для пробела, который готовые материалы не закрывают.
- Фигуры paper используются рядом с объяснением того, что именно на них смотреть.
- Для каждого изображения фиксируются автор, URL и, когда она известна, лицензия.

## Политика текста

- Сильные короткие определения и формулировки сохраняются как цитаты с автором.
- Большие тексты не копируются целиком: глава даёт редакторскую выжимку и ведёт
  к оригиналу.
- Если исходное объяснение уже ясное, наш текст не должен быть его более длинным
  и менее живым машинным парафразом.
- Авторский вклад учебника: маршрут чтения, переходы, сравнения, проверка
  фактов, единый пример, русские пояснения и ссылки между источниками.

## Visual quality gate

Наличие embed не означает, что иллюстрация принята.

| Проверка | Требование |
|---|---|
| Формат | настоящий PNG/JPEG/SVG, а не HTML-страница с неверным расширением |
| Разрешение | text-heavy raster обычно не уже 1200 px; меньший оригинал допустим только при крупной читаемой графике |
| Crop | показывается сама figure и caption; полная страница paper не вставляется |
| Читаемость | labels различимы в стандартной ширине заметки Obsidian без zoom |
| Семантика | figure объясняет конкретный абзац, а caption говорит, что на ней увидеть |
| Источник | paper/site и номер figure указаны; собственная схема явно помечена |
| Дубли | одна картинка не выдаётся за две разные визуализации |
| Доступность | цвет не является единственным носителем смысла |

Приоритет: исходный SVG/PDF figure → crop PDF не ниже 200 DPI → качественная
авторская схема → собственный SVG → raster из поисковой выдачи как последний
вариант.

`raw/` остаётся неизменяемым слоем источников. Исправленные crops и собственные
схемы хранятся в `Assets/Figures/`, чтобы не подменять оригинал.

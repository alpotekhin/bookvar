# Perplexity (PPL)

## Определение

**Perplexity** (PPL) — основная метрика качества языковых моделей, измеряющая, насколько хорошо модель предсказывает текст. Формально perplexity определяется как экспонента средней кросс-энтропии:

$$\text{PPL}(W) = \exp\left(-\frac{1}{N}\sum_{i=1}^{N} \log p_\theta(x_i \mid x_{<i})\right)$$

где $x_1, x_2, \ldots, x_N$ — токены тестового текста, $p_\theta(x_i \mid x_{<i})$ — вероятность, которую модель присваивает токену $x_i$ при условии всех предыдущих токенов.

Эквивалентная запись через кросс-энтропию $H(p, q)$:

$$\text{PPL} = 2^{H(p, q)}$$

где $H(p, q) = -\frac{1}{N}\sum_{i=1}^{N} \log_2 p_\theta(x_i \mid x_{<i})$ — кросс-энтропия между распределением данных и моделью.

## Интуиция: эффективный размер словаря

Perplexity можно интерпретировать как **эффективный размер словаря**, из которого модель «выбирает» следующий токен. Если PPL = 30, то в среднем модель «не уверена» между ~30 кандидатами на каждой позиции. Если PPL = 1, модель полностью уверена в каждом следующем токене.

Пример: для равномерного распределения над словарём размера $V$:

$$p(x_i) = \frac{1}{V} \implies \text{PPL} = V$$

Модель, которая ничего не знает о языке и присваивает равную вероятность каждому из 50 000 токенов, будет иметь PPL = 50 000. Хорошая языковая модель сужает это число до десятков.

## Связь с кросс-энтропией (loss)

В PyTorch стандартный `CrossEntropyLoss` для языковой модели возвращает среднюю кросс-энтропию по токенам (с натуральным логарифмом). Perplexity — это просто:

$$\text{PPL} = \exp(\mathcal{L}_{CE})$$

где $\mathcal{L}_{CE}$ — значение cross-entropy loss на тестовом наборе. Если модель показывает loss = 3.4, то PPL = $e^{3.4} \approx 30$.

Это означает, что **минимизация cross-entropy loss при обучении напрямую минимизирует perplexity**. Каждое улучшение loss на 0.1 соответствует мультипликативному снижению PPL.

## Типичные значения

| Модель | Датасет | PPL |
|--------|---------|-----|
| GPT-2 (1.5B) | WikiText-103 | ~30 |
| GPT-3 (175B) | Penn Treebank | ~20 |
| LLaMA-2 (70B) | WikiText-2 | ~3.3 |
| Случайная модель (50k vocab) | любой | 50 000 |
| Униграмная модель | WikiText | ~1000 |

**Правило: чем ниже PPL, тем лучше.** Снижение PPL означает, что модель лучше предсказывает текст, т.е. лучше «понимает» статистику языка.

## Вычисление для моделей с фиксированным контекстом

Для моделей с ограниченным контекстом (например, GPT-2 с окном 1024 токена) вычисление PPL на длинных текстах требует sliding window подхода. Hugging Face рекомендует **strided evaluation**:

1. Разбить текст на перекрывающиеся окна с шагом (stride) меньше длины контекста
2. Для каждого окна вычислить log-likelihood только для токенов за пределами перекрытия
3. Усреднить по всем токенам

Это даёт более точную оценку, чем наивное разбиение без перекрытия, где модель теряет контекст на границах окон.

## Ограничения PPL

### PPL не измеряет полезность

Perplexity оценивает только token-level prediction — способность модели предсказать следующий токен. Она **не измеряет:**

- **Фактическую корректность** — модель может уверенно (с низким PPL) генерировать ложные утверждения
- **Полезность и helpfulness** — модель может хорошо предсказывать токены, но плохо следовать инструкциям
- **Reasoning ability** — PPL не коррелирует с performance на задачах логического рассуждения

Для оценки этих качеств используются бенчмарки: [[02 Areas/ML & DL/Concepts/Evaluation/MMLU|MMLU]] для знаний, [[02 Areas/ML & DL/Concepts/Evaluation/HumanEval|HumanEval]] для кода, а также human evaluation.

### PPL не сравнима между токенизаторами

**Критически важное ограничение:** perplexity нельзя сравнивать между моделями с разными токенизаторами. Модель с BPE-словарём в 32K токенов и модель с 100K токенов решают разные задачи — у второй больший «словарь», но каждый токен несёт больше информации.

Для корректного сравнения используют **bits-per-byte** (BPB) или **bits-per-character** (BPC) — нормализацию по количеству байт/символов, а не токенов:

$$\text{BPB} = \frac{\mathcal{L}_{CE}}{\text{bytes per token}}$$

### PPL зависит от домена

Модель может показывать PPL = 5 на Wikipedia и PPL = 50 на медицинских текстах. Это не значит, что модель «плохая» — просто она не видела медицинских текстов при обучении. PPL всегда нужно интерпретировать **в контексте конкретного датасета**.

## PPL в эпоху LLM

В современных LLM perplexity остаётся важной метрикой при pre-training (как tracking metric), но для оценки instruction-tuned моделей практически не используется. Основные причины:

1. Chat-модели оцениваются по бенчмаркам (MMLU, HumanEval, MATH) и human preference
2. PPL не отражает improvement от RLHF/DPO — alignment может даже увеличить PPL при улучшении полезности
3. Leaderboards (LMSYS Chatbot Arena) опираются на head-to-head comparison, а не PPL

Тем не менее, PPL остаётся незаменимой для:
- Мониторинга pre-training (loss curves)
- Сравнения архитектур при прочих равных
- Детектирования data contamination (аномально низкий PPL на тестовом наборе)

# T5 — Text-to-Text Transfer Transformer

## Зачем это нужно: хаос transfer learning в NLP

К 2019 году transfer learning для NLP превратился в зоопарк подходов, и было неясно, **что работает и почему**:

- **Pre-training objectives**: autoregressive LM (GPT), masked LM (BERT), permutation LM (XLNet), replaced token detection (ELECTRA), denoising autoencoder...
- **Архитектуры**: encoder-only (BERT), decoder-only (GPT), encoder-decoder (оригинальный Transformer)
- **Данные**: BooksCorpus, Wikipedia, WebText, CommonCrawl — разные корпуса, разное качество
- **Fine-tuning методы**: full fine-tuning, adapter layers, multi-task learning, feature extraction

Каждая новая статья меняла несколько переменных одновременно, делая невозможным понять, какой именно компонент принёс улучшение.

**Raffel et al. (2020)** провели **систематическое контролируемое исследование** — варьировали одну переменную за раз при фиксированных остальных. Одновременно предложили **унифицирующий фреймворк**, который свёл все NLP задачи к единому формату.

## Text-to-Text: одна модель для всех задач

Центральная идея T5: **каждая NLP задача — это преобразование текста в текст**. Входной текст содержит task prefix, указывающий что делать:

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/t5/text-to-text-framework.png]]
*T5 text-to-text framework: все задачи (перевод, классификация, суммаризация, QA) приводятся к единому формату «текст на вход → текст на выход» с task prefix (источник: Cameron Wolfe / Raffel et al., 2020)*

**Одна модель**, **один loss** (token-level cross-entropy), **одна процедура fine-tuning** — для абсолютно всех задач.

**Почему это сработало?** Унификация устраняет необходимость в task-specific архитектурах (classification head для BERT, span extraction head, sequence labeling head). Модель учится общему навыку «чтения инструкций и генерации ответа» — это предвосхитило instruction tuning (FLAN, 2022) и ChatGPT paradigm.

Даже regression задачи (STS-B, где нужно предсказать число от 0 до 5) решаются генерацией текста — модель генерирует строку «3.8», которая округляется до ближайшего 0.2.

## Архитектура

T5 использует **encoder-decoder Transformer**, близкий к оригинальному Vaswani et al. (2017):

![[02 Areas/ML & DL/00 Учебник/Assets/Figures/curated/t5/encoder-decoder-architecture.png]]
*T5 encoder-decoder architecture: encoder обрабатывает input bidirectionally, decoder генерирует output autoregressively с cross-attention к encoder representations (источник: Cameron Wolfe)*

### Три типа attention

1. **Encoder self-attention** — bidirectional, каждый токен видит все остальные
2. **Decoder self-attention** — causal mask, предотвращает attention к будущим токенам
3. **Cross-attention** — Query из декодера, Key и Value из энкодера

### Отличия от оригинального Transformer

| Компонент | Original Transformer | T5 |
|-----------|---------------------|-----|
| Positional encoding | Sinusoidal absolute | **Relative positional biases** |
| Normalization | Post-LN | **Pre-LN (RMSNorm без additive bias)** |
| Embedding sharing | Shared input/output | Shared encoder-decoder embeddings |

**Relative positional biases** (не абсолютные PE): добавляются к attention logits (а не к embeddings). Каждая attention head имеет свой набор bias'ов в зависимости от расстояния между позициями. Преимущество: лучше обобщается на длины, не виденные при обучении.

### Размеры моделей

| Конфигурация | Параметры | Encoder layers | Decoder layers |
|-------------|----------|---------------|---------------|
| Small | 60M | 6 | 6 |
| Base | 220M | 12 | 12 |
| Large | 770M | 24 | 24 |
| XL (3B) | 3B | 24 | 24 |
| **XXL (11B)** | **11B** | **24** | **24** |

$d_{\text{model}}$ растёт от 512 (Small) до 1024 (XXL), $d_{ff}$ от 2048 до 65536, число heads от 8 до 128.

## Pre-training: C4 + Span Corruption

### Датасет C4 (Colossal Clean Crawled Corpus)

**750GB** чистого английского текста из Common Crawl. Процесс фильтрации:

1. Оставляют только предложения с **конечной пунктуацией** (точка, восклицательный, вопросительный знак)
2. Убирают страницы с менее чем **3 предложениями**
3. Убирают страницы с **кодом** (упоминания «javascript», «{», «}»)
4. Убирают страницы с **«lorem ipsum»**
5. Убирают **нецензурные** страницы (список «dirty words»)
6. **Дедупликация** на уровне 3-sentence spans

C4 стал **стандартным открытым датасетом** для pre-training — его использовали в десятках последующих моделей, включая [[02 Areas/ML & DL/Concepts/Architectures/LLaMA|LLaMA]].

### Span Corruption — pre-training objective

Из систематического сравнения 4 вариантов (Section 3.3) T5 выбирает **Span Corruption** как лучший:

```
Original text:
  "Thank you for inviting me to your party last week"

Span Corruption (15% tokens, средняя длина span = 3):
  Input:   "Thank you <extra_id_0> me to your party <extra_id_1> week"
  Target:  "<extra_id_0> for inviting <extra_id_1> last <extra_id_2>"
```

Механизм:
1. Случайно выбираются **spans** (непрерывные группы) токенов (15% всего текста, средняя длина span = 3)
2. Каждый span заменяется **уникальным sentinel токеном** (`<extra_id_0>`, `<extra_id_1>`, ...)
3. Target: только замаскированные spans с их sentinel ID + финальный sentinel

**Почему span corruption лучше token-level MLM (BERT)?**
- **Короче target**: вместо полной длины последовательности — только маскированные spans. При 15% masking rate и средней длине 3, target ≈ 15% длины входа. Это **экономит compute**.
- **Более сложная задача**: модель предсказывает непрерывные фрагменты, а не изолированные токены — лучше учит языковую когерентность.

### Сравнение pre-training objectives (Section 3.3)

| Objective | GLUE avg | SQuAD F1 | Примечание |
|-----------|---------|---------|-----------|
| **Span corruption** (T5 default) | **83.5** | **80.9** | Лучший по совокупности |
| BERT-style token MLM | 82.7 | 79.9 | Хуже и дороже (длинный target) |
| Prefix LM | 82.0 | 78.0 | Как GPT, но видит prefix bidirectionally |
| Deshuffling | 79.1 | 73.4 | Восстановление порядка — слишком просто |

## Fine-tuning

T5 fine-tune'ится на каждую задачу **отдельно**:

- Task prefix добавляется ко входу: `"translate English to German: ..."`, `"summarize: ..."`, `"cola sentence: ..."`
- Loss: token-level cross-entropy на target последовательность
- Одинаковая процедура для classification, regression, generation
- **SQuAD**: `"question: {Q} context: {C}"` → модель генерирует текст ответа (не start/end span)

**Multi-task fine-tuning** (ablation, Section 3.5): конкатенация всех задач в одну training mixture. Результат: multi-task лучше, чем single-task fine-tuning на отдельных задачах, если использовать proportional mixing (не equal mixing).

## Ключевые результаты (T5-11B)

### GLUE и SuperGLUE

| Бенчмарк | T5-11B | Prev. SOTA | Human baseline |
|----------|--------|-----------|---------------|
| **GLUE** | **~90.3** | ~88 | ~87 |
| **SuperGLUE** | **~89.3** | ~87 | ~89.8 |

T5-11B на GLUE **превышает** human baseline (~87) — хотя позже DeBERTa XXL и другие модели тоже достигли этого уровня.

### Другие бенчмарки

| Задача | T5-11B | Тип задачи |
|--------|--------|-----------|
| SQuAD 2.0 F1 | ~91.3 | QA (span extraction) |
| CNN/DailyMail ROUGE-2 | ~21.6 | Summarization |

## Ablation findings: что работает, а что нет

T5 paper — один из первых масштабных controlled ablation studies по transfer learning. Ключевые выводы:

### Архитектура (Section 3.2)

| Вариант | GLUE avg | SQuAD F1 |
|---------|---------|---------|
| **Encoder-Decoder** (T5 default) | **83.5** | **80.9** |
| Decoder-only (GPT-style) | 82.2 | 78.3 |
| Prefix LM (decoder with bidirectional prefix) | 82.0 | 78.0 |

**Encoder-decoder лучше decoder-only** для seq2seq задач при одинаковом числе параметров. Причина: encoder обрабатывает input bidirectionally (важно для понимания), decoder генерирует output autoregressively (важно для генерации).

### Данные (Section 3.4)

| Данные | GLUE avg |
|--------|---------|
| **C4** (filtered CommonCrawl) | **83.5** |
| Unfiltered CommonCrawl | 82.0 |
| WebText-like (Reddit links) | 83.1 |
| Wikipedia + TBC | 82.4 |

Фильтрация CommonCrawl **критически важна** — нефильтрованный CC на 1.5% хуже.

### Масштаб (Section 3.6)

| Размер | GLUE avg | SQuAD F1 |
|--------|---------|---------|
| Small (60M) | 77.4 | 69.8 |
| Base (220M) | 82.5 | 78.4 |
| Large (770M) | 85.0 | 82.5 |
| XL (3B) | 87.7 | 85.3 |
| **XXL (11B)** | **~90.3** | **~91.3** |

Строгое, монотонное улучшение с масштабом — без признаков plateau.

### Multi-task vs Single-task (Section 3.5)

- Multi-task pre-training **помогает**, но хуже, чем unsupervised pre-training + single-task fine-tuning
- Multi-task pre-training + fine-tuning (best of both) ≈ unsupervised pre-training + fine-tuning
- Вывод: **multi-task learning не заменяет fine-tuning** (но дополняет)

## Почему T5 важен

### 1. Text-to-text унификация → instruction tuning

T5 показал, что одна модель может решать **все** NLP задачи через текстовый интерфейс. Это прямой предшественник:
- **FLAN-T5** (Chung et al., 2022) — instruction-tuned T5 на 1800+ задачах → значительное улучшение zero-shot performance
- **InstructGPT/ChatGPT** — та же идея «следуй инструкции», но для decoder-only
- **Современные API** — единый текстовый интерфейс для всех задач

### 2. C4 как стандартный датасет

C4 стал **benchmark dataset** для pre-training. Его использовали:
- [[02 Areas/ML & DL/Concepts/Architectures/LLaMA|LLaMA]] (15% от training mix)
- UL2, PaLM, и десятки других моделей
- Как baseline для сравнения data filtering методов

### 3. Span corruption → лучший pre-training objective

BERT использует token-level MLM. T5 показал, что **span-level corruption** эффективнее — этот подход унаследовали UL2, mT5, и другие.

### 4. Controlled ablation methodology

До T5 сравнение моделей было apple-to-oranges: разные данные, разные objectives, разные размеры. T5 установил **стандарт** контролируемого сравнения, варьируя одну переменную за раз.

### 5. Encoder-decoder ренессанс

В эпоху GPT-доминирования T5 показал, что encoder-decoder **лучше** для задач с отдельными input и output (перевод, суммаризация, QA). Это мотивировало BART, mBART, UL2.

## Encoder-Decoder vs Decoder-only: когда что использовать

| Аспект | Encoder-Decoder (T5) | Decoder-only (GPT-3) |
|--------|---------------------|---------------------|
| Input processing | Bidirectional (encoder) | Causal (left-to-right) |
| Лучше для | Задачи с чётким input/output | Open-ended generation |
| Эффективность input | Encoder обрабатывает input один раз | Input re-processed при каждом output token |
| Масштабирование | T5-11B | GPT-3-175B → decoder-only побеждает при экстремальном масштабе |
| Примеры | T5, BART, mT5, UL2 | GPT-3/4, LLaMA, Mistral |

На практике к 2023+ decoder-only **доминирует** при масштабе >10B параметров — проще масштабировать, проще обучать, хватает одного формата для всех задач.

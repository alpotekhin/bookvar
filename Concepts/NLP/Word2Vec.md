# Word2Vec — векторные представления слов

## Зачем это нужно: дистрибутивная гипотеза

До Word2Vec слова в NLP представлялись как one-hot вектора: каждое слово — единица в одной позиции, нули в остальных. Два фундаментальных недостатка: (1) размерность равна размеру словаря (~100K+), (2) **все слова равноудалены** — cos("кот", "собака") = cos("кот", "трактор") = 0.

**Дистрибутивная гипотеза** (Firth, 1957): *"You shall know a word by the company it keeps."* — значение слова определяется его контекстом. Слова, встречающиеся в похожих контекстах, имеют похожие значения.

Word2Vec (Mikolov et al., 2013) реализует эту гипотезу через обучение **dense low-dimensional vectors** (embeddings), где близкие по смыслу слова оказываются близко в векторном пространстве.

## Две архитектуры

### CBOW (Continuous Bag of Words)

**Задача:** предсказать центральное слово по контексту (окружающим словам).

Для окна контекста размера $m$ и центрального слова $w_t$:

$$P(w_t | w_{t-m}, \ldots, w_{t-1}, w_{t+1}, \ldots, w_{t+m})$$

**Архитектура:**
1. Каждое контекстное слово представляется вектором из матрицы $W \in \mathbb{R}^{|V| \times d}$
2. Контекстные вектора **усредняются**: $h = \frac{1}{2m}\sum_{j \neq 0} v_{w_{t+j}}$
3. Результат подаётся в выходной слой (softmax по словарю)

CBOW быстрее обучается, лучше для частых слов.

### Skip-gram

**Задача:** обратная — предсказать контекстные слова по центральному.

Для каждого центрального слова $w_t$ максимизируется:

$$J = \frac{1}{T}\sum_{t=1}^{T}\sum_{\substack{-m \leq j \leq m \\ j \neq 0}} \log P(w_{t+j} | w_t)$$

Вероятность контекстного слова:

$$P(o | c) = \frac{\exp(u_o^T v_c)}{\sum_{w=1}^{|V|} \exp(u_w^T v_c)}$$

где $v_c$ — вектор центрального слова (input embedding), $u_o$ — вектор контекстного слова (output embedding).

Skip-gram лучше для редких слов и малых корпусов.

## Проблема softmax и Negative Sampling

**Проблема:** знаменатель softmax суммирует по **всему словарю** $|V|$ (100K-1M слов). Для каждого training step нужно вычислить $|V|$ скалярных произведений — неприемлемо дорого.

### Negative Sampling (NEG)

Вместо полного softmax, задача переформулируется как **бинарная классификация**: отличить настоящие пары (слово, контекст) от случайных.

Для пары (center word $c$, context word $o$) objective:

$$J_{NEG} = \log \sigma(u_o^T v_c) + \sum_{k=1}^{K} \mathbb{E}_{w_k \sim P_n(w)} \left[\log \sigma(-u_{w_k}^T v_c)\right]$$

где:
- $\sigma$ — сигмоида
- $K$ — число негативных примеров (5-20 для малых датасетов, 2-5 для больших)
- $P_n(w) \propto f(w)^{3/4}$ — распределение для сэмплирования негативов

**Почему степень 3/4?** Чистая частотная выборка ($f(w)^1$) слишком перекошена к частым словам ("the", "a", "is"). Uniform ($f(w)^0$) даёт слишком много редких слов. Степень 3/4 — эмпирически найденный компромисс, который «поднимает» вероятность редких слов.

### Hierarchical Softmax (альтернатива)

Другой подход — организовать словарь в **бинарное дерево** (Huffman tree). Вместо $O(|V|)$ вычислений — $O(\log |V|)$ решений "налево/направо" по дереву. На практике negative sampling проще и обычно работает лучше.

## Свойство аналогий

Самое известное свойство Word2Vec — **линейная структура** семантических отношений:

$$v_{king} - v_{man} + v_{woman} \approx v_{queen}$$

Это работает потому, что разные отношения кодируются как **параллельные направления** в пространстве:

$$v_{king} - v_{queen} \approx v_{man} - v_{woman} \approx v_{uncle} - v_{aunt}$$

Аналогии работают для разных типов отношений:
- **Род:** мужчина-женщина
- **Страна-столица:** France - Paris, Japan - Tokyo
- **Морфология:** run - running, go - going
- **Грамматика:** big - bigger, good - better

**Ограничения аналогий:** работают не всегда (accuracy ~40-70% на Google Analogy dataset). Для абстрактных или многозначных отношений — плохо.

## Гиперпараметры обучения

| Параметр | Типичные значения | Влияние |
|----------|------------------|---------|
| Размерность $d$ | 100-300 | Больше = больше capacity, но дольше обучение |
| Размер окна $m$ | 5-10 | Маленькое = синтаксическое сходство, большое = семантическое |
| Min count | 5-10 | Фильтрация редких слов (нет данных для хорошего вектора) |
| Negative samples $K$ | 5-15 | Больше = стабильнее, но дороже |
| Subsampling threshold | $10^{-5}$ | Случайное удаление слишком частых слов из контекста |
| Эпохи | 5-15 | Для больших корпусов достаточно 5 |

**Subsampling:** сверхчастые слова ("the", "is", "a") появляются почти в каждом контексте, давая мало информации. Subsampling случайно удаляет слово $w$ из training с вероятностью:

$$P(discard) = 1 - \sqrt{\frac{t}{f(w)}}$$

где $t$ — threshold (~$10^{-5}$), $f(w)$ — частота слова. Это ускоряет обучение и улучшает качество для редких слов.

## Word2Vec vs GloVe

**GloVe** (Pennington et al., 2014) — альтернативный подход к word embeddings, основанный на **матрице ко-встречаемости** (co-occurrence matrix).

| Свойство | Word2Vec | GloVe |
|----------|----------|-------|
| Тип | Predictive (neural) | Count-based + regression |
| Данные | Сканирует корпус window-by-window | Предвычисляет глобальную матрицу |
| Objective | Predict context words | $\min \sum_{i,j} f(X_{ij})(w_i^T \tilde{w}_j + b_i + \tilde{b}_j - \log X_{ij})^2$ |
| Обучение | Online (SGD по парам) | Batch (по всей матрице) |
| Масштабируемость | Хорошая для больших корпусов | Нужна RAM для матрицы |
| Качество | Сопоставимо | Сопоставимо |

На практике качество Word2Vec и GloVe сопоставимо. GloVe имеет теоретическое преимущество — использует глобальную статистику, но Word2Vec проще в реализации и обучении.

## Ограничения Word2Vec

### Один вектор на слово

"Bank" (финансовый) и "bank" (берег реки) имеют **один общий вектор** — усреднение всех значений. Это фундаментальная проблема, решённая контекстуальными эмбеддингами:

- **ELMo** (2018): отдельные вектора для каждого вхождения через BiLSTM
- **[[02 Areas/ML & DL/Concepts/Architectures/BERT|BERT]]** (2018): полностью контекстуальные представления через Transformer

### Другие ограничения

- **Out-of-vocabulary (OOV):** нет вектора для слов, не встречавшихся при обучении. Частично решается FastText (subword embeddings — вектора для n-gram символов)
- **Нет морфологии:** "run", "running", "ran" — три разных вектора без явной связи (FastText решает)
- **Статичность:** вектора не меняются от контекста к контексту
- **Bias:** word embeddings наследуют bias из обучающих данных (gender bias, racial bias)

## FastText — решение проблемы морфологии

**FastText** (Bojanowski et al., 2017) — расширение Word2Vec от Facebook, представляющее слова как **сумму character n-gram** эмбеддингов. Слово "where" с n-gram размером 3-6 разбивается на: `<wh`, `whe`, `her`, `ere`, `re>`, `<whe`, `wher`, `here`, `ere>`, ... и само слово `<where>`.

Вектор слова:

$$v_{where} = \sum_{g \in G(where)} z_g$$

где $G(w)$ — множество n-gram для слова $w$, $z_g$ — обучаемые эмбеддинги n-gram.

**Преимущества:**
- OOV-слова получают вектор через сумму своих n-gram
- Морфологически близкие слова автоматически получают близкие вектора
- Лучше работает для морфологически богатых языков (русский, финский, турецкий)

## Историческое значение

Word2Vec (2013) стал **поворотным моментом** в NLP:
- Показал, что простые нейросети на больших данных дают мощные representations
- Концепция transfer learning в NLP: предобученные эмбеддинги улучшают downstream tasks
- Прямой предшественник ELMo, BERT и всей парадигмы "pretrain + fine-tune"
- До сих пор используется в production для задач, где контекстуальность не критична (рекомендации, поиск по ключевым словам, feature engineering)

# Quantization — Квантизация моделей

## Зачем это нужно

Современные LLM имеют миллиарды параметров, хранящихся в FP32 или FP16. Для inference модели в 70B параметров нужно ~140 GB GPU RAM (при FP16) — это 2x A100 80GB или 2x H100. Квантизация решает эту проблему, **снижая точность представления весов** (а иногда и активаций) с 16/32-bit до 8/4/2-bit, пропорционально уменьшая потребление памяти и ускоряя вычисления.

**Ключевой trade-off:** меньше бит на параметр = меньше памяти и быстрее inference, но потенциальная деградация качества.

## Иерархия числовых форматов

```
FP32  (32 бит)  — полная точность, training baseline
  ↓
BF16  (16 бит)  — brain floating point, стандарт training на GPU
FP16  (16 бит)  — half precision, стандарт inference
  ↓
INT8  (8 бит)   — целочисленная квантизация, минимальная потеря качества
  ↓
INT4  (4 бита)  — агрессивная квантизация, заметная но допустимая потеря
NF4   (4 бита)  — NormalFloat4 (QLoRA), оптимизирован под нормальное распределение
  ↓
INT2  (2 бита)  — экспериментальная, значительная потеря качества
```

**FP16 vs BF16:** BF16 имеет тот же range, что FP32 (8 бит экспоненты), но меньше precision (7 бит мантиссы vs 10 у FP16). Для training BF16 предпочтительнее — меньше overflow/underflow.

## Таблица: потребление памяти для 7B модели

| Формат | Бит/параметр | Размер модели | Примерный RAM при inference |
|--------|-------------|---------------|----------------------------|
| FP32   | 32          | ~28 GB        | ~32 GB                     |
| FP16/BF16 | 16      | ~14 GB        | ~18 GB                     |
| INT8   | 8           | ~7 GB         | ~10 GB                     |
| INT4   | 4           | ~3.5 GB       | ~6 GB                      |
| INT2   | 2           | ~1.75 GB      | ~4 GB                      |

*RAM при inference включает KV-cache, activation memory и системный overhead. Указаны оценки для batch_size=1, context ~2K tokens.*

## Post-Training Quantization (PTQ)

PTQ применяется **после** обучения модели. Модель обучается в FP16/BF16, затем веса конвертируются в более низкую точность. Это самый распространённый подход.

### Наивная квантизация (Round-to-Nearest)

Простейший вариант — линейное отображение диапазона весов в целочисленную сетку:

$$q = \text{round}\left(\frac{w - w_{min}}{w_{max} - w_{min}} \cdot (2^b - 1)\right)$$

где $b$ — количество бит. Деквантизация:

$$\hat{w} = q \cdot \frac{w_{max} - w_{min}}{2^b - 1} + w_{min}$$

**Проблема:** outlier-ы (выбросы) в весах растягивают диапазон, снижая точность для основной массы значений.

### GPTQ — одноразовая квантизация весов

**GPTQ** (Frantar et al., 2023) — метод one-shot weight quantization, основанный на Optimal Brain Quantization (OBQ):

1. Квантизация весов **послойно** (layer-by-layer)
2. Для каждого слоя: квантизовать один столбец весовой матрицы, **скомпенсировать ошибку** обновлением оставшихся столбцов
3. Используется Hessian (матрица вторых производных loss по весам) для определения оптимальной компенсации

Ключевая формула компенсации для столбца $j$:

$$\delta_F = -\frac{w_j - \text{quant}(w_j)}{[H_F^{-1}]_{jj}} \cdot H_F^{-1}_{:,j}$$

**Преимущества:** требует лишь небольшой калибровочный датасет (~128 примеров), работает за минуты.

### AWQ — Activation-Aware Weight Quantization

**AWQ** (Lin et al., 2023) исходит из наблюдения, что **не все веса одинаково важны** — 1% весов (salient weights) непропорционально влияют на качество. Эти важные веса определяются по **magnitude активаций**, а не самих весов.

Подход: перед квантизацией масштабировать salient weight channels, чтобы минимизировать ошибку квантизации для наиболее важных каналов. Масштабирование:

$$w' = w \cdot s, \quad x' = x / s$$

где $s$ — per-channel scale factor, определяемый по статистике активаций.

**AWQ vs GPTQ:** AWQ обычно чуть лучше по качеству при INT4 и быстрее при inference (hardware-friendly quantization groups).

## Quantization-Aware Training (QAT)

В отличие от PTQ, QAT включает квантизацию **в процесс обучения**: forward pass использует квантизованные веса, но градиенты считаются в полной точности (Straight-Through Estimator — STE):

$$\frac{\partial L}{\partial w} \approx \frac{\partial L}{\partial \hat{w}}$$

**Преимущества:** модель адаптируется к ошибке квантизации, что даёт лучшее качество при агрессивной квантизации (INT4, INT2).

**Недостатки:** требует полного цикла обучения/дообучения — дорого для больших моделей. На практике QAT для LLM используется редко; вместо этого применяют [[02 Areas/ML & DL/Papers/QLoRA|QLoRA]].

## NF4 — NormalFloat4 (QLoRA)

**NF4** — ключевая инновация [[02 Areas/ML & DL/Papers/QLoRA|QLoRA]]. Распределение весов в обученных нейросетях приближённо **нормальное** (с нулевым средним после нормализации). NF4 оптимизирует 4-битную сетку квантизации под нормальное распределение:

1. Вычисляются квантили $N(0, 1)$ для $2^4 = 16$ уровней
2. Каждый уровень соответствует центру масс между соседними квантилями
3. Веса нормализуются к $N(0, 1)$ (absmax normalization), затем квантизуются в ближайший уровень

**Double quantization:** QLoRA дополнительно квантизует сами quantization constants (scales) из FP32 в FP8, экономя ещё ~0.5 бит/параметр.

NF4 теоретически оптимален для нормально распределённых данных — информационно обоснованное преимущество перед равномерной INT4 сеткой.

## GGUF и llama.cpp: квантизация для CPU

**GGUF** (GGML Universal Format) — формат для запуска LLM на CPU/смешанном CPU+GPU через llama.cpp. Поддерживает множество типов квантизации:

| Тип      | Бит  | Описание                                     | Качество |
|----------|------|----------------------------------------------|----------|
| Q2_K     | 2.6  | Агрессивная, заметная деградация             | Низкое   |
| Q3_K_M   | 3.4  | Компромисс для слабого hardware              | Ниже среднего |
| Q4_K_M   | 4.8  | **Рекомендуемый минимум** для большинства     | Хорошее  |
| Q5_K_M   | 5.7  | Хороший баланс качество/размер               | Очень хорошее |
| Q6_K     | 6.6  | Почти без потери качества                     | Отличное |
| Q8_0     | 8.5  | Baseline для сравнения                        | Почти идеальное |

*K-quants (Q4_K_M, Q5_K_M) используют mixed precision: разные слои квантизуются с разной точностью. Attention layers обычно сохраняются в более высокой точности.*

**Практическая рекомендация:** Q4_K_M — стандарт для локального inference. Q5_K_M — если позволяет память. Ниже Q3 — только для экспериментов.

## Деградация качества

Эмпирические наблюдения по MMLU/perplexity для моделей 7B-70B:

- **INT8:** потеря ~0.1-0.5% на бенчмарках — практически незаметна
- **INT4 (GPTQ/AWQ):** потеря ~1-3% — допустимо для большинства задач
- **NF4 (QLoRA):** аналогично INT4, иногда чуть лучше за счёт information-optimal сетки
- **INT2-3:** потеря 5-15% — заметная деградация, особенно на reasoning задачах

**Важная закономерность:** чем больше модель, тем лучше она переносит квантизацию. 70B INT4 часто лучше 13B FP16.

## Когда квантизовать, а когда нет

**Квантизовать стоит:**
- Inference в продакшне (INT8/INT4 — стандарт)
- Локальный запуск на consumer GPU (GGUF Q4_K_M+)
- Fine-tuning больших моделей ([[02 Areas/ML & DL/Papers/QLoRA|QLoRA]]: base model в NF4 + LoRA adapters в FP16)
- Edge deployment (мобильные устройства, embedded)

**Не стоит квантизовать:**
- Pre-training (нужна полная точность для стабильности training)
- Когда качество критично и memory достаточно (medical, legal)
- Модели <1B — мало параметров, сильная деградация при квантизации
- Evaluation/benchmarking — сравнивайте в FP16 для fair comparison

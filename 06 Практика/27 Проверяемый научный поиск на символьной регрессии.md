# Практика 27. Проверяемый научный поиск на символьной регрессии

## Цель

Восстановите неизвестную формулу по численным наблюдениям и сравните обычный
эволюционный поиск с поиском, который накапливает библиотеку повторно
используемых понятий. Все гипотезы исполняются, оцениваются на одинаковых данных
и получают штраф за сложность. Языковая модель может предлагать выражения и
абстракции, но не присваивает им итоговую научную ценность.

Практика адаптирует цикл LaSR из лекции 11 курса
[Berkeley Advanced LLM Agents](https://rdi.berkeley.edu/adv-llm-agents/sp25)
к небольшим синтетическим данным. Она не является официальной лабораторной
работой и не демонстрирует автономное научное открытие: целевые законы известны
автору benchmark-а и используются для проверки.

## 1. Создать задачи без утечки формулы

Сначала выполните однозадачный пример ниже. Для полного сравнительного
проекта выберите не менее восьми законов из разных структурных семейств: полином,
рациональная функция, затухающая экспонента, периодическая функция,
произведение степенных факторов и формула с безразмерной группой. Генератор задач
хранит истинное выражение в закрытом grader manifest и публикует только:

- имена переменных и их размерности;
- допустимые операторы;
- обучающие точки с шумом;
- validation points из того же диапазона;
- extrapolation points вне диапазона;
- лимиты сложности и вычислений.

До запуска зафиксируйте seeds, распределения входов, уровень шума и precision.
Не используйте известные названия законов в prompt или filenames: строка
`pendulum_period.csv` сама раскрывает структуру формулы.

### Первый запуск: дерево выражения, ошибка и выбор кандидата

Следующий пример работает на CPU в Python 3.12 без дополнительных библиотек.
Он перебирает пять заранее заданных выражений и выбирает лучшее по обучающим
точкам. Здесь нет эволюции, LLM и обучения библиотеки: сначала нужно проверить
исполнитель и разделение данных, от которых будут зависеть все три метода.
Данные без шума и целевой полином открыты читателю для проверки вычислений;
для сравнительного проекта ниже генератор и скрытые ответы отделяются от поиска.

В дереве `("mul", ("x",), ("x",))` первый элемент задаёт оператор, остальные —
его аргументы. Константа записывается как `("const", 2.0)`. Все величины в этом
примере безразмерны. `protected_div(a, b)` возвращает 1 при $|b|<10^{-12}$;
это явно выбранное продолжение функции возле нуля, а не обычное деление.
Для физических величин такую грамматику нужно дополнить проверкой единиц.

```python
# bookvar: symbolic-smoke
import math

ARITY = {"x": 0, "const": 1, "add": 2, "mul": 2,
         "pow2": 1, "protected_div": 2}

def size(tree, depth=0):
    if not isinstance(tree, tuple) or not tree or depth > 12:
        raise ValueError("invalid or too deep tree")
    op = tree[0]
    if not isinstance(op, str) or op not in ARITY or len(tree) != ARITY[op] + 1:
        raise ValueError("unknown operator or wrong arity")
    if op == "const":
        value = tree[1]
        if type(value) not in (int, float) or not math.isfinite(value) or abs(value) > 1e6:
            raise ValueError("invalid constant")
        return 1
    count = 1 + sum(size(child, depth + 1) for child in tree[1:])
    if count > 64:
        raise ValueError("node budget exceeded")
    return count

def evaluate(tree, x):
    size(tree)  # Validate the whole expression before execution.
    if not math.isfinite(x) or abs(x) > 1e6:
        raise ValueError("input outside the fixture domain")
    def run(node):
        op = node[0]
        if op == "x":
            value = x
        elif op == "const":
            value = float(node[1])
        else:
            args = [run(child) for child in node[1:]]
            if op == "add":
                value = args[0] + args[1]
            elif op == "mul":
                value = args[0] * args[1]
            elif op == "pow2":
                value = args[0] ** 2
            else:
                value = 1.0 if abs(args[1]) < 1e-12 else args[0] / args[1]
        if not math.isfinite(value) or abs(value) > 1e12:
            raise ValueError("invalid intermediate result")
        return value
    return run(tree)

def nmse(tree, rows):
    mean = sum(y for _, y in rows) / len(rows)
    variance = sum((y - mean) ** 2 for _, y in rows) / len(rows)
    if variance == 0:
        raise ValueError("NMSE needs a nonconstant target")
    mse = sum((evaluate(tree, x) - y) ** 2 for x, y in rows) / len(rows)
    return mse / variance

x = ("x",)
c = lambda value: ("const", float(value))
square = ("mul", x, x)
partial = ("add", square, ("mul", c(2), x))
candidates = {
    "zero": c(0), "linear": x, "square": square,
    "missing_constant": partial,
    "expanded_quadratic": ("add", partial, c(1)),
}
train = [(x, (x + 1) ** 2) for x in [-2., -1., 0., 1., 2.]]
penalty = 0.001  # Fixed before seeing the test points.
scores = {name: nmse(tree, train) + penalty * size(tree)
          for name, tree in candidates.items()}
best_name = min(scores, key=scores.get)
best = candidates[best_name]
test = [(x, (x + 1) ** 2) for x in [-4., -3., 3., 4.]]
assert best_name == "expanded_quadratic"
assert size(best) == 9 and nmse(best, test) == 0.0
assert evaluate(("protected_div", c(7), c(0)), 0.) == 1.0

deep = x
for _ in range(13):
    deep = ("pow2", deep)
bad_cases = [(("unknown", x), 0.), (("add", x), 0.),
             (c(float("nan")), 0.), (("y",), 0.),
             (("pow2", ("pow2", x)), 1e6), (deep, 0.)]
invalid_cases_checked = 0
for tree, value in bad_cases:
    try:
        evaluate(tree, value)
    except ValueError:
        invalid_cases_checked += 1
    else:
        raise AssertionError("invalid expression was accepted")
assert invalid_cases_checked == 6
print(best_name, "nodes:", size(best), "test NMSE:", nmse(best, test))
```

Ожидаемый вывод: `expanded_quadratic nodes: 9 test NMSE: 0.0`. В число узлов
входят операторы, переменные и константы; аргумент константы не считается
отдельным узлом. Последние шесть проверок намеренно подают неправильные деревья.
Для двух разных представлений одной функции ошибка может совпасть, а число
узлов — нет: `pow2(add(x, 1))` короче раскрытого полинома в выбранной грамматике.
Поэтому набор примитивов необходимо фиксировать до сравнения методов.

Заменяя список кандидатов эволюционным поиском, оставьте `evaluate`, критерий
качества и разбиение данных неизменными. Тестовые значения используются только
после выбора `best`; по ним нельзя менять коэффициенты или величину штрафа.
Нулевая ошибка здесь подтверждает работу маленького примера, но не способность
восстанавливать произвольные законы. Исполнитель ограничивает операции и размер
дерева; он не заменяет отдельную изолированную среду для произвольного кода модели.

## 2. Задать язык гипотез

Каждая формула хранится как абстрактное синтаксическое дерево, а не как строка,
передаваемая в `eval`. Разрешите небольшой набор операций, например
`+, -, *, protected_div, pow2, sqrt_abs, exp_clip, sin, cos`. Исполнитель
проверяет конечность, размер массива, диапазон и размерностную согласованность.

Качество кандидата определите до эксперимента:

$$
J(f)=\operatorname{NMSE}_{train}(f)
+\lambda C(f)+\rho V(f),
$$

где $C(f)$ — число узлов дерева, а $V(f)$ — штраф за невалидные вычисления или
нарушение размерностей. Validation и extrapolation не участвуют в выборе
коэффициентов и mutations.

## 3. Реализовать общий эволюционный baseline

Начальная популяция строится из переменных, констант и коротких случайных
выражений. На каждой итерации:

1. все кандидаты исполняются на train points;
2. коэффициенты подгоняются только на train;
3. кандидаты ранжируются по $J$;
4. elites сохраняются;
5. mutation и crossover создают следующую популяцию;
6. дубликаты удаляются по канонической форме дерева.

Этот baseline определяет, что даёт собственно search без библиотеки понятий.
Число исполненных выражений, population size и wall-clock budget фиксируются,
чтобы следующий вариант не получил скрытое преимущество.

## 4. Добавить обучаемую библиотеку понятий

Через каждые $m$ поколений соберите лучшие и характерно провалившиеся формулы.
Модель получает их структуру, оценки и ошибки, после чего предлагает
параметризованные подвыражения — например `ratio(a,b)=protected_div(a,b)` или
`osc(a,b,x)=a*sin(b*x)`. Каждое предложение проходит четыре проверки:

1. парсится в тот же безопасный AST;
2. имеет явные параметры и типы;
3. сокращает описание не менее двух сильных кандидатов либо улучшает held-out
   search seeds при фиксированном бюджете;
4. не содержит целевого выражения или данных grader-а.

Принятые понятия становятся новыми операторами mutation/crossover. Обратная
связь двунаправленна: библиотека меняет пространство новых формул, а успешные и
неуспешные формулы обновляют библиотеку. Именно этот цикл, а не разовая генерация
формулы LLM, составляет механизм
[LaSR](https://arxiv.org/abs/2409.09359). Он показан на
[слайдах 56–73 лекции 11](https://rdi.berkeley.edu/adv-llm-agents/slides/swarat.pdf#page=56).

## 5. Провести три контролируемых сравнения

Запустите при одинаковом evaluation budget:

| вариант | библиотека | что проверяет |
|---|---|---|
| `evolution_only` | только примитивы | качество базового поиска |
| `static_library` | фиксированный набор общих абстракций | пользу дополнительных операторов без обучения |
| `learned_library` | понятия, извлечённые по ходу поиска | вклад адаптивного обновления пространства |

Для каждого варианта используйте не менее пяти seeds. Чтобы проверить перенос,
можно обучить библиотеку на половине семейств и заморозить её перед поиском на
остальных. Нельзя выбирать лучший seed по validation и сообщать его как
ожидаемый результат.

## 6. Разделить подгонку, структурное восстановление и перенос

Низкая train error допускает чрезмерно длинную формулу. Поэтому публикуйте:

- NMSE на train, validation и extrapolation;
- размер и глубину AST;
- число вычисленных кандидатов и время до лучшего valid expression;
- точное структурное совпадение после символьного упрощения;
- численную эквивалентность на скрытой сетке;
- размер библиотеки, reuse count и marginal gain каждого понятия;
- долю невалидных, размерностно неверных и дублирующихся выражений.

Структурное совпадение и численная эквивалентность отвечают на разные вопросы:
две записи могут задавать одну функцию, а близкая ошибка на узком диапазоне не
гарантирует правильной структуры. Отдельно покажите Pareto-front
`ошибка ↔ сложность`.

Для сравнения сложности раскрывайте библиотечные вызовы в исходные примитивы:
один узел `osc(a,b,x)` не должен считаться дешевле той же формулы
`a*sin(b*x)` только из-за нового имени. Отдельно можно измерить длину записи
с библиотекой, учитывая стоимость определения каждого понятия.

## 7. Проверить, не закрепляет ли библиотека ошибку

Добавьте controlled failure с двумя заранее зафиксированными фазами обучения.
В фазе A search видит train points из узкого диапазона, где неверная простая
формула почти совпадает с истинной. В фазе B в **train split** добавляется
заранее подготовленный широкий диапазон; только после этого search и библиотека
могут обновляться. Validation и extrapolation всё время остаются только средством
оценки. Измерьте, продолжает ли learned library предлагать старую абстракцию и
сколько вычисленных кандидатов требуется, чтобы поиск от неё отказался.

Понятие считается полезным не потому, что модель дала ему убедительное имя, а
если при фиксированном бюджете оно улучшает несколько независимых запусков или
перенос на новые задачи. Иначе оно остаётся гипотезой. Лекция Berkeley обсуждает
эту границу на
[слайдах 74–92](https://rdi.berkeley.edu/adv-llm-agents/slides/swarat.pdf#page=74):
результаты на Feynman equations и scaling-law examples являются измерениями
авторов, а не общим доказательством автономного discovery.

## Критерии зачёта

1. целевые формулы и extrapolation labels недоступны proposal model;
2. выражения исполняются безопасным AST evaluator без `eval` и произвольного кода;
3. коэффициенты и selection используют только train split;
4. три варианта имеют одинаковые primitive operators, seeds и evaluation budget;
5. все кандидаты и library updates имеют provenance;
6. итог проверяется и по скрытой численной сетке, и по сложности;
7. negative result разрешён и сохраняется без подбора удачного seed;
8. controlled failure показывает, способна ли библиотека отказаться от
   преждевременной абстракции;
9. evidence bundle проходит contract validator.

## Что сдаётся

- generator manifest с хэшами и закрытым grader manifest отдельно;
- train/validation/extrapolation data manifests;
- versioned grammar и AST evaluator tests;
- `candidates.jsonl`, `generations.csv`, `library_events.jsonl`;
- результаты всех variants и seeds при равном бюджете;
- Pareto-front и полный разбор одной принятой и одной ошибочной абстракции;
- `report.md`, разделяющий fit, recovery, extrapolation и перенос понятий.

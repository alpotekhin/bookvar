# Собрать micrograd и bigram LM

Чтобы обучить модель, нужно вычислить, как изменение каждого параметра влияет
на ошибку предсказания. Сначала реализуйте эти производные для небольшого
вычислительного графа. Затем обучите языковую модель, в которой распределение
следующего символа зависит только от предыдущего: её результат можно проверить
не только по убывающей ошибке, но и по точному решению через счётчики.

Не копируйте `micrograd` целиком. До чтения готовой реализации напишите свой
минимальный класс `Value`: данные, градиент, родители, локальная операция и
функция обратного прохода.

## Часть 1. Автоматическое дифференцирование

Поддержите сложение, умножение, возведение в степень, `tanh` или ReLU. Метод
`backward()` должен построить топологический порядок графа и пройти его в
обратном направлении.

Первый обязательный тест использует одну переменную несколько раз:

```python
x = Value(3.0)
y = x * x + 2 * x
y.backward()
assert abs(x.grad - 8.0) < 1e-8
```

Если присваивать локальный градиент вместо накопления через `+=`, этот тест
сломается: две ветви графа вносят вклад в одну производную.

Затем для случайных выражений сравните аналитический градиент с центральной
конечной разностью

$$
\frac{f(x+\varepsilon)-f(x-\varepsilon)}{2\varepsilon}.
$$

Зафиксируйте $\varepsilon$ и объясните, почему слишком большое значение даёт
ошибку аппроксимации, а слишком малое — ошибку округления.

## Часть 2. От счётчиков биграмм к обучаемой модели

Разделите небольшой корпус имён или слов на обучающую и проверочную части
**до** подсчёта переходов. Добавьте граничный символ и по обучающей части
постройте матрицу $N_{ij}$. При положительном числе переходов из $i$ оценка
максимального правдоподобия равна $N_{ij}/\sum_kN_{ik}$. Ненаблюдавшиеся переходы
имеют нулевую вероятность, поэтому новый переход при проверке даёт бесконечную
отрицательную логарифмическую правдоподобность. Аддитивное сглаживание решает эту
проблему, добавляя к каждой ячейке псевдосчётчик $\alpha>0$:

$$
P(j\mid i)=\frac{N_{ij}+\alpha}{\sum_k(N_{ik}+\alpha)}.
$$

Теперь замените таблицу вероятностей обучаемой матрицей логитов $W$.
Для наблюдавшейся пары $(i,j)$ потеря равна
$-\log\operatorname{softmax}(W_i)_j$. Обучение только на исходных парах
соответствует **несглаженной** оценке, а не формуле с $\alpha$. При нулевых
счётчиках softmax с конечными логитами лишь приближается к нулевой вероятности;
для строки без наблюдений такая функция потерь вообще не задаёт распределение.

Чтобы сравнивать два способа получения именно **сглаженной** модели, обучайте
логиты по тем же псевдосчётчикам:

$$
\mathcal L(W)=-\frac{1}{\sum_{ij}(N_{ij}+\alpha)}
\sum_{ij}(N_{ij}+\alpha)\log\operatorname{softmax}(W_i)_j.
$$

В следующем примере три символа образуют словарь. Положительные псевдосчётчики
дают конечное оптимальное решение, поэтому можно проверить совпадение
распределений численно. Код выполняется на CPU с PyTorch; реализация `Value`
из первой части для этого отдельного теста не нужна.

```python
# bookvar: bigram-pseudocounts
import torch

counts = torch.tensor([[3., 1., 0.], [0., 2., 2.], [1., 0., 0.]],
                      dtype=torch.float64)
alpha = 1.0
smoothed = counts + alpha
expected = smoothed / smoothed.sum(dim=1, keepdim=True)
mle = counts / counts.sum(dim=1, keepdim=True)
W = torch.zeros_like(counts, requires_grad=True)
optimizer = torch.optim.SGD([W], lr=1.0)

def objective():
    return -(smoothed * W.log_softmax(dim=1)).sum() / smoothed.sum()

initial_loss = objective().item()
for _ in range(800):
    optimizer.zero_grad()
    loss = objective()
    loss.backward()
    optimizer.step()
final_loss = objective().item()
learned = W.detach().softmax(dim=1)
torch.testing.assert_close(learned, expected, atol=1e-5, rtol=1e-5)
print(learned)
```

Первая строка должна приблизиться к $(4/7,2/7,1/7)$, тогда как несглаженная
оценка равна $(3/4,1/4,0)$. Сравнивайте вероятности, а не сами логиты:
добавление одной константы ко всей строке $W_i$ не меняет softmax.

## Проверки корректности

- топологический проход посещает каждый узел ровно один раз;
- градиенты совпадают с finite differences как минимум на десяти случайных
  выражениях;
- каждая строка bigram probabilities суммируется в единицу;
- обучающая потеря уменьшается; на приведённом примере она ниже, чем у
  равномерного распределения; результат на проверочной части измеряется
  отдельно, без обещания обязательного улучшения;
- validation loss вычисляется на последовательностях, не участвовавших в
  обновлении параметров;
- генератор использует отдельный seed и останавливается на граничном символе.

## Что сдать

Репозиторий с реализацией и тестами, изображение одного вычислительного графа,
таблицу gradient checks, кривую train/validation NLL и двадцать примеров
генерации. В коротком выводе укажите, какие зависимости биграммная модель не
может выразить и почему следующий шаг требует контекст длиннее одного символа.

Работа закончена, когда новый запуск из чистого окружения воспроизводит тесты,
loss curve и samples по записанному seed.

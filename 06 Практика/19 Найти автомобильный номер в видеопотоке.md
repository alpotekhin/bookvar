# Найти автомобильный номер в видеопотоке

## Цель

Собрать проверяемый ALPR/ANPR pipeline, который по большому набору видеонарезок возвращает не просто строку, а запись вида

```text
plate=А123ВС77, video=cam12_0042.mp4, track=184,
first_seen=00:03:14.20, best_frame=00:03:15.08,
bbox=[x1,y1,x2,y2], confidence=0.94
```

Большая VLM здесь служит возможным fallback, но не основным распознавателем. Для массового потока специализированный каскад дешевле, быстрее и позволяет независимо измерять каждую ошибку.

## Конвейер

1. Декодировать видео с сохранением `video_id`, frame index и timestamp.
2. Запустить detector автомобилей и/или номерных знаков.
3. Связать detections во времени tracker вроде ByteTrack или BoT-SORT.
4. Для каждого track накопить несколько crops, а не распознавать единственный кадр.
5. Оценить качество crops: площадь, резкость, угол, засветка и отсутствие перекрытия.
6. Исправить perspective при заметном наклоне пластины.
7. Запустить OCR, ограниченный алфавитом и форматами целевого региона.
8. Агрегировать результаты по track: голосование целых гипотез либо объединение
   вероятностей после согласования символьных позиций.
9. Применить format validation, но сохранить исходные hypotheses для аудита.
10. Записать searchable index с лучшим crop, timestamp и confidence.

Temporal aggregation — центральное преимущество видео. На одном кадре буква закрыта бликом, на следующем видна; один crop резче, другой лучше показывает регион. Преждевременно выбранный «лучший кадр» отбрасывает эту информацию.

Складывать вероятности «символа номер $j$» можно лишь после выравнивания
гипотез. Например, в строках `A123BC77` и `A12BC77` пропущена `3`:
четвёртые позиции обозначают разные символы. Простое поколоночное
суммирование испортит также все следующие позиции. Начните с голосования
целых строк; затем добавьте выравнивание с вставками и удалениями. Если OCR
использует CTC, его покадровые выходы сначала нужно интерпретировать с учётом
blank и повторов, а не считать готовыми позициями номерного знака.

Сумма логарифмов вероятностей соответствует произведению вероятностей
при условной независимости наблюдений. Соседние кадры обычно сильно
коррелированы, а оценки OCR могут быть некалиброваны. Поэтому сравните этот
способ с голосованием и с отбором более разнообразных кадров; проверьте
калибровку на отдельной валидации. Не выдавайте накопленный score за
вероятность правильного номера без такой проверки.

## Почему не следует сразу спрашивать VLM

Generative VLM оптимизирована продолжать текст правдоподобно. Она может нормализовать редкий номер под знакомый формат, уверенно заменить неразличимый символ или вернуть строку без калиброванной confidence. Кроме того, длинное видео создаёт огромный visual token budget.

VLM полезна после специализированного каскада: проверить сложный crop, описать тип автомобиля, связать номер с контекстом сцены или разобрать нестандартную табличку. Но основной evidence должен оставаться воспроизводимым: crop, bbox, track и timestamp.

## Экспериментальные срезы

Используйте учебный набор с разрешённым использованием либо специально снятые
материалы, для которых получены необходимые разрешения. При публикации отчёта
не раскрывайте реальные номера, лица, маршруты и исходные видеозаписи без
соответствующих прав; для демонстрации подойдут синтетические номера и
обезличенные кадры. Исходные доказательства распознавания храните в закрытой
части эксперимента, если их нельзя публиковать.

Разметьте небольшой, но разнообразный test set на уровне tracks. Не допускайте попадания кадров одного автомобиля одновременно в train и test. Считайте отдельно:

- plate detection precision/recall и mAP;
- tracking ID switches и пропущенные tracks;
- exact-match номера на уровне кадра и на уровне track;
- character error rate;
- end-to-end recall при заданном false-positive rate;
- throughput в frames/s, GPU utilization и p95 задержки;
- качество по размеру номера, углу, ночи, дождю и motion blur.

Обязательная абляция сравнивает OCR по одному кадру, majority vote и объединение вероятностей. Вторая абляция меняет frame sampling rate: высокая скорость дороже, но может сохранить короткое появление номера. Третья сравнивает общий OCR и модель, дообученную на целевом алфавите.

## Критерий готовности

Работа завершена, когда по каждой найденной строке можно открыть исходный момент видео и проверить evidence; end-to-end метрика посчитана по независимым tracks; известны наиболее частые причины false negative и false positive; throughput измерен на целевом оборудовании. Красивые отдельные примеры без track-level test set результатом не считаются.

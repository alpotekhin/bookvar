# BPE: обучение и кодирование

## Частота пары и число замен

Возьмите обучающую строку `aaabdaaabac`. На нулевом шаге в ней
11 байтов; ASCII-байты `a` и `b` имеют ID 97 и 98. Пара
`97 + 97` встречается четыре раза: по два раза в каждом `aaa`.
Первое объединение создаёт ID 256 для `aa`. В каждом `aaa`
заменяется только одна пара, поскольку два вхождения делят один байт.
После шага остаётся девять токенов.

Затем `256 + 97` и `97 + 98` встречаются по два раза.
Программа выбирает первую из них: она раньше появилась при чтении слева
направо. Следующие два шага создают 257 для `aaa` и 258 для `aaab`.

| Объединений | Токены обучающей строки | Кодирование `aaabac` |
|---:|---|---|
| 0 | `97 97 97 98 100 97 97 97 98 97 99` | `97 97 97 98 97 99` |
| 1 | `256 97 98 100 256 97 98 97 99` | `256 97 98 97 99` |
| 2 | `257 98 100 257 98 97 99` | `257 98 97 99` |
| 3 | `258 100 258 97 99` | `258 97 99` |

## Незнакомый текст

На шаге 3 подставьте `я🦊` во второе поле, не меняя обучающую строку.
Получатся шесть токенов: `209 143 240 159 166 138`. Ни одно из
трёх выученных правил не применимо, поэтому каждый байт остаётся
отдельным токеном. Чтобы восстановить `я🦊`, декодер сначала соединяет
байты `D1 8F F0 9F A6 8A`, а затем читает их как UTF-8.
Если декодировать `D1` отдельно, буква `я` не получится.

Практика использует учебный байтовый BPE без нормализации,
предварительного разбиения и служебных токенов. Это не словарь GPT-2.
Реализацию см. в [minbpe, BasicTokenizer](https://github.com/karpathy/minbpe/blob/1acefe89412b20245db5a22d2a02001e547dc602/minbpe/basic.py);
связь с реальными токенизаторами — в
[[02 Areas/ML & DL/00 Учебник/02 Представление текста и токенизация/02 BPE, WordPiece и Unigram#bpe-merge-trace|главе о токенизации]].
